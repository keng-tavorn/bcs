# คู่มือ demo BCS (D-07)

สำหรับคนที่เตรียมและนำ demo กับ LK-RICH · ลำดับฉาก บัญชีผู้ใช้ การ reset ข้อมูลด้วยคำสั่งเดียว และแผนสำรอง
ข้อมูลทั้งหมดในระบบเป็นข้อมูลสมมติจาก `docs/inputs/BCS_inputs_v1_demo.xlsx` ห้ามใช้ข้อมูลจริงของลูกค้าจนกว่า OQ-19 ปิด

## 1. ก่อนวัน demo (ทำครั้งเดียว)

1. **ตรวจไฟล์ข้อมูล** — `pnpm inputs:check` ต้องขึ้น `0 FAIL` ทุกครั้งก่อน reset
2. **staging พร้อม** — เปิด `https://<staging>/api/health` แล้วได้ 200 พร้อมเลข commit (คู่มือ `docs/runbooks/p0-05-neon-staging.md` ถึง `p0-08-vercel.md`)
3. **LINE ของ BCS** — ตั้ง provider channel และ LIFF ตาม `docs/runbooks/line-demo-setup.md` (D-02 · ใส่ค่าใน Environment Variables ของ staging เอง ไม่ส่งในแชท) แล้วเปิด `/admin/line` กด "ทดสอบการเชื่อมต่อ" ต้องผ่านทุกข้อ (D-03) จากนั้นกดปุ่มสร้าง rich menu ในหน้าเดียวกันครั้งเดียว (บนเครื่องใช้ `pnpm line:richmenu` แทน · ADR-049)
4. **มือถือที่ใช้ demo** — แต่ละเครื่องเพิ่ม OA ของ BCS เป็นเพื่อน แล้วเข้าเว็บด้วยบัญชีตามตารางข้อ 3 เปิด `/settings/line` สแกน QR เพื่อผูก LINE กับผู้ใช้นั้น (ผูกใหม่ทุกครั้งหลัง reset เพราะ reset ลบการผูก)
5. **รหัสยืนยันตัวตน (TOTP)** — ผู้ใช้ที่มีบทบาทหรือตำแหน่งต้องใส่รหัส 6 หลักตอน login เพิ่มเข้าแอป authenticator ครั้งเดียวด้วย
   `pnpm exec tsx --env-file-if-exists=.env scripts/seed-totp.ts ceo coo vp_ops vp_sup dm_con proc_officer fin_officer receiver_con auditor admin`
   (คำสั่งพิมพ์ลิงก์ตั้งค่าและรหัสปัจจุบัน ใช้ได้เฉพาะ local และ staging เพราะคำนวณจาก `SEED_TOTP_KEY`)
6. **PIN ยืนยันธุรกรรม** — ยอดตั้งแต่ 100,000 บาทขึ้นไปต้องใส่ PIN (ฉาก 3) ถ้าตั้ง `SEED_DEV_PIN` (6 หลัก ไม่ใช่เลขเดาง่าย) ใน `.env` หรือ Environment Variables ของ staging ผู้อนุมัติตัวอย่างจะได้ PIN นี้ตอน seed ไม่เช่นนั้นตั้งเองที่ `/settings/pin`
7. **ซ้อม 1 รอบบนมือถือจริง** (D-08) และอัดวิดีโอสำรองฉาก 1–3

## 2. Reset ข้อมูลก่อน demo (คำสั่งเดียว)

ประวัติคำขอย้อนหลัง (ชีต `Demo_History`) นับวันย้อนจากวันที่ reset งานที่ค้างนับชั่วโมงทำการจากเวลานั้น จึง **reset ไม่เกินประมาณ 6 ชั่วโมงทำการก่อน demo** เพื่อให้กระดานค้างแสดง "H12 ค้าง 18 ชม. ที่ VP" ใกล้เคียงกับที่พูด

- บนเครื่อง: `pnpm demo:reset`
- บน staging (คนที่ดูแล staging เป็นผู้รันเอง เพราะข้อมูลบน staging ถูกลบทั้งหมด):
  `pnpm demo:reset --env=.env.staging --confirm=DEMO-<วันที่วันนี้ เช่น 2026-10-20>`
  - `.env.staging` คือค่าของ staging เก็บในเครื่องเท่านั้น ห้าม commit · **ยังใช้วิธีนี้ไม่ได้ (2026-10-07):** `vercel env pull` ได้ค่าว่างสำหรับค่าชนิด Secret เช่น `DATABASE_URL` `DIRECT_URL` และ `ENCRYPTION_KEY` วิธี reset staging ที่ใช้ได้รอคุณตัดสิน (NEW-70) · seed ครั้งแรกใช้ปุ่มใน Inngest ([p0-07-inngest.md](runbooks/p0-07-inngest.md) ส่วนที่ 3)
  - คำสั่งตรวจไฟล์ inputs ก่อน ล้างฐาน สร้างตารางใหม่ แล้ว seed องค์กร DEMO พร้อมประวัติ demo · production ปฏิเสธเสมอ
- หลัง reset: ผูก LINE ของมือถือ demo ใหม่ (ข้อ 1.4) แล้วเปิด `/admin/line` กดทดสอบการเชื่อมต่ออีกครั้ง

**ปีงบของข้อมูล demo:** ชีตผูกกับปีงบ 2569 (ม.ค.–ธ.ค. 2026) ถ้า demo เกิดหลังสิ้นปี 2026 คำสั่ง reset จะหยุดและบอกให้เลื่อนปีในชีต Budget Holidays และ Demo_History (แก้ใน Excel แล้วรัน `pnpm inputs:check`)

## 5. แผนสำรอง

| ถ้า | ทำแบบนี้ |
| --- | --- |
| LINE ส่งการ์ดไม่มา หรือ LIFF เปิดไม่ได้ | ทำฉากเดียวกันบนเว็บด้วยมือถือ (ทุกหน้าใช้งานได้ที่ 375 px) · งานอนุมัติส่งอีเมลสำรองพร้อมลิงก์ตัดสิน · เปิดวิดีโอสำรองฉาก 1–3 |
| staging ล่มหรือเน็ตไม่ดี | เปิดบนโน้ตบุ๊กด้วย Docker: `docker compose up -d` แล้ว `pnpm demo:reset` และ `pnpm dev` (LINE จะใช้ไม่ได้ ใช้เว็บแทน) |
| ตัวเลขบนกระดานไม่ตรงกับที่พูด | reset ใหม่ด้วยคำสั่งในข้อ 2 (ใช้เวลาไม่กี่นาที) แล้วผูก LINE ใหม่ |
| ลืม PIN หรือ PIN ถูกล็อก | ล็อก 15 นาทีหลังผิด 5 ครั้ง · ตั้ง PIN ใหม่ที่ `/settings/pin` (ต้องยืนยันรหัสผ่านก่อน) |
| ลูกค้าถามเรื่องที่ยังไม่มีคำตอบ | จดลงชีต `Questions` ของไฟล์ inputs (Q-01 ถึง Q-35) ใช้ทำ spec version 2 |
