# คู่มือ demo BCS (D-07 · หน้าจอใหม่ S16-13)

สำหรับคนที่เตรียมและนำ demo กับ LK-RICH · ลำดับฉาก บัญชีผู้ใช้ การ reset ข้อมูลด้วยคำสั่งเดียว และแผนสำรอง
ข้อมูลทั้งหมดในระบบเป็นข้อมูลสมมติจาก `docs/inputs/BCS_inputs_v1_demo.xlsx` (demo เดิม ข้อ 1–5 · องค์กร DEMO) และ `docs/inputs/BCS_inputs_p1.xlsx` (demo ระยะ 1 ข้อ 6 · องค์กร SIMEC) ห้ามใช้ข้อมูลจริงของลูกค้าจนกว่า OQ-19 ปิด

## 1. ก่อนวัน demo (ทำครั้งเดียว)

1. **ตรวจไฟล์ข้อมูล** — `pnpm inputs:check` ต้องขึ้น `0 FAIL` ทุกครั้งก่อน reset
2. **staging พร้อม** — เปิด `https://<staging>/api/health` แล้วได้ 200 พร้อมเลข commit (คู่มือ `docs/runbooks/p0-05-neon-staging.md` ถึง `p0-08-vercel.md`)
3. **LINE ของ BCS** — ตั้ง provider channel และ LIFF ตาม `docs/runbooks/line-demo-setup.md` (D-02 · ใส่ค่าใน Environment Variables ของ staging เอง ไม่ส่งในแชท) แล้วเปิด `/admin/line` กด "ทดสอบการเชื่อมต่อ" ต้องผ่านทุกข้อ (D-03) จากนั้นกดปุ่มสร้าง rich menu ในหน้าเดียวกันครั้งเดียว (บนเครื่องใช้ `pnpm line:richmenu` แทน · ADR-049)
4. **มือถือที่ใช้ demo** — แต่ละเครื่องเพิ่ม OA ของ BCS เป็นเพื่อน แล้วเข้าเว็บด้วยบัญชีตามตารางข้อ 3 เปิด `/settings/line` สแกน QR เพื่อผูก LINE กับผู้ใช้นั้น (ผูกใหม่ทุกครั้งหลัง reset เพราะ reset ลบการผูก)
5. **รหัสยืนยันตัวตน (TOTP)** — ผู้ใช้ที่มีบทบาทหรือตำแหน่งต้องใส่รหัส 6 หลักตอน login เพิ่มเข้าแอป authenticator ครั้งเดียวด้วย
   `pnpm exec tsx --env-file-if-exists=.env scripts/seed-totp.ts ceo coo vp_ops vp_sup dm_con proc_officer fin_officer receiver_con auditor admin`
   (คำสั่งพิมพ์ลิงก์ตั้งค่าและรหัสปัจจุบัน ใช้ได้เฉพาะ local และ staging เพราะคำนวณจาก `SEED_TOTP_KEY`)
   - คำสั่งข้างบนใช้ค่าใน `.env` ของเครื่องนี้ ซึ่งเป็นคนละค่ากับ staging · สำหรับ staging รันใน PowerShell ที่โฟลเดอร์โปรเจกต์ แล้ววางค่า `SEED_TOTP_KEY` ของ staging จากโปรแกรมจัดการรหัสผ่านเมื่อถูกถาม (ค่าไม่แสดงบนจอและไม่ผ่านแชต · ใช้ได้กับข้อมูลที่ reset หลังตั้งค่านี้ใน Vercel):
     `$k = Read-Host "วาง SEED_TOTP_KEY ของ staging" -AsSecureString; $env:SEED_TOTP_KEY = [Runtime.InteropServices.Marshal]::PtrToStringAuto([Runtime.InteropServices.Marshal]::SecureStringToBSTR($k)); $env:APP_ENV = "staging"; pnpm exec tsx scripts/seed-totp.ts admin ceo coo vp_ops proc_officer; Remove-Item Env:SEED_TOTP_KEY`
6. **PIN ยืนยันธุรกรรม** — ยอดตั้งแต่ 100,000 บาทขึ้นไปต้องใส่ PIN (ฉาก 3) ถ้าตั้ง `SEED_DEV_PIN` (6 หลัก ไม่ใช่เลขเดาง่าย) ใน `.env` หรือ Environment Variables ของ staging ผู้อนุมัติตัวอย่างจะได้ PIN นี้ตอน seed ไม่เช่นนั้นตั้งเองที่ `/settings/pin`
7. **ซ้อม 1 รอบบนมือถือจริง** (D-08) และอัดวิดีโอสำรองฉาก 1–3

## 2. Reset ข้อมูลก่อน demo (คำสั่งเดียว)

ประวัติคำขอย้อนหลัง (ชีต `Demo_History`) นับวันย้อนจากวันที่ reset งานที่ค้างนับชั่วโมงทำการจากเวลานั้น จึง **reset ไม่เกินประมาณ 6 ชั่วโมงทำการก่อน demo** เพื่อให้กระดานค้างแสดง "H12 ค้าง 18 ชม. ที่ VP" ใกล้เคียงกับที่พูด

- บนเครื่อง: `pnpm demo:reset`
- บน staging (คนที่ดูแล staging เป็นผู้กดเอง เพราะข้อมูลบน staging ถูกลบทั้งหมด · ADR-056):
  1. <https://app.inngest.com> → environment `staging` → เมนู **Functions** → กด `staging-demo-reset`
  2. กด **Invoke** → ลบข้อความเดิมในช่องข้อมูล แล้วพิมพ์ `{"data": {"confirm": "DEMO-<วันที่วันนี้ตามเวลาไทย>"}}` เช่น `{"data": {"confirm": "DEMO-2026-10-20"}}` → กด **Invoke function**
  3. หน้า **Runs** รอจนสถานะเป็น **Completed** (ราว 2–5 นาที) แล้วดู Output ว่ามี `"reset": true`
     - `"line": "KEPT"` คือค่า LINE ที่ตั้งไว้ยังอยู่ (webhook และ rich menu ใช้ได้เหมือนเดิม) · `"NONE"` คือยังไม่เคยตั้ง LINE · `"NOT_OPENED"` คือค่า LINE เดิมเปิดไม่ได้จึงหายไป ให้ทำ [line-demo-setup.md](runbooks/line-demo-setup.md) ส่วนที่ 3 ใหม่
     - `"refusal": "CONFIRMATION_MISMATCH"` คือพิมพ์คำยืนยันไม่ตรง Output บอกคำที่ถูก (`"expected"`) ไม่มีอะไรถูกลบ
     - `"refusal": "OTHER_ORGANIZATIONS"` คือมีองค์กรอื่นนอกจาก DEMO อยู่ใน staging งานจึงไม่ลบอะไร ให้บอก agent
     - ถ้าสถานะเป็น **Failed** ให้ส่งข้อความ error ให้ agent และอย่ากดซ้ำหลายครั้ง · ถ้าล้มที่ step `check` ยังไม่มีอะไรถูกลบ (เช่นวันนี้อยู่นอกปีงบของข้อมูล demo) · ถ้าล้มที่ step `reset` หรือ `history` ให้ถาม agent ก่อนกดใหม่ และอาจต้องตั้ง LINE ใหม่
  4. login ใหม่ทุกคน (session เดิมถูกล้างด้วย)
  - ทางเดิม `pnpm demo:reset --env=.env.staging --confirm=DEMO-<วันที่>` ใช้ได้เฉพาะเมื่อมีค่าของ staging ครบในเครื่อง ซึ่ง `vercel env pull` ให้ไม่ได้เพราะค่าชนิด Secret ดึงลงเครื่องไม่ได้ และทางนี้ไม่เก็บค่า LINE ไว้
  - ทั้งสองทางตรวจไฟล์ inputs ก่อนล้าง แล้ว seed องค์กร DEMO พร้อมประวัติ demo · production ไม่มีวันล้างด้วยทางใด
- หลัง reset: ผูก LINE ของมือถือ demo ใหม่ (ข้อ 1.4) แล้วเปิด `/admin/line` กดทดสอบการเชื่อมต่ออีกครั้ง

**ชุดข้อมูลระยะ 1 (องค์กร SIMEC · ข้อ 6):**

- บนเครื่อง: `pnpm db:reset:p1` (ราว 2–10 นาที)
- บน staging: ทำข้อ 1–4 ข้างบน แต่ในช่องข้อมูลพิมพ์ `{"data": {"inputs": "p1", "confirm": "SIMEC-<วันที่วันนี้ตามเวลาไทย>"}}` เช่น `{"data": {"inputs": "p1", "confirm": "SIMEC-2026-10-20"}}` · ไม่ใส่ `inputs` คือชุด demo เดิม
  - งานแบ่งเป็นหลาย step (`check` → `reset` → `sandbox` → `history-1-…` ถึง `history-n-…`) ใช้เวลานานกว่าชุด demo รอจน run เป็น **Completed** ทั้งหมด
  - Output มี `"inputs": "p1"` `"sandbox": "SIMEC-UAT"` (องค์กรทดลองของ workflow ระยะ 1) และ `"history"` จำนวนคำขอประวัติตามสถานะ
  - staging มีข้อมูลทีละชุด: reset ชุดระยะ 1 แล้วองค์กร DEMO หายไปจนกว่าจะ reset กลับด้วยชุด demo · ค่า LINE ย้ายตามองค์กรที่ reset (`"line": "KEPT"`) แต่ต้องผูก LINE ของมือถือใหม่ทุกครั้ง
- **ปีงบของข้อมูลระยะ 1:** ชีต Budget มีปีงบ 2569 และ 2570 (ม.ค.–ธ.ค.) · step `check` หยุดและบอกเหตุผลถ้าวันนี้อยู่นอกช่วงที่ชีตรองรับ

**ปีงบของข้อมูล demo:** ชีตผูกกับปีงบ 2569 (ม.ค.–ธ.ค. 2026) ถ้า demo เกิดหลังสิ้นปี 2026 คำสั่ง reset จะหยุดและบอกให้เลื่อนปีในชีต Budget Holidays และ Demo_History (แก้ใน Excel แล้วรัน `pnpm inputs:check`)

## 4. ลำดับฉาก (ชีต `Demo_Script` · ฉากหลัก core = Y คือ 1 2 3 4 5 7 8 9)

หน้าจอเว็บเป็นแบบใหม่ของรอบ A2 (S16): ทุกคนเข้าเว็บแล้วเจอ **หน้าแรก** ที่ทักชื่อและมีการ์ด 4 ใบ ("สิ่งที่ต้องทำ" "รอฉันอนุมัติ" "งานอนุมัติทันเวลา" "ที่ฉันติดตาม") เริ่มทุกฉากบนเว็บจากหน้านี้ด้วย 3 ทางเท่านั้น

- **ตัวเลขในการ์ด** → กดตัวเลขแล้วไปรายการที่นับตัวเลขนั้น (ตัวเลขกับจำนวนในรายการเท่ากันเสมอ)
- **⌘K** (Windows กด Ctrl K หรือกดช่อง "ค้นหาเลขเอกสาร ผู้ขาย หรือเมนู" กลางหน้าแรก) → พิมพ์เลขเอกสารบางส่วน เช่น `PR-2569` หรือชื่อเมนู → Enter · เห็นเฉพาะเอกสารที่ผู้ใช้คนนั้นมีสิทธิ์ดู
- **ปุ่ม "ขอซื้อ / ขอจ้าง"** บนแถบบน (หรือชิป "เริ่มคำขอใหม่" ใต้ช่องค้นหา) → dialog เลือกประเภท → กดประเภท เช่น "ซื้อของ" → ฟอร์มทีละขั้น "รายละเอียดคำขอ → รายการที่ขอ → ใบเสนอราคาและเอกสาร → ตรวจและส่ง" (ขั้นเอกสารขึ้นเฉพาะเมื่อยอดต้องมีใบเสนอราคา)

หน้าคำขอและหน้า PO เป็นแท็บ: **ภาพรวม** (การ์ดขั้นอนุมัติ ขั้นที่อนุมัติแล้วเป็นตราประทับพร้อม DOA ref) · **รายการและงบ** · **เอกสาร** · **ประวัติ** (ช่องทางและ DOA ref ของทุกการตัดสิน) · ผู้อนุมัติตัดสินจาก **แถบตัดสิน** ด้านล่างของหน้า ยอดตั้งแต่ 100,000 บาทขึ้นไปจะถาม PIN ก่อนยืนยัน

บนมือถือเมนูซ้ายยุบเป็นปุ่มเมนู (☰) มุมซ้ายบน · หน้า LIFF ในแอป LINE (ฉาก 1 3 4 8) โครงเหมือนเดิม เปลี่ยนแค่สีและป้ายสถานะ

### ฉากเปิด (2 นาที · แนะนำหน้าจอใหม่ก่อนฉาก 1)

1. `req_con` เข้าเว็บ → หน้าแรกขึ้น "สวัสดี คุณสมชาย วันนี้ต้องการทำอะไร" และงานของตัวเองในการ์ด "สิ่งที่ต้องทำ"
2. กด ⌘K พิมพ์ `PR-2569` → เห็นเฉพาะคำขอที่ `req_con` มีสิทธิ์ดู (ชี้ว่าคนอื่นค้นแล้วจะเห็นชุดต่างกัน) → Esc
3. กดชิป "เริ่มคำขอใหม่" → dialog เลือกประเภทแสดง 5 ประเภทพร้อม "ใช้เมื่อ" → กด Esc ปิด (ฉาก 1 ทำคำขอจริงใน LINE)
