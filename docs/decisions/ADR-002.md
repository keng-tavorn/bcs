# ADR-002: มือถือเริ่มที่ PWA แล้วค่อยเป็น Capacitor และใช้ LIFF ในแอป LINE

- สถานะ: ตัดสินแล้ว
- วันที่: 2026-10-01
- ที่มา: ตารางเรื่องที่ต้องตัดสินใจในเอกสารต้นทาง (spec §18.1 · ภาคผนวก C: เอกสารต้นทางหัวข้อ 14 "เรื่องที่ต้องตัดสินใจ")

## บริบท

- ผู้อนุมัติไม่อยู่หน้าคอม และถูกตามงานทาง LINE และโทรศัพท์ (§1.1) · เป้า G-5 คือการตัดสินผ่าน LINE/LIFF ≥ 60% ของทั้งหมด
- หลัก P-5 "เว็บไว้ทำงาน มือถือไว้ตัดสินใจ" · ไม่ทำแอป native และไม่ใช้ React Native (NG-3)

## การตัดสินใจ

> ช่องทางมือถือแรกคือ PWA แล้วค่อยเป็น Capacitor ส่วนหน้า LIFF ใช้ในแอป LINE

- S1: PWA ติดตั้งเป็นไอคอนได้ เปิดแบบ standalone มีหน้าออฟไลน์ ไม่ cache ข้อมูลธุรกิจ และไม่มี web push ในชั้น 1 เพราะ LINE เป็นช่องทางหลัก (FR-PLT-005 · §9.7)
- S5: หน้า LIFF ที่ `/liff/*` สำหรับงานในแอป LINE (FR-LINE-003 · §9.4) · เปิดนอกแอป LINE ใช้การ login ของเว็บตามปกติ
- S15: Capacitor ห่อเว็บเดิม (NG-3 · FR-PLT-301 · โมดูล `BCS_GO`)

## ผลที่ตามมา

- ทุกช่องทางมือถือใช้โค้ดชุดเดียวกับเว็บ (ADR-017)
- หน้า LIFF ออกแบบ mobile-first: ตัวอักษร 16 px ปุ่มสูงอย่างน้อย 44 px JavaScript เริ่มต้นไม่เกิน 200 KB (gzip) (§9.4) · LCP ไม่เกิน 2.5 วินาที INP ไม่เกิน 200 ms บนมือถือระดับกลางผ่าน 4G (NFR-PERF-01)
- งานใน LINE แชทและ LIFF จำกัดตามตารางช่องทาง (§9.1 · P-5) เช่น การตั้งค่า DOA workflow และฟอร์มทำใน Workspace (เว็บและ PWA) เท่านั้น ไม่ทำใน LINE แชท LIFF หรืออีเมล
