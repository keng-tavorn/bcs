# ADR-003: LINE OA ก่อน และออกแบบ adapter ให้รองรับ LINE WORKS

- สถานะ: ตัดสินแล้ว
- วันที่: 2026-10-01
- ที่มา: ตารางเรื่องที่ต้องตัดสินใจในเอกสารต้นทาง (spec §18.1 · ภาคผนวก C: เอกสารต้นทางหัวข้อ 14 "เรื่องที่ต้องตัดสินใจ")

## บริบท

- LINE เป็นช่องทางหลักบนมือถือ ผู้อนุมัติและผู้บริหารใช้ LINE เป็นช่องทางหลัก (§2.1 · §17.1)
- ความเสี่ยง "พึ่ง LINE มากเกินไป" ควบคุมด้วย core แบบ headless อีเมลสำรอง และ adapter ที่รองรับช่องทางอื่น (§18.4)

## การตัดสินใจ

> ใช้ LINE OA ก่อน และออกแบบ adapter ให้รองรับ LINE WORKS

- ชั้น 1 ใช้ LINE OA ผ่าน Messaging API เท่านั้น (BR-LINE-09) · ตั้งค่า provider เดียว + Messaging API channel + MINI App channel + Login channel (§9.2 · P0-04)
- โค้ด LINE อยู่ใน `src/channels/line` เป็น adapter บาง ๆ ที่เรียก service ชุดเดียวกับเว็บ (§4.2 · P-1)
- adapter ของ LINE WORKS และ Microsoft Teams อยู่ใน S15 (FR-NOTI-301)

## ผลที่ตามมา

- เพิ่มช่องทาง = เขียน adapter ไม่แตะ core (EG-4)
- อีเมลเป็นช่องทางสำรองเสมอ: ส่ง LINE ไม่ได้ → งานอนุมัติถึงผู้รับทางอีเมลภายใน 5 นาที (FR-LINE-007 AC3 · NFR-AVL-03 · §9.6)
- OA แยกต่อองค์กรและลูกค้าเป็นเจ้าของเป็นค่าเริ่มต้น (OQ-15) · demo ใช้ provider และ channel ของ BCS เอง (§16.10 · D-02 · D-03)
- รายละเอียด adapter ของ LINE WORKS spec ไม่ได้ระบุ ต้องเขียนใน sub-spec ของ S15 (§8.11 · §16.2 ข้อ 7)
