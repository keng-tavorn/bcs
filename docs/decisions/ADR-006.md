# ADR-006: Inngest เป็นตัวจับเวลา สถานะอยู่ในฐานข้อมูลของเรา

- สถานะ: ตัดสินแล้ว
- วันที่: 2026-10-01
- ที่มา: ตารางเรื่องที่ต้องตัดสินใจในเอกสารต้นทาง (spec §18.1 · ภาคผนวก C: เอกสารต้นทางหัวข้อ 14 "เรื่องที่ต้องตัดสินใจ")

## บริบท

- ระบบต้องเตือนและส่งต่องานตาม SLA ย้ายงานตามช่วงรักษาการ ส่งสรุปรายวัน และทำงานตามรอบ (§4.6)
- ฐานข้อมูลของเราเป็นแหล่งความจริงของสถานะ กฎ DOA และงบ (§4.1)

## การตัดสินใจ

> ใช้ Inngest สำหรับเตือนและส่งต่อ กฎ DOA และสถานะคำขอเก็บในฐานข้อมูลของเราเอง

- Inngest เป็นแค่ตัวจับเวลาและคิวงาน (§4.1)
- หลักของทุก function: อ่านสถานะล่าสุดก่อนทำและจบทันทีถ้างานไม่เกี่ยวแล้ว · ทุก step idempotent · คำนวณเวลาด้วย SLA engine ของ core แล้วใช้ `step.sleepUntil` `step.waitForEvent` `cancelOn` เป็นตัวรอ · ชื่อ event ขึ้นต้น `bcs/` (§4.6)

## ผลที่ตามมา

- `src/server/jobs` ห้ามเก็บสถานะธุรกิจไว้ใน Inngest (§4.2) · งานที่ปิดแล้วไม่ถูกเตือนเพราะ job ตรวจสถานะล่าสุดก่อนส่ง (FR-NOTI-003 AC3)
- endpoint `/api/inngest` · local ใช้ Inngest Dev Server · ตั้ง signing key ทุก env ที่ไม่ใช่ local (§5.1) · บัญชีและ key อยู่ใน P0-07
- hosting ต้องเปิด `/api/inngest` ให้ Inngest เรียกได้ (ADR-032) · ส่ง event ผ่าน outbox (ADR-030) · `/api/health` ตรวจ Inngest (FR-PLT-008 AC1)
- ตรวจ API กับเอกสารของ SDK เวอร์ชันที่ติดตั้ง (§4.6) ถ้าต่างจนต้องเปลี่ยนการออกแบบให้หยุดและถาม (§17.4)
