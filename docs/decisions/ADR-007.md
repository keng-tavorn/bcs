# ADR-007: Supplier Portal เข้าด้วยลิงก์ + OTP

- สถานะ: ตัดสินแล้ว
- วันที่: 2026-10-01
- ที่มา: ตารางเรื่องที่ต้องตัดสินใจในเอกสารต้นทาง (spec §18.1 · ภาคผนวก C: เอกสารต้นทางหัวข้อ 14 "เรื่องที่ต้องตัดสินใจ")

## บริบท

- ผู้ขาย (ชั้น 2 ขึ้นไป) ส่งเอกสารซ้ำทุกครั้งและไม่รู้สถานะ PO (§2.1)
- ความเสี่ยง "ผู้ขายไม่ใช้พอร์ทัล" ควบคุมด้วยลิงก์ + OTP บนมือถือ และจัดซื้อกรอกแทนได้ (§18.4)

## การตัดสินใจ

> Supplier Portal เข้าด้วยลิงก์ + OTP

- `/portal/*` ใช้ session แยกจากผู้ใช้ภายในโดยสิ้นเชิง: ลิงก์ใช้ครั้งเดียว + OTP 6 หลัก อายุ 10 นาที ผิดได้ 5 ครั้ง (§9.8 · NFR-SEC-05)
- ผู้ขายเห็นเฉพาะข้อมูลของตน · ตั้ง rate limit ต่อ IP และต่อผู้ขาย (§9.8)

## ผลที่ตามมา

- มีเทสต์แยกข้อมูลผู้ขายแบบเดียวกับ INV-TEN-01 (§9.8)
- ไฟล์ที่ผู้ขายอัปโหลดต้องผ่านการสแกนไวรัส (`scanStatus = CLEAN`) ก่อนผู้ใช้ภายในดาวน์โหลด (§9.8 · NFR-SEC-08)
- role `SUPPLIER_CONTACT` ใช้ session แยก (§2.2) · enum ของ Event มี `channel = PORTAL` และ `actorType = SUPPLIER` รองรับไว้แล้ว (§4.5)
- ผู้ขายสมัครเองผ่านลิงก์ + OTP ใน S7 (FR-SUP-101 · โมดูล `SUPPLIER`)
- ช่องทางส่ง OTP (เช่น อีเมลหรือ SMS) spec ไม่ได้ระบุ ต้องกำหนดใน sub-spec ของ S7

## อ้างอิง

spec §2.1 · §2.2 · §4.5 · §4.11 · §9.8 · §18.4 · NFR-SEC-05 · NFR-SEC-08 · FR-SUP-101 · INV-TEN-01
