# ADR-008: DOA เริ่มที่งานจัดซื้อ โครงข้อมูลรองรับทุกเอกสาร

- สถานะ: ตัดสินแล้ว
- วันที่: 2026-10-01
- ที่มา: ตารางเรื่องที่ต้องตัดสินใจในเอกสารต้นทาง (spec §18.1 · ภาคผนวก C: เอกสารต้นทางหัวข้อ 14 "เรื่องที่ต้องตัดสินใจ")

## บริบท

- DOA และงบเป็นแกนกลางของ BCS (§1.2) · ขอบเขตเดิมใน proposal v1.2 ของ Release 1 คือ PR · งบประมาณ · รวม PR · PO · ตรวจรับและ variance · รายงาน 7 ฉบับ (§1.5)
- เอกสารอื่นที่ต้องใช้อำนาจอนุมัติ เช่น e-Memo สัญญา ใบสำคัญจ่าย และการโอนงบ อยู่ในแผนภายหลัง (§4.11)

## การตัดสินใจ

> DOA เริ่มเฉพาะงานจัดซื้อ แต่โครงข้อมูลรองรับทุกเอกสาร

- ชั้น 1 `DoaRule.documentType` มี `PURCHASE_REQUEST` `PURCHASE_ORDER` `GR_VARIANCE` และข้อกำกับนโยบาย `DOA_CHANGE` `ORG_AUTHORITY_CHANGE` (§6.2 · §7.4)
- engine รับ documentType เป็น input (`resolveRoute`) และเลือกข้อตาม documentType (BR-DOA-03) · `ApprovalRoute` อ้างเอกสารด้วย `subjectType` และ `subjectId` (§6.2)
- DOA ของเอกสารอื่นคือโมดูล `DOA_EVERYWHERE` ใน S15 (FR-DOA-301 · §4.11)

## ผลที่ตามมา

- เพิ่มประเภทเอกสารเป็นการตั้งค่าและข้อมูล ห้ามเขียนวงเงิน ตำแหน่ง หรือเส้นทางอนุมัติในโค้ด (P-2 · §17.3)
- lint ตรวจช่วงวงเงินแยกต่อ documentType (BR-DOA-08)
- ชั้น 2 ขึ้นไปใช้ DOA กับการอนุมัติผู้ขาย (FR-SUP-104) ใบแจ้งหนี้ (FR-AP-105) รอบจ่าย (FR-PAY-101) และการขอเกินงบ (FR-BUD-101)
- คำขอผู้ขายรายใหม่ในชั้น 1 เข้าคิวจัดซื้อ ไม่ผ่าน DOA (ค่าเริ่มต้นของ OQ-23)
