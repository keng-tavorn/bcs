# ADR-011: รับและจับคู่ใบแจ้งหนี้ใน S8 · Finance ยังลงบัญชีใน Express เอง

- สถานะ: ตัดสินแล้ว
- วันที่: 2026-10-01
- ที่มา: ตารางเรื่องที่ต้องตัดสินใจในเอกสารต้นทาง (spec §18.1 · ภาคผนวก C: เอกสารต้นทางหัวข้อ 14 "เรื่องที่ต้องตัดสินใจ")

## บริบท

- หลัก P-4 "ประสาน ไม่แทนที่" · BCS ไม่เป็นระบบบัญชีหรือ ERP และไม่ลงบัญชีแยกประเภท (NG-1) · Express ยังเป็นระบบบัญชีหลัก (A-06)
- ฝ่ายบัญชีวันนี้คีย์ซ้ำเข้า Express และจับคู่ด้วยมือ (§2.1)

## การตัดสินใจ

> BCS รับและจับคู่ใบแจ้งหนี้ใน S8 โดย Finance ยังลงบัญชีใน Express เอง

- ชั้น 1: ยืนยันใบกำกับแบบง่าย (§7.12 · BR-IVC-01 ถึง BR-IVC-05) และส่งออกไฟล์ให้ Express (§7.13 · BR-EXP-01 ถึง BR-EXP-04)
- S8 (โมดูล `PAY`): รับใบแจ้งหนี้หลายช่องทาง จับคู่ 3 ทางและ 2 ทางพร้อมเกณฑ์ความคลาดเคลื่อน จัดการรายการไม่ตรง ภาษีหัก ณ ที่จ่าย และตรวจใบซ้ำ (FR-AP-101 ถึง FR-AP-108 · BR-MATCH-01 ถึง BR-MATCH-04 · BR-WHT-01 · BR-WHT-02)

## ผลที่ตามมา

- schema ไม่มีตาราง GL หรือ journal (P-4) · รายงานรับของแล้วยังไม่มีใบกำกับไม่ลงบัญชีเอง (BR-RPT-02)
- รูปแบบไฟล์ Express ตั้งค่าได้ต่อองค์กรและรอไฟล์ตัวอย่างจากลูกค้า ห้ามเดารูปแบบ (OQ-10 · §7.13 · §17.3 · P0-10)
- Express API และ webhook อยู่ใน S14 (FR-INTG-301) · ระหว่างนี้ใช้ไฟล์เป็นสะพาน (§18.4)
- S8 ต้องขยายเป็น sub-spec ละเอียดก่อนเริ่ม (§7.14 · §16.2 ข้อ 7)
