# ADR-012: ไฟล์จ่ายเงินเริ่ม 1–2 ธนาคาร

- สถานะ: ตัดสินแล้ว
- วันที่: 2026-10-01
- ที่มา: ตารางเรื่องที่ต้องตัดสินใจในเอกสารต้นทาง (spec §18.1 · ภาคผนวก C: เอกสารต้นทางหัวข้อ 14 "เรื่องที่ต้องตัดสินใจ")

## บริบท

- BCS ไม่โอนเงินเองและไม่เชื่อม API ธนาคารเพื่อจ่าย ทำแค่ไฟล์ Batch Payment ในชั้น 2 (NG-2)
- ความเสี่ยง "รูปแบบไฟล์ธนาคารต่างกันและเปลี่ยนได้" (§18.4) · เป้า G-6 ไฟล์ที่ธนาคารตีกลับ 0 ไฟล์

## การตัดสินใจ

> ไฟล์จ่ายเงินเริ่ม 1–2 ธนาคารที่ LK-RICH ใช้จริง และถามธนาคารเรื่องรูปแบบไฟล์ที่กำหนดเอง

- S9: ไฟล์ Batch Payment 1–2 ธนาคาร พร้อมตรวจก่อนส่งออก (FR-PAY-102)
- P0-03 `[คน]` (ลูกค้า + ธนาคาร · ก่อน S9): ได้สเปกและไฟล์ตัวอย่างที่ผ่านระบบทดสอบของธนาคาร

## ผลที่ตามมา

- ตัวสร้างไฟล์แยกต่อธนาคาร golden test แบบ byte-exact + sha256 เทียบไฟล์ตัวอย่าง (BR-BANK-01)
- ก่อนส่งออกตรวจบัญชีผู้รับ ยอดรวม และรายการซ้ำ (BR-BANK-02) · ไฟล์ที่สร้างแล้วแก้ไม่ได้ สร้างใหม่ต้องมีเหตุผลและเป็นเวอร์ชันใหม่ (BR-BANK-03)
- ส่งออกไฟล์ได้ใน Workspace (เว็บและ PWA) เท่านั้น ไม่ทำใน LINE แชท LIFF หรืออีเมล (§9.1) · ต้องมีเทสต์ก่อนหรือพร้อมโค้ด (§16.2 ข้อ 4)
- S9 เสร็จเมื่อการเงินอัปโหลดไฟล์ทดสอบกับธนาคารได้และยอดรวมตรงรอบจ่าย (§16.8)
- ธนาคารที่จะเริ่ม spec ไม่ได้ระบุ รอ P0-03
