# ADR-013: อ่านเอกสารด้วย Claude API ให้คนยืนยัน ไม่เทรนโมเดล

- สถานะ: ตัดสินแล้ว
- วันที่: 2026-10-01
- ที่มา: ตารางเรื่องที่ต้องตัดสินใจในเอกสารต้นทาง (spec §18.1 · ภาคผนวก C: เอกสารต้นทางหัวข้อ 14 "เรื่องที่ต้องตัดสินใจ")

## บริบท

- Document Agent อ่านใบเสนอราคา ใบส่งของ และใบแจ้งหนี้ เพื่อเติมฟอร์มให้คนยืนยัน (FR-AI-303 · §8.12)
- ความเสี่ยง "Claude อ่านใบแจ้งหนี้ไทยไม่แม่น" (§18.4) · AI อยู่ในชั้น 4 เท่านั้น (EG-1 · NG-5)

## การตัดสินใจ

> อ่านเอกสารด้วย Claude API พร้อม schema ชุดทดสอบ และคนยืนยัน ไม่เทรนโมเดล

- ไม่เทรนหรือ fine-tune โมเดล (NG-6) · ใช้ API ที่ไม่นำข้อมูลไปเทรน ส่งข้อมูลเท่าที่จำเป็น ปิดบังเลขบัญชีและเลขบัตรประชาชน และบันทึกใน ROPA (BR-AI-08)
- ใช้ structured outputs กับ JSON schema ที่สร้างจาก Zod schema ชุดเดียวกับฟอร์ม · schema รับประกันรูปแบบ ไม่รับประกันว่าค่าถูก (BR-AI-10 · ADR-023)
- ผลเป็นร่างให้คนยืนยันหรือแก้ ค่าที่ความมั่นใจต่ำถูกไฮไลต์ (BR-AI-02)
- ชุดประเมินสร้างจากเอกสารจริงที่ลบข้อมูลอ่อนไหวแล้ว (P0-02) · ตัวอย่างเกณฑ์ใบแจ้งหนี้: ยอดรวม VAT เลขผู้เสียภาษี และเลขที่เอกสาร ถูกต้องอย่างน้อย 98% ต่อฟิลด์ (§12.4)

## ผลที่ตามมา

- Document Agent เป็นข้อแรกของ S13 (FR-AI-303) · ไม่มี AI ใน demo หรือชั้น 1 (§8.12) · ชั้น 1 อ่านไฟล์ e-Tax จาก XML โดยไม่ใช้ AI (BR-IVC-05)
- เปลี่ยนรุ่นโมเดลหรือ prompt ต้องรันชุดประเมินใหม่ (BR-AI-09) · ทุกการเรียกถูกบันทึก (BR-AI-04)
- Claude API key อยู่ใน secret manager และ `AI_ENABLED` เป็น false จนถึง S13 (P0-13) · Anthropic อยู่ในรายการ sub-processor (NFR-PRIV-06)
