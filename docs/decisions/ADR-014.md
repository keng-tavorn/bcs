# ADR-014: ตรวจตัวตนผู้ขายตั้งแต่ S4 · ข้อมูลความเสี่ยงเริ่มจากแบบประเมิน

- สถานะ: ตัดสินแล้ว
- วันที่: 2026-10-01
- ที่มา: ตารางเรื่องที่ต้องตัดสินใจในเอกสารต้นทาง (spec §18.1 · ภาคผนวก C: เอกสารต้นทางหัวข้อ 14 "เรื่องที่ต้องตัดสินใจ")

## บริบท

- ความเสี่ยง "ข้อมูลความเสี่ยงภายนอกในไทยหายากหรือแพง" ควบคุมด้วยการเริ่มจากแบบประเมิน (§18.4)
- เป้า G-9 ผู้ขายความเสี่ยงสูงต้องประเมินครบก่อนทำสัญญา 100% (ชั้น 3)

## การตัดสินใจ

> ตัวตนผู้ขายตรวจกับสรรพากรและ DBD ตั้งแต่ S4 (FR-SUP-001) · ข้อมูลความเสี่ยงเริ่มจากแบบประเมินและเอกสารที่ผู้ขายส่ง · แหล่งข้อมูลความเสี่ยงที่ต้องเสียเงินประเมินก่อน S11 และเชื่อมใน S14 (FR-INTG-303)

- S4: ค้นบริการ VAT Service ของกรมสรรพากรและ Open API ทะเบียนนิติบุคคลของ DBD แล้วเติมข้อมูลให้ผู้ใช้ยืนยัน (BR-SUP-01) · บุคคลธรรมดาตรวจเฉพาะสรรพากร ผู้ขายต่างประเทศข้ามการตรวจ (BR-SUP-02) · บริการล่มให้ยืนยันด้วยมือพร้อมหลักฐาน (BR-SUP-03) · ตรวจซ้ำรายเดือน (BR-SUP-04)
- ข้อมูลความเสี่ยง: เอกสารผู้ขาย (FR-SUP-102 · S7) และแบบประเมินตามคำตอบคัดกรอง (FR-RSK-201 · S11)
- FR-INTG-303 (S14) ใช้เฉพาะแหล่งข้อมูลความเสี่ยงที่ต้องเสียเงิน (§8.12)

## ผลที่ตามมา

- adapter มีโหมด `stub` และ `live` · เทสต์ใช้ stub เสมอ · ใช้ `live` ได้เมื่อตรวจแล้วว่าบริการยังเปิดและเรียกจาก hosting ได้ (BR-SUP-05 · OQ-37) · ค่าเริ่มต้น `REGISTRY_MODE=stub` (ภาคผนวก B)
- job `supplier-registry-recheck` รายเดือน (§4.6) · ชั้น 3 เปลี่ยนคำเตือนเป็นบล็อก (BR-SUP-04 · FR-RSK-205)
- ผู้ให้บริการข้อมูลความเสี่ยงแบบเสียเงิน และเกณฑ์ที่ใช้ประเมินแหล่งข้อมูลเหล่านี้ก่อน S11 spec ไม่ได้ระบุ
