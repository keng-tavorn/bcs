# ADR-018: เงินเป็น BigInt หน่วยสตางค์ อัตราเป็น basis point

- สถานะ: เสนอ
- วันที่: 2026-10-01
- ที่มา: เสนอโดย spec · ใช้ได้ทันทีเว้นแต่มีผู้คัดค้านใน PR (§18.1)

## บริบท

- ตรรกะเงินต้องเป็น pure function deterministic มี golden tests และ branch coverage 100% (EG-2)
- ความเสี่ยง "โค้ดที่ AI เขียนมีบั๊กเงียบในส่วนเงินและสิทธิ์" (§18.4)

## การตัดสินใจ

> เงินเป็น BigInt หน่วยสตางค์ อัตราเป็น basis point

- เงินทุกจำนวนเป็นจำนวนเต็มหน่วยสตางค์ (`bigint`) ห้ามใช้ float · รับและส่งออกนอกระบบเป็นสตริง `"12345.50"` (BR-MONEY-01)
- ในฐานข้อมูล: เงินเป็น `BigInt` ชื่อฟิลด์ลงท้าย `Satang` และ CHECK ≥ 0 · อัตราเป็น `Int` หน่วย basis point ลงท้าย `Bp` (7% = 700) · จำนวนเป็น `Decimal(18,4)` + `uom` (§6.1)
- จำนวน (ไม่ใช่เงิน) คำนวณด้วย decimal.js (§5.1)

## ผลที่ตามมา

- ปัดเศษแบบ half-up เฉพาะ 4 จุดใน BR-MONEY-02 ห้ามปัดที่อื่น · แสดงผลตาม BR-MONEY-03 · สูตร VAT จากราคารวมใช้ 10000 + rate (BR-VAT-03)
- DTO และ API ใช้ `{ "amount": "12345.50", "currency": "THB" }` แปลงด้วย helper เดียว `toMoneyDto` (§14.1)
- golden YAML เขียนเงินเป็นสตริงบาทแล้วแปลงเป็นสตางค์ตอนโหลด (§7.0) · property test `net + vat = gross` (§15.4)
- ห้ามใช้ `number` หรือ float กับเงิน (§17.3)
