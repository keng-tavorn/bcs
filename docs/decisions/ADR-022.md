# ADR-022: service layer เป็นทางเขียนข้อมูลทางเดียว

- สถานะ: เสนอ
- วันที่: 2026-10-01
- ที่มา: เสนอโดย spec · ใช้ได้ทันทีเว้นแต่มีผู้คัดค้านใน PR (§18.1)

## บริบท

- หลัก P-1 "หนึ่งแกนกลาง หลายประตูหน้า (Headless)" · การเพิ่มช่องทาง = เขียน adapter ไม่แตะ core (EG-4)

## การตัดสินใจ

> service layer เป็นทางเขียนข้อมูลทางเดียวของทุกช่องทาง

- ทุกช่องทาง (เว็บ LIFF LINE แชท PWA ลิงก์อีเมล Portal API) เป็น adapter บาง ๆ ที่เรียก application service ชุดเดียวกัน (§4.1)
- ทุกการเปลี่ยนสถานะผ่าน `runCommand()` ใน `src/server/services/_pipeline.ts`: idempotencyKey → ตรวจด้วย Zod → สร้าง `ctx` → ธุรกรรม (CommandLog · `SELECT … FOR UPDATE` + version · authorize + SoD · `core.decide` · เขียน aggregate ledger Event Outbox Notification CommandLog) → commit → ส่ง outbox (§4.3)

## ผลที่ตามมา

- `src/app` และ `src/channels` ห้ามเข้าถึงฐานข้อมูลตรง (§4.10 · §17.3) · server action เป็นแค่ตัวแปลง ห้ามมีตรรกะธุรกิจ (§14.1)
- ทุก Server Action และ Route Handler เป็น public endpoint ต้องตรวจตัวตนและสิทธิ์ใน service ทุกครั้ง (BR-AUTH-05)
- idempotency และ optimistic lock ตาม INV-PLT-01 ถึง INV-PLT-03 · ทุกการเปลี่ยนสถานะสร้าง Event (INV-EVT-02)
- service คืน DTO ไม่คืน model ของ Prisma (§14.1)
