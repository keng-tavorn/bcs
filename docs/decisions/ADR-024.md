# ADR-024: LIFF app เดียวต่อ environment และตรวจ ID token เองที่เซิร์ฟเวอร์

- สถานะ: เสนอ
- วันที่: 2026-10-01
- ที่มา: เสนอโดย spec · ใช้ได้ทันทีเว้นแต่มีผู้คัดค้านใน PR (§18.1)

## บริบท

- LINE แนะนำให้สร้าง LIFF app ใหม่เป็น LINE MINI App · MINI App channel มี 3 internal channel (Developing · Review · Published) และแต่ละตัวมี LIFF ID ของตัวเอง (§9.2)
- ID token จาก MINI App channel มี `aud` ไม่ตรงกับ LINE Login channel จึงพึ่งการตรวจ `aud` ของ LINE provider ใน Better Auth ไม่ได้ (BR-LINE-02)

## การตัดสินใจ

> LIFF app เดียวต่อ environment ที่ `/liff` และตรวจ ID token เองที่เซิร์ฟเวอร์

- LIFF app เดียวต่อ internal channel · endpoint คือ `/liff` และหน้าย่อยเป็น path ต่อท้าย (§9.2)
- LIFF ID ต่อ environment ผ่าน `NEXT_PUBLIC_LIFF_ID`: local/staging = Developing · UAT = Review · production = Published (§9.2)
- ตัวตนใน LIFF มาจาก `liff.getIDToken()` ที่ส่งไปตรวจที่เซิร์ฟเวอร์เท่านั้น (BR-LINE-01) · ตรวจกับ endpoint verify ของ LINE ด้วย `LINE_LIFF_CHANNEL_ID` ตรวจ `aud` และ `exp` แล้วใช้ `sub` เป็น LINE userId ผ่าน plugin `liffIdToken` ที่สร้าง session ด้วย API ภายในของ Better Auth (BR-LINE-02)

## ผลที่ตามมา

- route `/api/liff/session` และ `/api/liff/link` (§9.1) · session LIFF idle 15 นาที ต่ออายุเงียบ ๆ ด้วย ID token ใหม่ (§9.4 · NFR-SEC-04)
- ถ้า API ของ Better Auth ในเวอร์ชันที่ติดตั้งไม่รองรับการสร้าง session แบบนี้ ให้หยุดและถาม (BR-LINE-02)
- ค่าเริ่มต้นของ OQ-16 คือ MINI App channel พร้อมตรวจ ID token เอง · ตรวจเงื่อนไขการเผยแพร่ MINI App ในไทยตั้งแต่ Phase 0 (§9.2)
- ก่อน go-live ต้องมี LIFF ของ channel Published (§16.9)
