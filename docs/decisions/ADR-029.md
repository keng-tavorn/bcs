# ADR-029: แยก tenant ด้วย Prisma extension (RLS ภายหลัง)

- สถานะ: เสนอ
- วันที่: 2026-10-01
- ที่มา: เสนอโดย spec · ใช้ได้ทันทีเว้นแต่มีผู้คัดค้านใน PR (§18.1)

## บริบท

- LK-RICH ใช้งาน tenant เดียวบนระบบที่ออกแบบเป็น multi-tenant (ตารางหัวเอกสาร spec) · 1 tenant = 1 นิติบุคคล (A-01)
- ทุกตาราง tenant มี `organizationId` ตั้งแต่ migration แรก (EG-5)

## การตัดสินใจ

> แยก tenant ด้วย Prisma extension และเทสต์ที่สร้างอัตโนมัติ (RLS ภายหลัง)

- เข้าถึงข้อมูลผ่าน `db.forTenant(ctx.organizationId)` (Prisma client extension ที่เติม `where` และ `data`) เท่านั้น (§4.8)
- raw SQL อยู่ได้เฉพาะ `src/server/db/sql/*.ts` และรับ `organizationId` เป็นพารามิเตอร์ชัดเจน · ESLint ห้าม `$queryRawUnsafe` ทุกที่ และห้าม `$queryRaw` นอกโฟลเดอร์นี้ (§4.8)
- ตารางที่ไม่ผูก tenant มีเท่านั้น: ตารางของ Better Auth · `TaxRate` · `PlatformAdmin` · `BreakGlassSession` (§4.8)
- Postgres RLS ทำเมื่อเปิด multi-tenant เต็มรูปแบบ (§4.8) ซึ่งอยู่ใน S15 (FR-PLT-303)

## ผลที่ตามมา

- เทสต์อ่าน Prisma DMMF หาทุก model ที่มี `organizationId` (นับเอง ไม่ hardcode) สร้าง 2 องค์กร แล้วตรวจ INV-TEN-01 (§4.8 · §15.3 · FR-PLT-001 AC3)
- INV-TEN-02: `organizationId` NOT NULL มี index และ unique constraint ทางธุรกิจรวม `organizationId` เสมอ
- Supplier Portal มีเทสต์แยกข้อมูลผู้ขายแบบเดียวกับ INV-TEN-01 (§9.8)
- PLATFORM_ADMIN เข้าข้อมูล tenant ได้เฉพาะ break-glass (BR-AUTH-03)
