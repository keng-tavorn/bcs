# ADR-032: Hosting เว็บ

- สถานะ: ตัดสินแล้วเฉพาะ staging (ผู้ใช้ 2026-10-02) · production ยังไม่ตัดสิน
- วันที่: 2026-10-02 (แถวเดิมใน spec ฉบับ 0.2 ลงวันที่ 1 ต.ค. 2026)
- ที่มา: spec §18.1 เดิมเป็น "ยังไม่ตัดสิน" · ผู้ใช้ตัดสินเรื่อง staging เมื่อ 2026-10-02 · production ยังต้องยืนยันภายหลัง

## บริบท

- ข้อความเดิมใน spec §18.1: "Hosting เว็บ (Vercel · AWS · ผู้ให้บริการในไทย) ต้องอยู่ภูมิภาคเดียวกับฐานข้อมูลและเปิด endpoint ให้ Inngest — ชั่วคราวใช้ staging ที่ภูมิภาคสิงคโปร์กับข้อมูลสังเคราะห์เท่านั้น"
- เส้นชัย A ต้องเปิด staging จาก URL จริงได้และ `/api/health` ตอบ 200 (ส่วน "เริ่มที่นี่") · P0-08 `[คน]` เลือก hosting (§16.1)

## การตัดสินใจ

> (ผู้ใช้ตัดสิน 2026-10-02) staging ใช้ Vercel ภูมิภาคสิงคโปร์ (sin1)

- วิธี deploy ตามแผนงานที่ผู้ใช้อนุมัติ (2026-10-02): staging เป็นโปรเจกต์ Vercel แยก (ชื่อ `bcs-staging` ตามคู่มือ `docs/runbooks/p0-08-vercel.md` · แผนไม่ได้ระบุชื่อ) และ deploy ด้วย `vercel deploy --prod` · `--prod` คือ URL หลักของโปรเจกต์ staging นี้ ไม่ใช่ production ของ BCS (`APP_ENV` ยังเป็น `staging`)
- hosting ของ production ยังไม่ตัดสิน ต้องยืนยันภายหลัง (ตัวเลือกเดิม: Vercel · AWS · ผู้ให้บริการในไทย)

## ผลที่ตามมา

- sin1 อยู่ภูมิภาคเดียวกับ Neon สิงคโปร์ (ADR-010) · ต้องเปิด `/api/inngest` ให้ Inngest เรียกได้และตั้ง signing key (§5.1 · ADR-006) · route ที่แตะฐานข้อมูลใช้ Node runtime ห้าม Edge (§5.1)
- เว็บที่ deploy บน Vercel ตาม ADR นี้คือ env `staging` ของ BCS (§4.12) ไม่ใช่ production จึงตั้ง `APP_ENV=staging` (ภาคผนวก B) · ใช้ seed และข้อมูลสังเคราะห์เท่านั้นจนกว่า OQ-19 ปิด (§4.12 · §17.3)
- การ migrate และ seed ครั้งแรกบน staging ผู้ใช้อนุมัติแล้ว (2026-10-02) · การ reset หรือแก้ข้อมูลบน staging ครั้งต่อไปต้องขอผู้ใช้ก่อน (§17.4) · D-07 เสร็จเมื่อคำสั่ง reset ใน runbook รันบน staging (§16.10) จึงต้องขอผู้ใช้ก่อนรัน
- ยังไม่มี GitHub repo (ผู้ใช้ 2026-10-02: commit บนเครื่องเท่านั้น) จึงยังทำไม่ได้: รัน `pnpm verify` ใน CI ทุก PR (FR-PLT-006 AC1) และ deploy อัตโนมัติเมื่อ merge `main` (EG-3 · FR-PLT-006 AC2) · ทั้งสองเรื่องอยู่ใน "เสร็จเมื่อ" ของ S1-14
- ต้องตรวจว่าบริการสรรพากรและ DBD เรียกจาก hosting นี้ได้ก่อนใช้โหมด `live` (OQ-37) · hosting อยู่ในรายการ sub-processor พร้อมสัญญา DPA (NFR-PRIV-06)
- spec §18.1 และแถว Hosting ใน §5.1 ปรับให้ตรงกับ ADR นี้แล้วใน NEW-01 (spec.md มีลำดับเหนือ ADR · §0.1)
- P0-08 `[คน]` ยังไม่เสร็จ: เสร็จเมื่อ agent deploy staging ได้ด้วย token ที่ผู้ใช้ให้ (บัญชีและ token ของ Vercel) และยังรอ inbox อีเมลสำหรับ demo (ADR-031) · agent ห้ามติ๊กเอง
