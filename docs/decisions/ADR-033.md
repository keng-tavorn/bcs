# ADR-033: ที่เก็บไฟล์

- สถานะ: ยังไม่ตัดสิน
- วันที่: 2026-10-01 (เพิ่มหมายเหตุ 2026-10-02)
- ที่มา: ยังไม่ตัดสินใน spec · ระหว่างรอใช้ค่าชั่วคราวที่ระบุ (§18.1)

## บริบท

- ระบบเก็บไฟล์แนบ เช่น ใบเสนอราคา ใบส่งของ รูปตรวจรับ ใบแจ้งหนี้ PDF ของ PO และไฟล์ e-Tax (`FileLink.kind` · §6.2) · อัปโหลดและดาวน์โหลดไฟล์ตั้งแต่ S1 (FR-PLT-004)

## การตัดสินใจ

> ที่เก็บไฟล์ (Cloudflare R2 · S3 · Neon Object Storage) — ชั่วคราวบนเครื่องใช้ RustFS ผ่าน S3 API (ADR-036)

- โค้ดใช้ S3 API (`@aws-sdk/client-s3` + presigner) กับ bucket private (§5.1)
- P0-06 `[คน]`: ทดสอบ Neon Object Storage ถ้าไม่ผ่านใช้ R2 หรือ S3 · เสร็จเมื่ออัปโหลดและดาวน์โหลดผ่าน presigned URL บน staging ได้

## ผลที่ตามมา

- NFR-SEC-08: allowlist ชนิดไฟล์และตรวจ magic bytes · ขนาดไม่เกิน 20 MB · bucket private · presigned URL อายุไม่เกิน 5 นาที · ไฟล์จากภายนอกต้องสแกนไวรัส
- ตั้งค่าผ่าน `S3_ENDPOINT` `S3_REGION` `S3_BUCKET` `S3_ACCESS_KEY_ID` `S3_SECRET_ACCESS_KEY` `S3_FORCE_PATH_STYLE` (ภาคผนวก B) · `/api/health` ตรวจ storage (FR-PLT-008 AC1)
- ผู้ให้บริการที่เก็บไฟล์อยู่ในรายการ sub-processor พร้อมสัญญา DPA (NFR-PRIV-06)
- ไม่ใช้ Vercel Blob และไม่เก็บไฟล์ลงดิสก์ของเซิร์ฟเวอร์ (CLAUDE.md §5)

## หมายเหตุ (2026-10-02)

- ตัวแทน S3 บนเครื่องใช้ RustFS 1.0 แทน MinIO (สำรอง bitnamilegacy/minio) เพราะ image ทางการของ MinIO ถูกลบแล้ว ผู้ใช้ตัดสินตาม ADR-036 ซึ่งเก็บรายละเอียดและหลักฐาน · โค้ดยังเรียกผ่าน S3 API เหมือนเดิม
- S1-10 เดิมเขียนว่าเทสต์ต้องผ่าน "กับ MinIO" · NEW-01 ปรับเป็น "กับที่เก็บไฟล์บนเครื่อง (RustFS · ADR-036)" แล้ว
- ที่เก็บไฟล์ของ staging และ production ยังไม่ตัดสิน (P0-06)
