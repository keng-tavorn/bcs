# ADR-035: ลูกค้าเป็นเจ้าของ DOA และโครงสร้างอำนาจ

- สถานะ: ตัดสินแล้ว
- วันที่: 2026-10-01
- ที่มา: การตัดสินใจของเจ้าของโปรเจกต์ (spec §18.1)

## บริบท

- ลูกค้าต้องดูแลอำนาจอนุมัติเองครบวงจร โดยไม่มี deploy และไม่มีการกระทำของ PLATFORM_ADMIN (G-11 · EG-8)
- ความเสี่ยง ORG_ADMIN คนเดียวเปลี่ยนตัวผู้มีอำนาจจริง (§18.4)

## การตัดสินใจ

> ลูกค้าเป็นเจ้าของ DOA และโครงสร้างอำนาจ แก้ได้เองผ่าน 4-eyes + step-up ส่วน BCS คุมเฉพาะกลไกและกติกาความปลอดภัย

- ลูกค้าเป็นเจ้าของนโยบาย ได้แก่ DOA ผู้ดำรงตำแหน่ง และผังองค์กร · BCS เป็นเจ้าของกลไกและกติกาความปลอดภัยที่ลูกค้าแก้ไม่ได้ (§1.2)
- DOA เปลี่ยนผ่าน นำเข้าไฟล์หรือแก้บนหน้าจอ → lint → diff → ทดลองส่ง → 4-eyes + step-up (§1.5 · FR-DOA-001 · FR-DOA-002 · FR-DOA-009) · โครงสร้างอำนาจเปลี่ยนผ่าน `OrgAuthorityChange` ที่อนุมัติตามข้อ `ORG_AUTHORITY_CHANGE` (FR-DOA-010 · BR-DOA-17)
- ผู้ส่งหรือผู้เสนอห้ามเป็นผู้อนุมัติ (BR-SOD-06 · BR-SOD-08) และผู้อนุมัติต้อง step-up ทุกครั้งไม่ขึ้นกับยอด (BR-DOA-15)
- PLATFORM_ADMIN และทีม BCS ไม่ร่าง ไม่แก้ และไม่อนุมัติเนื้อหา DOA หรือโครงสร้างอำนาจของลูกค้าในระบบ · ช่วยอธิบายหรือรีวิวแม่แบบนอกระบบได้ แต่ผู้ส่งและผู้อนุมัติต้องเป็นคนของลูกค้า (NG-12)

## ผลที่ตามมา

- ชุดตั้งต้นอนุมัติโดยผู้มีอำนาจลงนามตามสัญญา PLATFORM_ADMIN ยืนยันแค่ตัวตนและไม่เห็นเนื้อหา (BR-DOA-19 · OQ-31)
- lint บังคับให้มีข้อ `DOA_CHANGE` และ `ORG_AUTHORITY_CHANGE` ที่หาผู้อนุมัติได้ กันลูกค้าล็อกตัวเองออกจากระบบ (BR-DOA-08 ข้อ จ) · การเปลี่ยนที่ทำให้ผู้อนุมัติของสองข้อนี้หาไม่ได้ถูกปฏิเสธ เว้นแต่แต่งตั้งผู้แทนในคำขอเดียวกัน (BR-DOA-17 · OQ-32)
- ห้ามให้ PLATFORM_ADMIN สคริปต์ หรือ migration ของ BCS สร้าง แก้ หรือเผยแพร่ DOA หรือโครงสร้างอำนาจของลูกค้า ยกเว้น seed ขององค์กรตัวอย่างใน local และ staging · ห้ามเขียนโค้ดที่เปลี่ยนผู้ดำรงตำแหน่งที่ DOA อ้าง ย้ายแผนก หรือตั้งรักษาการแทนผู้อื่น นอกเส้นทาง `OrgAuthorityChange` (§17.3) · มีเทสต์สแกนเส้นทางเขียนข้อมูล (§15.3)
- ORG_ADMIN คนเดียวเผยแพร่ DOA ไม่ได้ (BR-AUTH-02) และควรมีอย่างน้อย 2 คนต่อองค์กร (§2.2 · §16.9) · AUDITOR เห็นประวัติการเปลี่ยนนโยบาย (FR-DOA-011)
