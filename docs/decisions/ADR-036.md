# ADR-036: ที่เก็บไฟล์บนเครื่องใช้ RustFS แทน MinIO

- สถานะ: ตัดสินแล้ว (ผู้ใช้ 2026-10-02)
- วันที่: 2026-10-02
- ที่มา: ผู้ใช้ตัดสินในรอบวางแผน 2026-10-02 (ข้อ 4 ของตารางการตัดสินใจใน ADR-038)

## บริบท

- spec ใช้ MinIO เป็นตัวแทน S3 บนเครื่อง (§5.1 §5.3 · ADR-025 · ADR-033) แต่ image ทางการ `minio/minio` และ `minio/mc` ถูกลบจาก Docker Hub เมื่อ 2026-09-11 และ quay.io กับ dl.min.io ไม่ให้ดาวน์โหลดแล้ว (ตรวจตอนวางแผน 2026-10-02)
- โค้ดเรียกที่เก็บไฟล์ผ่าน S3 API เท่านั้น (`@aws-sdk/client-s3` + presigner) จึงเปลี่ยนตัวแทนบนเครื่องได้โดยไม่แก้โค้ดของแอป

## การตัดสินใจ

> (ผู้ใช้ตัดสิน 2026-10-02) บนเครื่องใช้ RustFS 1.0 เป็นตัวแทน S3 · ถ้าการอัปโหลดจาก browser ผ่าน presigned URL ไม่ผ่าน ให้ถอยไปใช้ `bitnamilegacy/minio` โดยไม่ต้องถามซ้ำ

- `docker-compose.yml` ใช้ `rustfs/rustfs:1.0.0` ที่พอร์ต 9000 (S3 API) และ 9001 (หน้าจัดการ) ตามพอร์ตเดิมของ MinIO (CLAUDE.md §7)
- เทสต์ตัดสิน: `tests/e2e/storage-presign.spec.ts` อัปโหลดและดาวน์โหลดจาก browser จริงผ่าน presigned URL พร้อมกฎ CORS ของ bucket ผ่านกับ RustFS (S1-02 · 2026-10-02) จึงไม่ต้องใช้ทางสำรอง
- ชื่อตัวแปรใน `.env` ยังเป็นชุดเดิม (`S3_ENDPOINT` `S3_ACCESS_KEY_ID` …) ตามภาคผนวก B

## ผลที่ตามมา

- ข้อความใน spec ที่เขียนว่า MinIO (§5.1 §5.3 · S1-02 · S1-10 "ผ่านกับ MinIO") และ CLAUDE.md §5 §7 ปรับเป็น RustFS ใน NEW-01 · ภาคผนวก B ไม่เปลี่ยน: ค่าตัวอย่างของ `S3_ACCESS_KEY_ID` และ `S3_SECRET_ACCESS_KEY` ที่มีคำว่า minio เป็นรหัสบนเครื่องที่ RustFS ใน `docker-compose.yml` ใช้ร่วม ไม่ใช่ชื่อบริการ
- ที่เก็บไฟล์ของ staging และ production ยังไม่ตัดสิน (ADR-033 · P0-06) · ข้อนี้กำหนดเฉพาะบนเครื่องและเทสต์
- ถ้า RustFS ทำงานต่างจาก S3 จริงในเรื่องที่ระบบใช้ (presigned URL · CORS · path style) ให้เพิ่มเทสต์ที่จับได้ก่อนเปลี่ยนตัวแทน
