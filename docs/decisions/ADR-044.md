# ADR-044: สร้าง PDF ของ PR และ PO ด้วย react-pdf พร้อมแก้การวางวรรณยุกต์และสระอำ

- สถานะ: เสนอ
- วันที่: 2026-10-03
- ที่มา: ตัดสินหลัง spike ของ S4-05 (OQ-18) · ลองทั้งสองวิธีที่ §5 ให้เลือก แล้วตรวจภาพของทั้งสองเองก่อนเลือก · agent เสนอ ใช้ได้ทันทีเว้นแต่ผู้ใช้คัดค้าน

## บริบท

- §5 ให้เลือกระหว่าง headless Chromium กับ `@react-pdf/renderer` พร้อมฟอนต์ไทย เกณฑ์คือตัดคำไทย สระ และวรรณยุกต์ถูกต้อง ตรวจด้วย snapshot ภาพ (FR-PLT-009 AC3) และแผนให้ดูขนาด function และเวลาเริ่มทำงานบน Vercel ด้วย
- PDF ของ PO ถูกสร้างภายในคำสั่งส่ง PO ที่มีเวลาธุรกรรม 20 วินาที (ADR-043) และดาวน์โหลดได้ตามต้องการ
- spike ใช้ข้อมูลไทยที่ยาก (ที่ น้ำ ปั๊ม ผู้ใหญ่ ญี่ปุ่น ฤๅษี ฎีกา ฐาน ปฏิบัติ ข้อความยาวไม่มีวรรค PO 40 บรรทัด) วัดบน Windows และใน Linux container แบบเดียวกับ Vercel

## ผลของ spike

| เรื่อง | react-pdf 4.9.0 | Chromium 153 (playwright-core + @sparticuz/chromium) |
| --- | --- | --- |
| ภาษาไทย | ถูกเมื่อแก้ 2 จุด: วรรณยุกต์หายเข้าตัวอักษรหางยาว (บั๊กของ @react-pdf/render) และ "ำ" ทำให้ตัวท้ายบรรทัดหายและตัดกลางคำ (cache ของ fontkit) | ถูกเองด้วย HarfBuzz และพจนานุกรม ICU |
| ตัดคำ | ต้องส่งจุดตัดเองด้วย Intl.Segmenter | ตัดเอง |
| ขนาดบน Vercel | ราว 4.4 MB ที่ไฟล์ trace ได้ | ราว 73 MB |
| เริ่มทำงานครั้งแรก | ราว 0.5–1 วินาที | ราว 1.6–4.5 วินาที (แตกไฟล์ Chromium) |
| หน่วยความจำ | ราว 0.3 GB | ราว 0.45 GB |
| ผลบน Windows กับ Linux | ภาพเหมือนกันทุกพิกเซล | ต่างกันราว 0.5% ของพิกเซล |
| ข้อความใน PDF | "ำ" เก็บเป็น ํ + า (ค้นหาคำที่มี ำ ในโปรแกรมอ่าน PDF ไม่เจอ) | เก็บเป็น ำ |

## การตัดสินใจ

1. ใช้ `@react-pdf/renderer` 4.9.0 กับ Sarabun (`assets/fonts/sarabun`, OFL) ใน `src/server/pdf/`: `printable.ts` สร้างข้อมูลที่จัดรูปแล้ว (วันที่ พ.ศ. จำนวนเงิน คำอ่าน) · `document.tsx` วางหน้า A4 · `render.ts` แปลงเป็น PDF
2. แก้วรรณยุกต์ด้วย `pnpm patch` ของ `@react-pdf/render@4.7.0` สองบรรทัด (offset ของ mark ต้องคูณ scale เหมือน advance) ใน `patches/` และควรส่งแก้ให้ต้นทาง
3. แก้ "ำ" และจุดตัดคำใน callback เดียว (`thai-breaks.ts`): หาคำด้วย Intl.Segmenter แล้วคั่นด้วยพยางค์ว่าง (ตัดบรรทัดได้โดยไม่มีขีด) และแปลง ำ เป็น ํ + า ก่อนถึง fontkit (ภาพเหมือนเดิม)
4. ล็อกเวอร์ชัน `@react-pdf/renderer` แบบตรงตัว และ `@react-pdf/render` `@react-pdf/textkit` `fontkit` ด้วย overrides ใน `pnpm-workspace.yaml` เพราะการแก้ทั้งสองจุดพึ่งรายละเอียดภายในของเวอร์ชันนี้
5. เทสต์ภาพ: ทุกหน้าของ PO 3 บรรทัด PO 40 บรรทัด และ PR ถูก rasterize ด้วย poppler ใน image `pdf-raster` ของ docker-compose แล้วต้องตรงกับภาพใน `tests/snapshots/pdf/` ทุกไบต์ อัปเกรด library เมื่อไรต้องดูภาพใหม่ก่อน commit (`UPDATE_PDF_SNAPSHOTS=1`)
6. ไฟล์ฟอนต์และ standard font ของ pdfkit ส่งไปกับ route ที่สร้าง PDF ผ่าน `outputFileTracingIncludes` ใน `next.config.ts` · route ใช้ Node.js runtime

## ผลที่ตามมา

- PDF เล็ก เริ่มเร็ว และเหมือนกันทุกเครื่อง เทสต์ภาพจึงเทียบได้ตรงทั้งบนเครื่องผู้พัฒนาและ CI
- อัปเกรด react-pdf หรือ fontkit ต้องทำตั้งใจพร้อมกันทั้งชุด และดูภาพ snapshot ก่อน
- ค้นหาคำที่มี "ำ" ใน PDF ไม่เจอ คัดลอกแล้วได้ ํ + า (ดูเหมือนกัน) ยอมรับได้เพราะ PDF เป็นเอกสารพิมพ์
- แถวที่ยาวเกินหนึ่งหน้าแยกไม่ได้ คำอธิบายรายการมีความยาวจำกัดอยู่แล้ว
- PDF ไม่มีโครงสร้างสำหรับการเข้าถึง (untagged) และไม่ใช่ PDF/A
- เทสต์: `tests/integration/pdf-snapshot.test.ts` `tests/integration/printed-documents.test.ts` `tests/unit/pdf-thai-breaks.test.ts`
