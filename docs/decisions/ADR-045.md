# ADR-045: ค่า LINE ต่อองค์กร: เข้ารหัส secret และปุ่มทดสอบการเชื่อมต่อ

- สถานะ: เสนอ (ข้อ 2 และข้อ 6 รอผู้ใช้ยืนยัน)
- วันที่: 2026-10-04
- ที่มา: S5-01 (FR-ADM-006 AC2 AC3) · docs/sub-specs/S5.md แถว "ค่า channel ต่อองค์กร" และ "ปุ่มทดสอบ" · agent เสนอ ใช้ได้ทันทีเว้นแต่ผู้ใช้คัดค้าน

## บริบท

- แต่ละองค์กรมี LINE OA ของตัวเอง (OQ-15) จึงเก็บค่า channel หนึ่งแถวต่อองค์กรใน `LineChannelConfig`
- channel secret และ access token เป็นความลับระดับที่ใครได้ไปก็ส่งข้อความในนามลูกค้าได้ ต้องเข้ารหัสในฐานและไม่แสดงซ้ำ
- ORG_ADMIN ต้องรู้ได้เองว่าตั้งค่าครบหรือยังก่อนวัน demo (D-03) โดยไม่ต้องเปิดเครื่องมือของ LINE

## การตัดสินใจ

1. **รูปแบบค่าที่เข้ารหัส** `v1.<kid>.<iv>.<ciphertext>.<tag>` แบบ base64url ด้วย AES-256-GCM (IV สุ่ม 12 ไบต์ tag 16 ไบต์) key คือ `ENCRYPTION_KEY` · `kid` = 8 ตัวแรกของ sha256 ของ key · associated data = เวอร์ชัน + kid + `LineChannelConfig:<orgId>:<field>` ค่าที่ย้ายไปแถวหรือช่องอื่นจึงถอดไม่ได้ · เปลี่ยน key ผ่าน `SecretKeyring.previous` และ `needsResealing()` (ยังไม่มีตัวแปร `ENCRYPTION_KEY_PREVIOUS` จนกว่าจะต้องหมุน key จริง)
2. **การแสดงหลังบันทึก** แสดงเพียงว่าตั้งแล้วหรือยัง ไม่แสดงตัวอักษรใดของ secret หรือ token (ร่างแรกแสดง 4 ตัวท้าย ซึ่งเปิดเผย 16 จาก 128 บิตของ secret จึงเลือกทางที่ปลอดภัยกว่า) — รอผู้ใช้ยืนยัน
3. **เปลี่ยน Provider ID** ถูกปฏิเสธ (`PROVIDER_IN_USE`) ระหว่างที่ยังมีสมาชิกผูก LINE ภายใต้ provider เดิม เพราะ LINE user id ต่างกันตาม provider · คำสั่งผูกบัญชีล็อกแถว Organization เดียวกัน (`lockLineChannelForLinking`) จึงไม่มีการผูกแทรกระหว่างเปลี่ยน
4. **กันแก้ทับกัน** หลังบันทึกครั้งแรก การบันทึกต้องส่ง `expectedVersion` ที่ตรงกับปัจจุบัน ไม่ตรงได้ `CONFLICT_VERSION` (INV-PLT-02)
5. **บันทึกด้วย command ของ ORG_ADMIN** และ event `organization.settings_updated` ส่วน `lineChannel` ที่ไม่มีค่าลับ · seed ใช้ command เดียวกันในนาม ORG_ADMIN คนแรกบนช่องทาง SYSTEM key กันซ้ำ `seed:line-channel` และไม่ส่ง outbox
6. **seed เปิดช่องทาง LINE (`active=true`)** เมื่อ `.env` มีค่า LINE ที่จำเป็นครบ 4 ค่า · บน staging ที่ใช้ channel จริงของ D-03 สมาชิกตัวอย่างที่ผูก LINE จะได้ข้อความทาง LINE ทันที ซึ่งเป็นสิ่งที่ demo ต้องการ — รอผู้ใช้ยืนยัน
7. **ปุ่มทดสอบ** ตรวจ access token ก่อน แล้วตรวจอีก 3 ข้อของ LINE พร้อมกันภายใน 8 วินาที (`LINE_CONNECTION_TEST_BUDGET_MS`) ข้อที่ยังไม่ตอบรายงานว่าติดต่อไม่ได้ (TIMEOUT) · webhook URL มาจาก `APP_URL` เสมอ ไม่รับจากผู้เรียก · ระหว่างที่ ADR-024 ยังใช้ LIFF app เดียว ข้อ LIFF ต้องตรงกับ `NEXT_PUBLIC_LIFF_ID` และ `LINE_LIFF_CHANNEL_ID` ถ้า OQ-15 นำไปสู่ LIFF ต่อลูกค้า ADR-024 `liff.ts` และข้อนี้ต้องเปลี่ยนพร้อมกัน
8. **ขนาดของ Flex** ยึดการอ่านแบบเข้มของคำว่า KB ในเอกสาร LINE (29 KiB และ 48 KiB) · คำตอบจริงของ LINE เมื่อ push ถึงผู้ที่บล็อก OA ยังไม่ยืนยันจนกว่าจะทำ D-03 (NEW-44)
9. **ตรวจ ID token ของ LIFF** อยู่ที่ `src/server/auth/liff.ts` ที่เดียว (BR-LINE-02)

## ผลที่ตามมา

- ฐานข้อมูลที่หลุดออกไปไม่มี secret ของ LINE ที่ใช้ได้ ถ้าไม่มี `ENCRYPTION_KEY` ด้วย · หมุน `ENCRYPTION_KEY` ต้องทำพร้อม reseal ทุกแถว
- องค์กรที่ย้าย provider ต้องให้สมาชิกยกเลิกผูกก่อน (ไม่มีการยกเลิกผูกอัตโนมัติ)
- หน้า `/admin/line` บอกได้เองว่าค่าใดยังขาดและแก้อย่างไร
