# ADR-046: session ของ LIFF และ webhook ของ LINE

- สถานะ: เสนอ (ข้อ 3 และข้อ 4 รอผู้ใช้ยืนยัน)
- วันที่: 2026-10-04
- ที่มา: S5-02 S5-03 (FR-LINE-005 · FR-AUTH-003 · BR-LINE-02 ถึง 05) · ต่อจาก ADR-040 (plugin `liffIdToken`) · agent เสนอ ใช้ได้ทันทีเว้นแต่ผู้ใช้คัดค้าน

## บริบท

- LIFF เปิดในแอป LINE ผู้ใช้เข้าด้วย ID token ของ LINE อย่างเดียว ไม่มีรหัสผ่านหรือ TOTP ในขั้นนั้น
- webhook ของ LINE ต้องตอบเร็ว (LINE รอไม่นาน) และส่งซ้ำได้ ส่วนการตัดสินงานต้องทำครั้งเดียวและเรียงลำดับถูก

## การตัดสินใจ: LIFF session

1. `POST /api/liff/session` รับเฉพาะ `{idToken}` ไม่เกิน 16 KiB ตรวจว่ามาจาก site เดียวกัน แล้วส่งต่อ `/api/auth/liff/session` ของ Better Auth · ทั้งสองทางตรวจ same-site เอง เพราะ Better Auth ข้ามการตรวจของตัวเองเมื่ออยู่ในโหมดทดสอบ
2. เข้าได้เมื่อมี `ChannelIdentity` ที่ยังผูกภายใต้ provider ของ channel · member เป็น ACTIVE และมีผู้ใช้ · องค์กร ACTIVE · channel เปิดใช้และ `liffChannelId` ตรงกับ `LINE_LIFF_CHANNEL_ID` · ไม่ครบได้ 403 `LINK_REQUIRED`
3. **บัญชี LINE เดียวที่ผูกกับสมาชิกของผู้ใช้เข้าระบบสองคน** ถูกปฏิเสธ 403 `LINK_AMBIGUOUS` ไม่เลือกให้ — รอผู้ใช้ยืนยัน
4. **session ที่เปิดด้วย ID token ของ LINE อย่างเดียว** (token ขึ้นต้น `liff_`) ใช้ได้กับหน้า LIFF เท่านั้น ว่าง 15 นาทีหรือครบ 12 ชั่วโมงหมดอายุ และตรวจข้อ 2 ทุกคำขอ ไม่ผ่านแล้วลบ session · endpoint ของ Better Auth ปฏิเสธ session นี้ (403 `LIFF_SESSION`) ยกเว้นอ่าน session ออกจากระบบ ต่ออายุ เข้าระบบด้วยอีเมล และรีเซ็ตรหัสผ่าน จึงเปลี่ยนรหัสผ่าน ตั้ง TOTP หรือดูรายการ session ไม่ได้ — รอผู้ใช้ยืนยัน
5. ต่ออายุด้วย ID token ใหม่และลบ session เก่าของเบราว์เซอร์นั้น · ทุกการเข้าบันทึก `auth.login_succeeded` หรือ `auth.login_failed` ด้วย step `liff` ช่องทาง LIFF และเหตุผลที่ปฏิเสธ

## การตัดสินใจ: webhook

6. ตรวจ `x-line-signature` บนไบต์ดิบก่อน parse · ตอบ 404 เมื่อไม่รู้จัก `channelKey` · 401 เมื่อ signature ผิด · 200 เมื่อ signature ถูก · 500 เมื่อบันทึกหรือส่งต่อไม่สำเร็จ (ให้ LINE ส่งซ้ำ)
7. `LineWebhookEvent` หนึ่งแถวต่อ (องค์กร, `webhookEventId`) กันซ้ำ · ทำ inline ภายใน 1.5 วินาที งานที่ยังไม่เสร็จส่งเข้าคิว `bcs/line.webhook_received` (job `line-webhook`) พร้อม `notBefore` = เวลาที่มาถึง + 60 วินาที · event ถัดไปของผู้ใช้เดียวกันเรียงตามงานที่ส่งต่อไปแล้ว
8. ไม่มีอะไรตกหล่น: แถว RECEIVED ที่เก่ากว่า 60 วินาทีถูกเก็บโดยการส่งซ้ำของ LINE หรือ job `line-webhook-sweep` (ทุก 5 นาที) · run ที่ล้มทำซ้ำอีก 2 รอบห่าง 5 และ 10 นาที แล้วเป็น FAILED (`GAVE_UP`) พร้อมแจ้งเตือน · อะไรที่รอเกิน 1 วันเลิกพร้อมแจ้งเตือน · handler ทุกตัวต้อง idempotent
9. `Member.lineReachable` เป็นข้อมูลการส่งที่เขียนนอก `runCommand` และไม่มี Event · follow หรือ unfollow ล่าสุดตามเวลาของ LINE ชนะ (ล็อกแถว member และตรวจ event ที่บันทึกหลังกว่า)
10. โค้ด webhook อยู่ใน `src/server/line/webhook` ไม่ใช่ `src/channels/line` (§4.10) เพราะ channels เข้าฐานไม่ได้ (§4.2) แต่ webhook ต้องบันทึกก่อนทำ · ข้อความตอบกลับสองข้อความอยู่ใน `src/server/line/webhook/messages.ts` ไม่ใช่ templates ของการแจ้งเตือน (§4.7 ข้อ 5) เพราะเป็นการตอบ ไม่ใช่การแจ้งเตือน
11. `pnpm line:simulate` เซ็น event ทดสอบด้วย channel secret ใน `.env` และใช้ได้บนเครื่องเท่านั้น

## ผลที่ตามมา

- คนที่ได้มือถือที่ผูก LINE ไปทำได้เฉพาะงานในหน้า LIFF ตามสิทธิ์ของสมาชิกนั้น แต่ยึดบัญชีไม่ได้
- ระยะเก็บ `LineWebhookEvent` (มี LINE user id และข้อมูล postback) ยังไม่กำหนด รอผู้ใช้ตัดสินใน NEW-48
- ทางเลือกภายหลัง: เก็บช่องทางของ session ในคอลัมน์แทน prefix ของ token และเพิ่ม `Member.lineReachableAt` แทนการค้นใน `LineWebhookEvent`

## ส่วนเพิ่ม (2026-10-04 · หน้า LIFF ของ S5-06)

- **bootstrap** ใช้ `@line/liff/core` แบบเลือก plugin โหลดด้วย `import()` · `liff.init` ก่อนทุกอย่าง · ต่ออายุเฉพาะ session ที่เปิดจาก LINE เมื่อมีการใช้งานหลังเข้าระบบหรือต่ออายุครั้งก่อน 12 นาที ไม่เกินนาทีละครั้ง และหยุดเมื่อถูกปฏิเสธถาวร (`LINK_REQUIRED` `LINK_AMBIGUOUS` `TOKEN_INVALID` `NOT_IN_LINE`) · หน้าเรียก `ensureSession()` ก่อน server action และไม่ส่งอะไรหลังถูกปฏิเสธถาวร · `TOKEN_INVALID` โหลดหน้าใหม่ได้ไม่เกินนาทีละครั้ง
- **LIFF_MOCK** (local เท่านั้น) `POST /api/liff/mock-token { lineUserId }` ตอบ 404 เว้นแต่ `APP_ENV=local` และ `LIFF_MOCK=1` ขอ ID token จาก fake LINE server · ผู้ใช้ LINE จำลองมาจาก cookie `bcs-liff-mock-user` · SDK ยังโหลดแต่ไม่ `liff.init`
- **session ผูกกับบัญชี LINE ที่เปิด** token ของ session LIFF มี id ของ `ChannelIdentity` ที่เปิด และใช้ได้เฉพาะขณะการผูกนั้นยังอยู่และเป็นของสมาชิกคนนั้น · ยกเลิกผูกหรือย้ายการผูก (เว็บ LIFF และการปิดใช้งาน) ปิด session LIFF ของสมาชิกในธุรกรรมเดียวกัน
- **ยกเลิกผูกจาก LIFF** ยกเลิกได้เฉพาะการผูกของบัญชี LINE ที่เปิดหน้านั้น · ยกเลิกการผูกของบัญชี LINE อื่นต้องเข้าระบบด้วยรหัสผ่าน — รอผู้ใช้ยืนยัน
- **หน้าช่วยเหลือ** แสดงชื่อผู้ดูแลระบบขององค์กรเท่านั้น (อ่านภายใต้ `self.lineLink` เพราะ §2.4 ยังไม่มี capability ของเรื่องนี้) · จะแสดงอีเมลหรือเบอร์โทรด้วยหรือไม่เป็นเรื่องข้อมูลส่วนบุคคล — รอผู้ใช้ยืนยัน
- **งบ JavaScript เริ่มต้น 200 KB gzip (§9.4)** นับไฟล์ script ที่หน้าโหลดจนเครือข่ายนิ่ง รวม LINE SDK และข้อมูลหน้าที่ฝังใน HTML · ส่งข้อความไปเฉพาะ namespace ที่หน้า LIFF ใช้ และหน้า LIFF ไม่โหลดการลงทะเบียน PWA · โค้ดฝั่ง client ของ LIFF เลี่ยง library หนัก (lucide-react next/link next/dynamic uuid client ของ Better Auth) และใช้ตัวเบาของตัวเอง
