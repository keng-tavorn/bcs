# ADR-049: ผูกบัญชี LINE และ rich menu

- สถานะ: เสนอ (ข้อ 9 และข้อ 10 รอผู้ใช้ยืนยัน)
- วันที่: 2026-10-04
- ที่มา: S5-04 D-02 (FR-LINE-001 · FR-LINE-004 · FR-AUTH-003 AC2 · §9.2 · §9.5) · agent เสนอ ใช้ได้ทันทีเว้นแต่ผู้ใช้คัดค้าน

## บริบท

- §9.2 ขั้น 1 ให้บันทึกรหัสผูกตอนออกรหัส ส่วน sub-spec ของ S5 เลือกรหัสที่ลงชื่อแล้วบันทึกเมื่อใช้ เพื่อไม่ต้องเขียนฐานทุกครั้งที่เปิดหน้า
- rich menu ต้องสลับระหว่าง "ยังไม่ผูก" กับ "ผูกแล้ว" ต่อผู้ใช้ และ LINE อาจล้มชั่วคราว

## การตัดสินใจ

1. **รูปแบบรหัส** `l1.<org>.<member>.<ออกเมื่อ ms>.<nonce>.<HMAC-SHA256>` ลงชื่อด้วย `BETTER_AUTH_SECRET` (context `bcs/line-link-code/v1`) สะกดได้แบบเดียว อายุ 10 นาทีบนนาฬิกาความปลอดภัย (คลาดได้ 30 วินาที) · ใช้รหัสด้วยการ insert sha256 ของรหัสลง `ChannelLinkCode` (unique) จึงใช้ได้ครั้งเดียว · key กันซ้ำ `line-link:<codeHash>` · logger ลบรหัสนี้ทุกที่ในข้อความ
2. **ต่างจาก §9.2 ขั้น 1** ตาม sub-spec: ไม่บันทึกอะไรตอนออกรหัส · ยกเลิกผูกทำให้รหัสที่ออกก่อนหน้านั้นใช้ไม่ได้ (`TOKEN_EXPIRED` `UNLINKED_SINCE`) · รหัสใหม่ไม่ทำให้รหัสเก่าหมดอายุ (NEW-45)
3. **หน้า LIFF แสดงตัวอย่างก่อนผูก** ชื่อองค์กรและชื่อสมาชิกไทยและอังกฤษ (อ่านอย่างเดียว ไม่เรียก LINE) แล้วผูกเมื่อผู้ใช้กดยืนยันเท่านั้น ไม่ส่งตอนเปิดหน้าหรือจาก URL
4. **ลำดับใน `POST /api/liff/link`** ตรวจรหัส → นับต่อสมาชิก 10 ครั้งต่อ 10 นาที (ตาราง RateLimit key `bcs:line-link:<org>:<member>` เป็นข้อมูลบัญชีนอก `runCommand` แบบ AuthAttempt · NFR-SEC-05) → ตรวจ ID token กับ LINE → คำสั่ง `line.link`
5. channel ต้องเปิดใช้และ `liffChannelId` ตรงกับ `LINE_LIFF_CHANNEL_ID` (ADR-024) · ลำดับล็อก Organization แล้ว Member สำหรับการผูก · Member อย่างเดียวสำหรับยกเลิกผูกและปิดใช้งาน
6. `lineReachable` ตอนผูกมาจาก follow หรือ unfollow ล่าสุดที่บันทึกไว้ของผู้ใช้ LINE นั้น (ไม่มี = ส่งได้)
7. **สลับเมนูหลัง commit** ใน job `line-rich-menu` (event `line.linked` `line.unlinked`) และตอนสมาชิกที่ผูกแล้ว follow ใหม่ (follow hook) · ทุกครั้งอ่านสถานะการผูกและ id ของเมนู LINKED ใหม่หลัง LINE ตอบ · แทนที่เมนูทั้งชุด: ตามสมาชิกทีละคน การปฏิเสธถาวรรายคนไม่ขวางการเก็บกวาด การล้มชั่วคราวขวาง · ชื่อเมนู `bcs:<channelKey>:<kind>:<ms>` ลบเฉพาะเมนูเก่าของ key เดียวกัน · `pnpm line:richmenu` ใช้บนเครื่องเท่านั้น staging และ production ใช้ปุ่มใน `/admin/line`
8. **ไม่มีการยกเลิกผูกจากแชท** เพราะ BR-TOK-02 ต้องมี token ทุก postback ฝั่ง LINE ยกเลิกผูกใน LIFF
9. **unfollow (บล็อก OA) ไม่ยกเลิกผูก** แค่หยุดส่ง LINE (`lineReachable=false` แล้วส่งอีเมลแทน) และได้เมนู LINKED คืนเมื่อเลิกบล็อก — รอผู้ใช้ยืนยัน
10. **ผูก LINE แล้วส่งอีเมลแจ้งเจ้าของบัญชี** (`security.notice` ชนิด `LINE_LINKED` ลิงก์ไป `/settings/line`) เพื่อให้รู้ทันทีถ้ามีคนเอา QR ไปผูก LINE ของตัวเอง · ตัวอย่างก่อนผูกแสดงเฉพาะชื่อองค์กรและชื่อสมาชิก · บัญชี LINE เดียวผูกกับสมาชิกต่างองค์กรได้ตาม FR-LINE-001 AC3 — รอผู้ใช้ยืนยัน
11. **ข้อยกเว้นของ §4.7 ข้อ 5** ข้อความต้อนรับ push ตรงด้วย id ของการผูกเป็น `X-Line-Retry-Key` ไม่มีแถว Notification และไม่สำรองทางอีเมล แบบเดียวกับข้อความตอบของ webhook
12. **ข้อยกเว้นของ §9.9** ภาพ rich menu ใช้ Sarabun (OFL อยู่ใน repo แล้ว) เพราะ IBM Plex Sans Thai ไม่ได้เก็บใน repo · ถ้าจะเปลี่ยน เพิ่มไฟล์ OFL ใน `assets/fonts` แล้วรัน `pnpm line:richmenu --images` และ commit ภาพใหม่

## ผลที่ตามมา

- รหัสที่ถ่ายรูปไปใช้ได้จนหมดอายุ 10 นาทีหรือจนเจ้าของยกเลิกผูก อีเมลแจ้งการผูกช่วยให้เจ้าของรู้ทัน
- ต้องตรวจกับ LINE จริงใน D-03 ว่าเมนูกลับมาหลังเลิกบล็อกและข้อความต้อนรับถึงเมื่อผูกก่อนเพิ่ม OA (NEW-44)

## ส่วนเพิ่ม (2026-10-04 · หน้าตั้งค่า LINE)

- ออกรหัสผูกได้ด้วย session เว็บที่เข้าระบบอยู่ตามคำของ FR-LINE-001 AC1 · การผูกจึงเป็นการเข้าระบบช่องทางที่สองที่อยู่นานกว่า session (LIFF และการอนุมัติในแชทใต้ `stepUpThreshold`) และไม่หายเมื่อรีเซ็ตรหัสผ่าน ตัวคุมคืออีเมลแจ้งเจ้าของทุกครั้งที่ผูก ยกเลิกผูกจากเว็บได้ และหน้า `/settings/line` มีลิงก์ลืมรหัสผ่าน · ทางเลือก: ให้ยืนยันรหัสผ่านหรือ TOTP ภายใน 5 นาทีก่อนออกรหัสแบบหน้า `/settings/pin` — รอผู้ใช้ยืนยัน
- สมาชิกที่เข้าระบบอยู่ยังไม่มีหน้าเปลี่ยนรหัสผ่าน ระหว่างนี้ใช้ลืมรหัสผ่าน ซึ่งปิด session ทุกอุปกรณ์ (NEW-60)
