# ADR-050: อนุมัติในแชท LINE และส่งการแจ้งเตือนทาง LINE

- สถานะ: เสนอ (ข้อ 4 และข้อ 7 รอผู้ใช้ยืนยัน)
- วันที่: 2026-10-04
- ที่มา: S5-05 S5-08 (FR-LINE-002 · FR-LINE-007 AC2 AC3 · FR-NOTI-002 · BR-TOK-01 ถึง 05 · BR-LINE-07 08 · §9.3 · §10.1) · ต่อจาก ADR-043 · agent เสนอ ใช้ได้ทันทีเว้นแต่ผู้ใช้คัดค้าน

## การตัดสินใจ

1. **ActionToken ของ LINE** ออกคู่กับ token ของอีเมลใน `applyTokenLifecycle` เมื่อผู้รับงานผูก LINE อยู่ภายใต้ provider ของ channel และ channel เปิดใช้ · ทำได้เฉพาะ APPROVE ไม่มี secret อายุ 72 ชั่วโมง · เพิกถอนพร้อมงาน เมื่อยกเลิกผูก และเมื่อปิดใช้งานสมาชิก
2. **postback** ต้องเป็น `v` `a` `k` เท่านั้น · ผู้ทำคือสมาชิกที่ผูกกับ `source.userId` ที่ LINE เซ็นมา ผู้ใช้ LINE ที่ไม่ได้ผูกกับใครทำในนาม SYSTEM job `line-postback` · ไม่ตรงกับเจ้าของ token ได้ FORBIDDEN และ `security.token_misuse` · ลำดับ: ล็อกแถวงาน → ตรวจ step-up ซ้ำ → ใช้ token ด้วยคำสั่งเดียว → ตัดสินผ่าน command เดียวกับเว็บบนช่องทาง `LINE_CHAT` · key กันซ้ำ `line-postback:<webhookEventId>`
3. **ทุกทางที่ตัดสินล็อกงานก่อน token** (เว็บ ลิงก์อีเมล และ postback) จึงไม่ deadlock กัน · งานที่ยอดตั้งแต่ `stepUpThreshold` และงานเชิงนโยบายไม่มีปุ่มอนุมัติในการ์ด ปุ่มพาไปตัดสินใน LIFF พร้อม PIN และ server ปฏิเสธซ้ำ
4. **คำตอบเมื่อกดซ้ำ** `TOKEN_USED` พร้อมชื่อผู้ตัดสินและเวลาตาม §9.3 เมื่องานถูกตัดสินแล้วจากทางใดก็ตาม หรือถูกยกเลิกหรือย้ายระหว่างที่อีกงานของขั้นเดียวกันถูกตัดสิน (ผู้ร่วมพิจารณา ผู้รักษาการ) · คำตอบส่งถึงผู้ใช้ LINE ที่ได้ปุ่มนั้นเท่านั้น · ชื่อที่ตอบอาจเป็นผู้อนุมัติอีกคนของขั้นเดียวกัน ซึ่ง BR-NOTI-01 ให้ข้อความ LINE ระบุชื่อได้เฉพาะผู้ขอ — รอผู้ใช้ยืนยัน · `TOKEN_INVALID` เมื่อถูกเพิกถอนโดยยังไม่มีใครตัดสิน · `TOKEN_EXPIRED` กรณีอื่น
5. **ตอบกลับ** ด้วย reply token ขณะยังไม่หมดอายุ ไม่เช่นนั้นหรือเมื่อ reply ถูกปฏิเสธ push ถึงสมาชิกที่ผูกอยู่เท่านั้น ด้วย retry key = id ของ `LineWebhookEvent`
6. **ช่องทางของการแจ้งเตือน** เปิดด้วย `LineChannelConfig.active` อย่างเดียว · ส่ง LINE เฉพาะ templateKey ใน allowlist ตาม §10.1 · การส่งต่อถึง ADMIN `admin.*` `security.notice` และรายงานส่งทางอีเมลเท่านั้น · การ์ด Flex สำหรับ `task.assigned` และการส่งต่อถึงผู้ร่วมพิจารณา อื่น ๆ เป็นข้อความสั้นพร้อมลิงก์ LIFF หรือเว็บ ในภาษาขององค์กร · retry key = id ของ Notification
7. **เนื้อหาการ์ด** การ์ดคำขอซื้อมีครบทุกแถวของ §9.3 · การ์ด PO มีเลขที่ ประเภท ยอด งบที่กัน และข้อ DOA **ไม่ระบุชื่อใคร** (PO รวมหลายคำขอและจัดซื้อเป็นผู้สร้าง) · การ์ดผลต่างการตรวจรับมีเลข PO ยอด และข้อ DOA เท่านั้น — รอผู้ใช้ยืนยันว่าการ์ด PO ควรระบุผู้ขอและแผนกของคำขอต้นทางหรือไม่
8. **อ่านงานใหม่ทุกครั้งที่ส่ง** งานที่ไม่ OPEN บนเส้นทาง ACTIVE หรือผู้รับไม่ได้ถืองานแล้ว ไม่ส่ง และตั้งแถวเป็น SENT ช่องทาง IN_APP พร้อม error `TASK_CLOSED` (ยังไม่มีสถานะ SKIPPED)
9. **ส่งไม่สำเร็จ** เฉพาะ 400 ที่ระบุ `to` ตั้ง `lineReachable=false` (unfollow เป็นสัญญาณหลักตาม BR-LINE-08) · 401 403 และ 429 เพราะโควตารายเดือนหมด แจ้งเตือนผู้ดูแล ส่งอีเมลทันที และคงสมาชิกเป็นส่งได้ · ล้มชั่วคราว ทำซ้ำแบบ backoff เริ่ม 15 วินาทีเพิ่มเท่าตัว เลิกที่ 4 นาที ไม่เกิน 6 ครั้ง แล้วส่งอีเมลภายใน 5 นาทีนับจากครั้งแรก (FR-LINE-007 AC3)
10. ข้อความ LINE อยู่ใน `src/channels/line/flex` ทั้งไทยและอังกฤษ (§4.7 ข้อ 5)

## ผลที่ตามมา

- คำตอบจริงของ LINE เมื่อ push ถึงผู้ที่บล็อก OA และข้อความ 429 เมื่อโควตาหมด ต้องตรวจใน D-03 แล้วปรับ `recipientRefused` และ `MONTHLY_LIMIT_MESSAGE` (NEW-44)
- ช่องทางของ template ที่ §10.1 ยังไม่ระบุ ส่งทางอีเมลอย่างเดียวจนกว่าผู้ใช้จะตัดสิน (NEW-49)
