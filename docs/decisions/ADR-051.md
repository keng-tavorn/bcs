# ADR-051: เลขบัตรประชาชนใน audit trail และไฟล์ส่งออก

- สถานะ: เสนอ (ข้อ 2 ถึงข้อ 4 เป็นเรื่องสิทธิ์และข้อมูลส่วนบุคคล รอผู้ใช้ยืนยัน)
- วันที่: 2026-10-04
- ที่มา: NEW-33 (BR-AUTH-04 · FR-VIS-004 AC2) และการรีวิว S4-11 (FR-VIS-002 AC3) · agent เสนอ ใช้ได้ทันทีเว้นแต่ผู้ใช้คัดค้าน

## บริบท

- event `supplier.created` และ `supplier.registry_checked` ของผู้ขายบุคคลธรรมดาเก็บเลขผู้เสียภาษี ซึ่งคือเลขบัตรประชาชน
- หน้าทะเบียนผู้ขาย mask เลขนี้ตามสิทธิ์แล้ว แต่การค้น หน้า audit และไฟล์ส่งออก audit แสดง `data` ของ event ตรง ๆ
- Event แก้ไม่ได้ (append-only) จึง mask ได้เฉพาะตอนอ่าน

## การตัดสินใจ

1. **mask ตอนอ่าน** ผ่าน `src/server/services/audit/masking.ts`: `supplier.created` และ `supplier.registry_checked` (ช่อง `taxId` ของบุคคลธรรมดาไทย) และ `audit.exported` (เลข 13 หลักที่พิมพ์ในช่องค้นเอกสาร) · ใช้รูปแบบ mask เดียวกับทะเบียนผู้ขาย (เห็น 4 หลักท้าย) · การค้น หน้า audit และไฟล์ส่งออกใช้ฟังก์ชันอ่านเดียวกัน checksum ของไฟล์คิดจากไบต์ที่ mask แล้ว · เทสต์ที่ไล่ทุก schema ของ event ล้มทันทีถ้าวันหน้ามีช่องแบบเลขผู้เสียภาษีที่ยังไม่ mask
2. **ใครเห็นเต็ม** เฉพาะผู้ที่ทะเบียนผู้ขายแสดงเลขเต็มให้ด้วย grant อื่นที่ไม่ใช่ AUDITOR (เช่น FINANCE หรือ PROCUREMENT) · AUDITOR เห็นแบบ mask · **ORG_ADMIN เห็นแบบ mask** (ก่อนแก้เห็นเต็ม ทะเบียนผู้ขายไม่แสดงเลขผู้เสียภาษีให้ ORG_ADMIN เลย) ทางเลือกอื่นคือซ่อนเลขจาก ORG_ADMIN ทั้งหมด — รอผู้ใช้ยืนยัน
3. **ไฟล์ส่งออก audit บอกว่ามีเลขเต็มหรือไม่** (`ExportJob.params.wholeNationalIds`) · ไฟล์ที่มีเลขเต็มดาวน์โหลดได้เฉพาะผู้ที่เห็นเลขเต็ม แบบเดียวกับหลักฐานยืนยันตัวตนของผู้ขายบุคคลธรรมดา เพราะ id ของไฟล์ปรากฏใน `audit.exported` ที่ AUDITOR อ่านได้ ถ้าไม่มีเงื่อนไขนี้ AUDITOR จะโหลดไฟล์ของคนที่เห็นเลขเต็มได้ · capability ยังเป็น `audit.export` เดิม — รอผู้ใช้ยืนยัน
4. **ไฟล์ audit ที่ทำก่อนการแก้นี้** ไม่มีบันทึก `wholeNationalIds` จึงถือว่าอาจมีเลขเต็ม ดาวน์โหลดได้เฉพาะผู้ที่เห็นเลขเต็ม AUDITOR ส่งออกใหม่ได้ (ไฟล์ใหม่ mask แล้ว) · ไม่ลบไฟล์เก่า (staging ยังไม่มีไฟล์ audit) — รอผู้ใช้ยืนยัน
5. **ไฟล์รายงาน** (ExportJob ชนิด REPORT) ดาวน์โหลดได้เฉพาะเมื่อ `report.view` ของผู้อ่านครอบขอบเขตที่ไฟล์สร้าง (`params.scope`) ผ่าน `reportFileReadable` ตัวเดียวกับหน้ารายงาน · ชนิดที่ไม่รู้จักปฏิเสธ (NEW-43)

## ผลที่ตามมา

- Event ในฐานยังเก็บเลขเต็มตามจริง (หลักฐานไม่ถูกแก้) แต่ไม่มีทางอ่านผ่านหน้าจอหรือไฟล์โดยไม่มีสิทธิ์เห็นเลขเต็ม
- AUDITOR ที่ต้องการไฟล์ของคนอื่นที่มีเลขเต็มต้องส่งออกเอง ซึ่งได้ไฟล์ที่ mask แล้ว
