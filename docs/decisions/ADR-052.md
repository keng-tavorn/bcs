# ADR-052: งบ JavaScript เริ่มต้นของหน้า LIFF และการคอมไพล์ข้อความล่วงหน้า

- สถานะ: เสนอ
- วันที่: 2026-10-04
- ที่มา: §9.4 "JavaScript เริ่มต้นไม่เกิน 200 KB (gzip)" · S5-06 · agent เสนอ ใช้ได้ทันทีเว้นแต่ผู้ใช้คัดค้าน

## บริบท

- หน้า LIFF เปิดในแอป LINE บนมือถือผ่าน 4G บ่อยครั้งโดยไม่มี cache (NFR-PERF-01)
- §9.4 ไม่ได้บอกว่า "JavaScript เริ่มต้น" นับอะไรบ้าง ไฟล์ script ของหน้าอยู่ราว 190–199 KB แต่ HTML ของทุกหน้ายังฝังข้อมูลหน้า (RSC payload) ราว 92 KB ซึ่งเกือบทั้งหมดเป็นข้อความทุก namespace ที่ layout ราก ส่งไปทุกหน้า

## การตัดสินใจ

1. **นับแบบเข้ม** ไฟล์ script ทุกไฟล์ที่หน้าโหลดจนเครือข่ายนิ่ง รวม LINE SDK บวกข้อมูลหน้าที่ฝังใน HTML · gzip · KB = 1000 ไบต์ · ชั่งทุกหน้า LIFF ทั้งสองแบบที่ LINE เปิด (เปิดจาก LINE ที่ยังไม่มี session และมี session ของ LIFF แล้ว) ด้วยเอกสารขนาดจริง 40 รายการ รวมหน้า `/liff` ที่ลิงก์ลึกเปิดก่อน (`tests/e2e/liff-support.ts` `liff-budget-scene.ts`)
2. **ส่งข้อความเฉพาะที่ใช้** layout รากส่งเฉพาะ namespace ที่หน้า error ใช้ · กลุ่ม `(workspace)` ส่งทุก namespace (ไม่มีงบ) · `(auth)` และ `(platform)` ส่งเฉพาะที่ใช้ · หน้า LIFF ส่งข้อความของประตูเข้าระบบใน `src/app/liff/layout.tsx` และข้อความของแต่ละส่วนใน layout ของส่วนนั้น ให้เฉพาะสมาชิกที่เข้าระบบแล้ว (`src/i18n/client-messages.ts` `src/app/liff/_lib/part-messages.tsx`) · เทสต์ `tests/unit/client-messages.test.ts` ล้มเมื่อ component อ่าน namespace ที่ส่วนของตัวเองไม่ได้ส่ง
3. **หน้า LIFF ไม่โหลดการลงทะเบียน PWA** (LIFF ทำงานในแอป LINE) และ component ฝั่ง client ของ LIFF ใช้ตัวต่อ class แบบเบาแทน tailwind-merge
4. **คอมไพล์ข้อความตอน build** ด้วย `experimental.messages.precompile` ของ next-intl ใน `next.config.ts` ลด JavaScript ราว 9.4 KB ทุกหน้า · ความต่างที่รู้: `t.raw` ใช้ไม่ได้ และข้อความที่ส่งค่าไม่ครบแสดง `undefined` แทน key · มีเทสต์กัน 3 ชุด (`messages-raw-readers.test.ts` `messages-precompile.test.ts` `messages-arguments.test.ts` ที่ตรวจการเรียกข้อความทุกจุดใน src ทั้งไทยและอังกฤษ) · ถ้าต้องเลิกใช้ ให้กลับไปใช้ `createNextIntlPlugin('./src/i18n/request.ts')` แล้วหาทางลดขนาดอื่นแทน

## ผลที่ตามมา

- หน้า LIFF ทุกหน้าผ่านงบแบบเข้มพร้อมเทสต์ e2e ที่ล้มทันทีเมื่อเกิน การเพิ่มข้อความหรือ component ในหน้า LIFF ต้องดูผลการชั่งทุกครั้ง
- เพิ่ม namespace ใหม่ให้หน้า LIFF ต้องเพิ่มใน `src/i18n/client-messages.ts` ด้วย
- next-intl รุ่นถัดไปอาจเปลี่ยน API ของ precompile เพราะยังเป็น experimental ต้องรันเทสต์ทั้ง 3 ชุดหลังอัปเกรด
