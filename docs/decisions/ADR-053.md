# ADR-053: e2e ของฉาก demo บนฐานแยกและนาฬิกาจริง

- สถานะ: เสนอ
- วันที่: 2026-10-05
- ที่มา: D-04 · docs/sub-specs/D.md · agent เสนอ ใช้ได้ทันทีเว้นแต่ผู้ใช้คัดค้าน

## บริบท

- D-04 ต้องการ e2e ของฉากหลักที่อ่านผู้ใช้และยอดจากชีต `Demo_Script` เอง และฉากต่อกันแบบวันจริง (ฉาก 2 อนุมัติคำขอของฉาก 1 ฉาก 7 รวมเป็น PO ฉาก 8 ตรวจรับ ฉาก 9 เห็นทั้งหมด)
- เทสต์หน้าจอทั้งหมดใช้ฐาน e2e ที่ไม่มีประวัติ demo เพราะนับงาน งบ และการแจ้งเตือนเอง
- แผนเดิม (docs/sub-specs/D.md) ใช้องค์กรแยกในฐานเดียวกันและนาฬิกาธุรกิจของ e2e ที่ตั้งเวลาเริ่มได้

## การตัดสินใจ

1. ฉากรันในโหมด demo ของ Playwright (`--grep @demo` หรือ `E2E_DEMO=1`) บนฐานของตัวเองที่ seed องค์กร DEMO ของชีตพร้อมประวัติ D-01 · โปรเจกต์ demo รันเฉพาะ `tests/e2e/demo/*.spec.ts` ตามลำดับชื่อไฟล์ · `pnpm verify --e2e` รันหน้าจอก่อนแล้วรันฉาก และให้ด่าน traceability อ่านรายงานรวม
2. ใช้นาฬิกาจริง: ค่าที่ขึ้นกับเวลา (ชั่วโมงค้าง สัดส่วน KPI งบคงเหลือ) อ่านจากฐานตอนรันพร้อมขอบเขต ไม่พิมพ์ตัวเลขไว้ในเทสต์ · ฉากจึงรันได้เฉพาะเมื่อวันที่รันทำให้ประวัติอยู่ในปีงบของชีต ซึ่งเป็นข้อจำกัดเดียวกับ demo จริง (seed หยุดพร้อมบอกให้เลื่อนปีในชีต)
3. นาฬิกาธุรกิจแยกจากนาฬิกาความปลอดภัย (ให้ e2e ตั้งเวลาเริ่มและเดินเวลาเพื่อฉากเตือนตาม SLA) ย้ายไปเป็น NEW-63 `[go-live]`

## ผลที่ตามมา

- หลังสิ้นปี 2026 ต้องเลื่อนปีในชีต Budget Holidays และ Demo_History ก่อนรันฉาก (คู่มือ demo บอกไว้แล้ว)
- ฉากเตือนตาม SLA และส่งต่อ (ฉากรอง) ยังไม่มี e2e ที่เดินเวลา มีเทสต์ integration ของ handler ด้วยนาฬิกาปลอมแทน
