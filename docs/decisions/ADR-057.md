# ADR-057: ลำดับพัฒนาใหม่: ระยะ 1 Intake-to-Procure ถึง LINE และแอป · ระยะ 2 Supplier Sourcing Risk

- สถานะ: ตัดสินแล้ว (ผู้ใช้ 2026-10-08)
- วันที่: 2026-10-08
- ที่มา: ผู้ใช้ปรับลำดับ 2026-10-08 · spec 0.3 §16.0

## บริบท

- ลำดับเดิมของ spec 0.2 เรียงตามชั้น (T1–T4) และรหัสขั้น S1–S15 ซึ่ง FR ADR และ OQ อ้างถึงอยู่แล้ว
- ผู้ใช้ต้องการส่งมอบงานที่ลูกค้าใช้ทุกวันก่อน: ขอซื้อถึงสั่งซื้อ แล้วจึงจ่ายเงิน AI และแอป ส่วนพอร์ทัลผู้ขาย การจัดหา และความเสี่ยงรอขอบเขตระยะ 2
- AI เคยผูกกับชั้น ทำให้ agent ของโมดูลที่เลื่อนไประยะ 2 ค้างอยู่ในขั้นที่ไม่ได้ทำ

## การตัดสินใจ

> ลำดับพัฒนาใหม่: ระยะ 1 = Intake-to-Procure (S1–S5 S16 S6) → Procure-to-Pay (S8 S9) → AI Agent (S13) → LINE และแอป BCS Go (S17) · ระยะ 2 = Supplier Onboarding (S7) Sourcing (S10) Risk Orchestration (S11) แล้วจึง S12 S14 S15 · รหัสขั้นเดิมไม่เปลี่ยน · EG-1 และ NG-5 เปลี่ยนเป็น "ไม่มี AI นอกโมดูล AI และทุกโมดูลทำงานได้เมื่อปิด AI" · agent ของระยะ 2 ย้ายไปพร้อมโมดูล

## ผลที่ตามมา

- §16.0 คือลำดับที่ใช้จริง รหัสขั้นเดิมไม่เปลี่ยน จึงไม่ต้องแก้ FR ADR OQ หรือเทสต์ที่อ้างรหัสขั้น
- เส้นชัยใหม่ A2 และ D ถึง H ในส่วน "เริ่มที่นี่" · `pnpm spec:check` แสดงความคืบหน้าของทุกเส้นชัย (S16-01)
- ไม่เริ่มแถวถัดไปของ §16.0 จนกว่าเส้นชัยของแถวก่อนผ่าน และทุกขั้นตั้งแต่ S6 เริ่มด้วย sub-spec ที่ผู้ใช้อนุมัติ (§16.2 ข้อ 7)
- ระยะ 1 ไม่มีพอร์ทัลผู้ขาย ใบแจ้งหนี้รับทางอีเมลและการอัปโหลด (§8.12)

## อ้างอิง
