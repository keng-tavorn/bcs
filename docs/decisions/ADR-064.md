# ADR-064: ทำระยะ 1 ทั้งหมดบนข้อมูลสังเคราะห์ก่อนขอข้อมูลจริง

- สถานะ: ตัดสินแล้ว (ผู้ใช้ 2026-10-11)
- วันที่: 2026-10-11
- ที่มา: ผู้ใช้เปลี่ยนแผนหลังถึงเส้นชัย A2 (2026-10-11) · spec 0.4 ส่วนเริ่มที่นี่ · §16.0 · §16.2 · §16.8 · §16.13

## บริบท

- แผนเดิม (0.3.1): demo กับลูกค้า → ขอข้อมูลจริงและทำ spec version 2 (เส้นชัย B) → go-live ชั้น 1 (C) → จึงเริ่ม S6 (D) S8 S9 (E) S13 (F) S17 (G)
- ผู้ใช้ต้องการให้ลูกค้าเห็นระยะ 1 ทั้งหมดก่อนขอข้อมูลจริง จึงต้องพัฒนา S6 S8 S9 S13 S17 ให้เสร็จก่อน ด้วยข้อมูลที่ใกล้ของจริงที่สุดเท่าที่ทำได้โดยไม่ใช้ข้อมูลของลูกค้า (OQ-19)
- "เสร็จเมื่อ (ต้นฉบับ)" ของ S9 S13 และ S17 ต้องใช้ของจากลูกค้าหรือธนาคาร (P0-03 สเปกไฟล์ธนาคาร · P0-02 เอกสารจริง · P0-04 LINE ของลูกค้า) ซึ่งจะได้หลัง demo
- §16.2 ข้อ 7 ให้หยุดรออนุมัติ sub-spec ทีละขั้น ซึ่งทำให้งานช้าเมื่อมีหลายขั้นติดกัน

## การตัดสินใจ

> ลำดับใหม่ (0.4): ทำระยะ 1 ทั้งหมด (S6 S8 S9 S13 S17) บนข้อมูลสังเคราะห์ที่ใกล้ของจริงก่อน แล้ว demo ระยะ 1 (เส้นชัย A3) จากนั้นจึงขอข้อมูลจริง (B) และ go-live (C) · S6 S8 S9 และ S13 ทำพร้อมกันได้ · "เสร็จเมื่อ" ที่ต้องใช้ของจากลูกค้าหรือธนาคารแยกเป็นชั้น demo และชั้นของจริง (`[go-live]`) · sub-spec ทุกขั้นเขียนรวมและอนุมัติครั้งเดียว · §16.2 ข้อ 5 ไม่ใช้กับรอบ P1

## ผลที่ตามมา

- รอบใหม่ชื่อรอบ P1 อยู่ใน §16.13 พร้อมข้อ P1-01 ถึง P1-13 และส่วนของขั้น §16.14 ถึง §16.18 · เส้นชัยใหม่ A3 = demo ระยะ 1 พร้อม
- ตัวอักษรของเส้นชัยเป็น ID ไม่ใช่ลำดับ: B (ข้อมูลจริง) และ C (go-live) อยู่หลัง A3 · C ครอบคลุมข้อ `[go-live]` ของทุกขั้นในระยะ 1 ที่ลูกค้าเปิดใช้
- ชั้นของจริงของ S9 S13 S17 เป็นข้อ `[go-live]` ในส่วนของขั้นนั้น ส่วนชั้น demo ใช้แม่แบบไฟล์ธนาคารกลาง เอกสารสังเคราะห์ และ channel LINE ของ BCS
- ผู้ใช้จริงลองใช้ (§16.2 ข้อ 5 · `verifiedBy`) ย้ายไปก่อน go-live ในเส้นชัย C
- กฎเงิน DOA SoD audit golden และ "ห้ามข้อมูลจริงของลูกค้า" ยังบังคับครบ

## อ้างอิง
