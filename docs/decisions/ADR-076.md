# ADR-076: เส้นทางอนุมัติเป็นผังกล่องบนจอคอม และกล่องของงานตัวเองมีปุ่มตัดสิน

- สถานะ: ตัดสินแล้ว (ผู้ใช้ 2026-11-01)
- วันที่: 2026-11-01
- ที่มา: คำสั่งของผู้ใช้ในแชตบน main (2026-11-01) พร้อมภาพจากวิดีโอของ Zip · รายงาน `docs/reports/zip-gap-p1.md`

## ข้อความที่สั่ง

```text
โดยเฉพาะ ใช้ผังกล่องบนเว็บจอคอม และคงการ์ดเรียงยาวไว้บนมือถือ
ใช้ @xyflow/react ซูมและลากได้เหมือน Zip
(หมายเหตุ ไม่มีปุ่มอนุมัติบนกล่อง: spec กำหนดให้ตัดสินจากแถบตัดสินใจจุดเดียว เพื่อกันการกดผิด อันนี้ให้ใช้ได้ เป็นกรณีพิเศษ เพื่อความง่ายต่อการใช้ง่าย เหมือน ZIP)
```

## บริบท

- ADR-103 เลือกแสดงเส้นทางคู่ขนานเป็นการ์ดตราประทับที่จัดกลุ่ม และไม่ติดตั้ง `@xyflow/react` · §9.10 และ FR-INT-012 AC3 AC4 ให้ตัดสินที่แถบตัดสินจุดเดียว
- ผู้ใช้เห็นวิดีโอของ Zip แล้วต้องการให้จอคอมอ่านเส้นทางที่แยกสายได้ในครั้งเดียว และกดอนุมัติได้จากกล่องของตัวเอง
- หน้า LIFF และมือถือมีงบ JavaScript และจอแคบ ผังกล่องจึงไม่เหมาะ (ADR-052)

## การตัดสินใจ

> หน้าเอกสาร (คำขอและ PO) บนจอตั้งแต่ 1024 px แสดงเส้นทางอนุมัติเป็นผังกล่องด้วย `@xyflow/react` ที่ลากและซูมได้ · ขั้นผู้ตรวจและกรรมการแตกเป็นกล่องต่อ slot · มือถือคงการ์ดตราประทับเรียงยาว และ LIFF ไม่เปลี่ยน (ADR-052 ADR-103) · กล่องของงานที่เปิดอยู่ของผู้อ่านมีปุ่มตัดสินเป็นกรณีพิเศษ ซึ่งเปิดการยืนยันของแถบตัดสินเดิม จึงยังกดยืนยันซ้ำ ใส่ PIN ใส่เหตุผล และเรียก service เดิมทุกครั้ง · แก้ส่วนหนึ่งของ ADR-103

1. ปุ่มบนกล่องไม่มีทางลัด: กด "อนุมัติ" บนกล่องแล้วเปิด Alert Dialog ที่บอกเลขเอกสารและยอด พร้อมช่อง PIN เมื่อถึงเกณฑ์ (BR-TOK-05) · เมนู ⋯ เปิดกล่องขอข้อมูล ตีกลับ และไม่อนุมัติของแถบตัดสินเดิม
2. แถบตัดสินยังอยู่และเป็นเจ้าของการตัดสินทั้งหมด (`src/ui/document/decision-link.tsx`): กล่องขอให้แถบเปิดการยืนยันเท่านั้น เมื่องานปิดหรือตัดสินแล้ว ปุ่มบนกล่องหายพร้อมแถบ · การตรวจสิทธิ์อยู่ใน service เหมือนเดิม การซ่อนปุ่มไม่ใช่ด่านตรวจ
3. เห็นปุ่มเฉพาะกล่องของงานตัวเอง: หา step และ slot จากงานที่เปิดอยู่ (`getMyOpenTask`) ไม่ใช่เทียบชื่อ จึงถูกต้องกับผู้รักษาการ
4. ผู้ตรวจเห็นคำว่า "ผ่าน" และไม่มีปุ่มไม่อนุมัติทั้งบนกล่องและบนแถบ (BR-WF-09) · เดิมแถบบนหน้าคำขอแสดง "อนุมัติ" และ "ไม่อนุมัติ" ให้ผู้ตรวจ แม้ service จะปฏิเสธการไม่อนุมัติอยู่แล้ว
5. ผังแสดงอย่างเดียว (NG-4): ย้ายกล่องหรือลากเส้นไม่ได้ ลากได้เฉพาะพื้นผัง · ลำดับกล่องมาจากเส้นทางจริง ไม่มีตรรกะอำนาจในหน้าจอ
6. ไม่จองล้อเมาส์: ล้อเลื่อนหน้าเหมือนเดิม ซูมด้วยปุ่ม Ctrl กับล้อ หรือการบีบ · เปิดที่ขนาดจริงเพื่อให้ตัวอักษรไม่เล็กกว่าที่ §9.9 กำหนด · ซูมออกเมื่อผู้ใช้เลือกเอง
7. โหลดเฉพาะจอกว้าง: `@xyflow/react` อยู่ใน chunk แยก (`next/dynamic` แบบ `ssr: false`) มือถือจึงไม่ดาวน์โหลด · หน้า LIFF ห้าม import ตามเดิม (`eslint/liff-forbidden.mjs`)
8. ตราประทับยังเป็นจุดเด่นเดียว (§9.9): กล่องที่ตัดสินแล้วมีชื่อ ตำแหน่ง เวลา ช่องทาง และ DOA ฉบับกับข้อครบเหมือนการ์ด

## ผลที่ตามมา

- เพิ่ม dependency `@xyflow/react` 12 (MIT) ใน Workspace เท่านั้น
- ซ่อนป้าย "React Flow" ที่มุมผังด้วย `proOptions.hideAttribution` เพราะตัวอักษร 10 px สีจาง ไม่ผ่าน §9.9 และ axe · สัญญาอนุญาต MIT อนุญาตให้ทำได้ แต่ผู้พัฒนาขอให้องค์กรเชิงพาณิชย์พิจารณาสมัคร Pro เพื่อสนับสนุน ซึ่งเป็นคำขอ ไม่ใช่ข้อบังคับ
- เทสต์ถาวร: `tests/unit/step-flow-layout.test.ts` · `tests/e2e/step-flow.spec.ts` · `tests/e2e/review-step.spec.ts` · FR-INT-012 AC3 AC4 และ §9.10 เขียนใหม่ให้ตรง
- เทียบกับกติกาเดิม: ปุ่มตัดสินมี 2 จุดบนจอคอม เสี่ยงกดผิดมากขึ้นเล็กน้อย แต่ยังต้องยืนยันซ้ำทุกครั้ง และแผงขั้น (Sheet) ยังไม่มีปุ่มตัดสินเพื่อไม่ให้ dialog ซ้อนกัน
