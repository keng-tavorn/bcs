# ADR-077: หน้าใบแจ้งหนี้แบ่งจอข้างไฟล์ แถบยอดเทียบกับ PO และแจ้งเตือนรวมที่เดียว

- สถานะ: ตัดสินแล้ว (ผู้ใช้สั่ง "ทำชุดใบแจ้งหนี้ต่อ" 2026-11-02 · NEW-115 NEW-116)
- วันที่: 2026-11-02
- ที่มา: รายงาน `docs/reports/zip-gap-p1.md` หัวข้อใบแจ้งหนี้และการจ่ายเงิน

## บริบท

- คนบัญชีต้องเทียบค่าในฟอร์มกับไฟล์ของผู้ขาย แต่หน้าเดิมต้องกดเปิดไฟล์แยก และไม่มีภาพรวมว่า PO ตัดไปแล้วเท่าไร
- เหตุผลที่ใบถูกเตือนกระจายอยู่หลายที่: รายการไม่ตรงอยู่ในแผงหนึ่ง เรื่องบัญชีธนาคารเห็นเฉพาะตอนเข้ารอบจ่าย และป้ายในรอบจ่ายไม่บอกความหมาย
- ข้อนี้เป็นงานหน้าจอกับการอ่านอย่างเดียว ห้ามเปลี่ยนกฎการจับคู่ การคำนวณเงิน และสิทธิ์

## การตัดสินใจ

> จอตั้งแต่ 1280 px หน้าใบแจ้งหนี้ชั้น 2 แบ่งสอง: ไฟล์ต้นฉบับซ้าย ข้อมูลขวา มีแถบยอดเทียบกับ PO รายการไม่ตรง และแท็บ รายละเอียด · จับคู่ PO · ที่มา · ความเห็น · จอเล็กกว่านั้นเป็นคอลัมน์เดียวไม่มีแท็บตามเดิม · ป้าย "N แจ้งเตือน" บนหัวใบเปิดดูเหตุผลทุกข้อเมื่อกด

1. เปิดไฟล์ในหน้าเฉพาะชนิดที่ `ALLOWED_FILE_TYPES` ระบุ `inline` (PDF JPEG PNG) ผ่าน `getDownloadUrl` เดิมซึ่งตรวจสิทธิ์ทุกครั้ง · ที่อยู่ไฟล์ขอเมื่อจอกว้างเท่านั้น มือถือจึงไม่ขอจนกว่าจะกดดาวน์โหลด · e-Tax XML ไม่มีหน้าให้ดู จึงบอกเหตุผลและให้ดาวน์โหลด
2. หน้านี้กว้างเกิน 1280 px ได้บนจอตั้งแต่ 1280 px (`WIDE_PAGE`) เพราะไฟล์อ่านยากเมื่อแคบ จอ 1920 px จึงได้พื้นที่เพิ่ม · หน้าอื่นคงตาม §9.9
3. แท็บซ่อนด้วย CSS ไม่ถอดออก (`DocTabs stackNarrow`): ค่าที่พิมพ์ค้างในฟอร์มไม่หายเมื่อสลับแท็บ และจอเล็กแสดงทุกแผงต่อกันโดยไม่ต้องมีหน้าจอสองชุด
4. รายการไม่ตรงอยู่เหนือแท็บ ไม่ซ่อนในแท็บจับคู่ PO เพราะเป็นเรื่องที่ต้องทำก่อน และหลังกดส่งจับคู่ต้องเห็นทันทีโดยไม่ต้องเปลี่ยนแท็บ
5. แถบยอดเป็นยอดก่อน VAT: ยอด PO − ใบอื่นที่นับตาม BR-MATCH-08 (`INVOICED_STATUSES` ชุดเดียวกับการจับคู่) − ใบนี้ · ติดลบเมื่อเกิน PO และบอกเป็นคำว่าเกิน · ใบที่ปฏิเสธหรือยกเลิกไม่ตัด · ตัวเลขนี้แสดงอย่างเดียว ไม่ใช้ตัดสินสิ่งใด เพราะการจับคู่ตรวจรายบรรทัด (`src/core/matching/po-balance.ts`)
6. ธงที่รอบจ่ายจะขึ้นกับผู้ขาย (BR-PAY-06) แสดงบนใบเฉพาะผู้มี `paymentRun.view` ระดับองค์กร (FINANCE AUDITOR) ตามสิทธิ์เดิมของรอบจ่าย ฝ่ายจัดซื้อเห็นรายการไม่ตรงแต่ไม่เห็นธง · ส่งแต่รหัสธง ไม่มีเลขบัญชีทั้งเต็มและ mask (BR-AUTH-04) · ธงไม่บล็อกการจ่าย (OQ-132)
7. ร่างที่เลขซ้ำกับใบอื่นของผู้ขายแสดงในป้ายตั้งแต่ร่างตาม BR-MATCH-12 · เดิมระบบปฏิเสธตอนส่งแต่ไม่มีป้ายให้เห็นก่อน
8. อีเมลผู้ส่งและหัวเรื่องในแท็บที่มาเห็นเฉพาะผู้มี `invoice.record` เพราะเป็นข้อมูลของกล่องรับ · ผู้อ่านใบคนอื่นเห็นแค่ว่ามาทางอีเมล
9. แท็บความเห็นแสดงเหตุผลที่คนเขียนไว้กับใบ เหมือนหน้าเอกสาร · การเขียนความเห็นเองอยู่ใน NEW-78 `[go-live]` ไม่เพิ่มคำสั่งใหม่ในรอบนี้
10. คำอธิบายอยู่ในข้อความไทยและอังกฤษครบทุกรหัส และมีเทสต์ให้ล้มเมื่อเพิ่มรหัสใหม่โดยไม่มีคำอธิบาย (`tests/unit/invoice-explanations.test.ts`)
11. ไฟล์ตัวอย่างของใบสแกน (`scannedInvoicePdf`) เปลี่ยนเป็น PDF ที่ถูกต้อง เพราะของเดิมมีแค่หัวไฟล์และโปรแกรมอ่าน PDF ขึ้น error เมื่อเปิดในหน้า · หน้ากระดาษแสดงอักษรละตินและตัวเลขเท่านั้นเพราะไม่ฝังฟอนต์ไทย คำทั้งหมดยังอยู่ในบรรทัด comment

## สิ่งที่ไม่ทำ

- ไม่ลอกสีน้ำเงิน พื้นไล่สี ข้อความ และชื่อฟีเจอร์ของ Zip (§9.9)
- ไม่มีคำอธิบายจาก AI และปุ่มบอกว่าช่วยได้ไหมในแผงแจ้งเตือน: เป็นลำดับ 5 ของรายงานและ NEW-119
- ไม่เพิ่มกฎใหม่ เช่น โดเมนอีเมลแปลกหรือส่วนลดสูงผิดปกติ: ต้องมีชุดทดสอบของจริงก่อน

## ผลที่ตามมา

- ผู้ตรวจเทียบค่ากับไฟล์ได้ในหน้าเดียว และเห็นว่า PO เหลือเท่าไรโดยไม่ต้องเปิดหน้า PO
- ลิงก์เปิด PO ย้ายจากหัวใบไปอยู่บนแถบยอดที่เดียว
- `getApInvoicePage` อ่านเพิ่ม 4 ถึง 7 query ต่อการเปิดหน้า ในธุรกรรมอ่านอย่างเดียวเดิม
