# ADR-081: สมุดของผู้ช่วย ผลงานเดือนนี้ และประวัติการทำงานใน `/admin/ai`

- สถานะ: ตัดสินแล้ว (ผู้ใช้ยืนยัน NEW-125 ในลำดับของ ADR-080 เมื่อ 2026-11-03 · คำถาม OQ-41 รอผู้ใช้ตอบ)
- วันที่: 2026-11-03
- ที่มา: NEW-125 · ข้อเสนอ `docs/reports/bcs-assistants.md` หัวข้อ "รายการและที่อื่น" · BR-AI-04 BR-AI-08 BR-AP-10

## บริบท

- หน้า `/admin/ai` มีแค่ credits ของเดือนกับสวิตช์ของผู้ช่วยแต่ละตัว และเปิดได้เฉพาะ ORG_ADMIN (`admin.ai.manage`)
- AgentAction เก็บทุกการเรียกอยู่แล้ว (BR-AI-04) แต่ไม่มีหน้าให้อ่าน · `GET /api/ai/actions/[id]` อ่านได้ทีละรายการ และ `ai.actions.view` กำหนดแล้วว่า AUDITOR เห็นเนื้อหา ORG_ADMIN เห็น metadata
- การตั้งค่าของผู้ช่วยมี `version` และ `updatedById` และทุกการเปลี่ยนเป็น event `ai_agent.*` แต่หน้าจอไม่บอกว่าใครเปลี่ยน
- สิ่งเดียวที่ผู้ช่วยเรียนรู้ในระยะ 1 คือรหัสบัญชีที่เสนอจากประวัติ (BR-AP-10 · ไม่ใช้ AI): ผู้ดูแลไม่เห็นว่าเรียนอะไร และปิดหรือลบไม่ได้
- NEW-125 ขอ "ยอดที่หาได้" ในผลงานรายเดือน แต่ spec ไม่ได้นิยามว่านับอะไร และผู้ช่วยหาเงินประหยัด (NEW-123) ยังไม่มีบันทึกของยอดที่เจอ

## การตัดสินใจ

> หน้า `/admin/ai` เป็นที่เดียวที่ผู้ดูแลและผู้ตรวจสอบเห็นว่าผู้ช่วยทำอะไรไปแล้ว เรียนอะไรไว้ และใครตั้งค่าอะไร ทุกตัวเลขนับด้วยโค้ดจาก AgentAction และ Event ผู้ดูแลปิดหรือลบสิ่งที่ผู้ช่วยเรียนรู้ได้ และทุกการเปลี่ยนเป็น event

1. **ใครอ่านและใครเปลี่ยน** (BR-AI-28): capability ใหม่ `admin.ai.view` ของ ORG_ADMIN และ AUDITOR (ORG) อ่านทั้งหน้า รวม credits และการตั้งค่าที่เดิมใช้ `admin.ai.manage` · การเปิดปิดผู้ช่วยและการแก้สมุดยังเป็น `admin.ai.manage` ของ ORG_ADMIN · AUDITOR เห็นหน้าเดียวกันโดยไม่มีสวิตช์และปุ่ม · เมนู "ผู้ช่วย AI" ใช้ `admin.ai.view`
2. **ประวัติการทำงาน** (`listAgentActivity` ใน `src/server/services/ai/report.ts`): AgentAction ใหม่สุดก่อน ทีละ 20 รายการ บอกเมื่อไร ใครสั่ง (ระบบเมื่อไม่มีผู้สั่ง) ทางช่องทางไหน ทำอะไร ผลเป็นอย่างไร เอกสารเลขอะไร ใช้ข้อมูลอะไร (จำนวนไฟล์ ประเภทคำขอ งานอนุมัติ เครื่องมือของคำถาม) เติมกี่ช่อง คนแก้ช่องไหน และ credits · ไม่แสดง `inputText` และ `output` ให้ใครเลยบนหน้านี้ · ค่าที่ AI อ่านกับค่าที่คนแก้ (`diff`) เห็นเฉพาะ AUDITOR และผู้สั่งเอง ตาม `ai.actions.view` · ชื่อช่องที่คนแก้ (key ของ `diff`) เป็น metadata เพราะ event `agent_action.edited` มีอยู่แล้ว
3. **ประวัติการตั้งค่า** (`listSettingChanges`): จาก event `ai_agent.enabled` `.disabled` `.updated` พร้อมผู้เปลี่ยน เวลา ค่าหลังเปลี่ยน และฉบับ · แต่ละผู้ช่วยบอก "ฉบับที่ n · บันทึกล่าสุดโดย ... เมื่อ ..." จาก `AiAgentSetting` (ฉบับที่แสดง = `version` + 1)
4. **สมุดของผู้ช่วย** (`src/server/services/assistants/notebook.ts` · `learning.ts`): ระยะ 1 มีเรื่องเดียว คือรหัสบัญชีที่ผู้ช่วยเสนอต่อคู่ "เลขผู้เสียภาษีของผู้ขาย + หมวดของบรรทัด PO"
   - แต่ละเรื่องคือสิ่งที่หน้าลงรหัสจะเสนอให้ใบที่ลงวันนี้ คำนวณด้วย `suggestCoding` ตัวเดียวกันจากบรรทัดชุดเดียวกับ BR-AP-10 พร้อมที่มาภาษาไทย (ยืนยันกี่ครั้งจากกี่รายการ ช่วงกี่วัน ใช้ล่าสุดวันไหน ใครยืนยัน)
   - **ปิด**: ผู้ช่วยไม่ใช้เรื่องนั้นจนกว่าจะเปิดอีกครั้ง หน้าลงรหัสเสนอรหัสของบรรทัดงบแทน บรรทัดเดิมยังอยู่
   - **ลบ**: บรรทัดที่ยืนยันถึงเวลาที่ลบไม่ถูกใช้อีกตลอดไป และเรื่องกลับเป็นเปิด · ถ้าฝ่ายบัญชียืนยันรหัสในใบต่อไป ผู้ช่วยเริ่มเรียนใหม่จากใบนั้น (เป็นเรื่องใหม่ที่มีที่มาของตัวเอง) · ต้องยืนยันใน AlertDialog เพราะย้อนไม่ได้ (§9.9)
   - เก็บใน `AssistantLearning` แถวละคู่ (`disabled` `forgottenAt` `version`) ไม่มีแถว = ใช้อยู่ · ไม่ลบหรือแก้บรรทัดใบแจ้งหนี้ ซึ่งเป็นบันทึกทางบัญชี · ทุกการเปลี่ยนเป็น event `assistant_learning.disabled` `.enabled` `.forgotten` ที่อ้างผู้ขายด้วย id ไม่ใช่เลขผู้เสียภาษี (บุคคลธรรมดาใช้เลขบัตรประชาชน)
   - `suggestionsFor` ของ S8 และสมุดอ่านผ่าน `learningInUse` ตัวเดียวกัน สิ่งที่ผู้ดูแลเห็นจึงตรงกับที่หน้าลงรหัสเสนอ และ `invoice.confirmCoding` บันทึก `codingSource` ตามนั้น (BR-AP-10 เพิ่มข้อความนี้)
   - หน้าบอกว่าผู้ช่วยใช้ข้อมูลขององค์กรในระบบนี้เท่านั้น ไม่ส่งไปเทรนหรือปรับแต่งโมเดล (BR-AI-08)
5. **ผลงานเดือนนี้** (`monthResults` · เดือนไทยของ `ctx.now`): จำนวนการเรียกและที่ไม่สำเร็จ · ช่องที่ AI เติมของเอกสารที่คนยืนยันในเดือน แยกที่คนเก็บไว้และที่คนแก้ · เอกสารที่ระบบตรวจแล้วเตือนหรือไม่ผ่าน และที่คนตัดสินแล้ว · ความเห็น "ช่วยได้" "ไม่ช่วย" · credits ที่ใช้เทียบที่ได้และแยกตามผู้ช่วย · ยอดที่หาได้ (ข้อ 6) · ทุกตัวเลขเป็นลิงก์ไปประวัติการทำงานที่กรองชุดเดียวกัน (`?show= &month= &agent=`) ตาม §9.9 และเทสต์ตรวจว่าจำนวนเท่ากัน · ไม่มี "ชั่วโมงที่ประหยัด" เพราะไม่มีข้อมูลที่วัดได้จริง
6. **ยอดที่หาได้ (OQ-41 ค่าเริ่มต้น)**: ยอดที่ใบแจ้งหนี้เรียกเกิน PO คือราคาเกินและจำนวนเกินที่สั่ง จาก `invoice.exception_raised` ครั้งล่าสุดของแต่ละใบในเดือน ไม่นับรอตรวจรับ งบไม่พอ VAT และใบที่อาจซ้ำ เพราะไม่ใช่เงินที่ผู้ขายเรียกเกิน · เห็นเฉพาะผู้มี `po.view` ทั้งองค์กร (AUDITOR เห็น ORG_ADMIN ไม่เห็น เพราะ ORG_ADMIN ไม่มีสิทธิ์อ่านใบแจ้งหนี้) · รายการใบที่นับอยู่ใต้ผลงานในหน้าเดียวกัน · ยอดประหยัดของ NEW-123 เพิ่มเมื่อมีบันทึกเป็น event

## สิ่งที่ไม่ทำ

- ไม่ให้ผู้ดูแลแก้รหัสที่ผู้ช่วยเสนอเอง: ลบแล้วให้ฝ่ายบัญชียืนยันรหัสที่ถูกในใบถัดไป เพราะรหัสบัญชีเป็นงานของ FINANCE
- ไม่แสดงคำถาม เอกสาร หรือคำตอบของ AI บนหน้านี้ (อ่านทีละรายการได้ตาม `ai.actions.view` เดิม)
- ไม่นับเรื่องบนการ์ด "ผู้ช่วยเจอให้คุณ" เพราะคำนวณสดและไม่ได้บันทึกว่าแสดงอะไรไป (นับได้เฉพาะที่ปัดทิ้ง ซึ่งบอกฝั่งเดียว)
- ไม่ส่งข้อมูลไปเทรนโมเดล และไม่ให้ AI เรียนรู้จากผลของตัวเองโดยไม่มีที่มา (BR-AI-08 · NG-6)

## ผลที่ตามมา

- ผู้ตรวจสอบตอบได้ว่าผู้ช่วยทำอะไร เรียนอะไร และใครตั้งค่า จากหน้าเดียว · ผู้ดูแลหยุดคำแนะนำที่ผิดได้ทันทีโดยไม่ต้องแก้ข้อมูลบัญชี
- หน้าอ่านประวัติการยืนยันรหัสทั้งปีทุกครั้งที่เปิด ข้อมูล demo เล็กจึงเร็ว · ข้อมูลจริงอาจต้องสรุปล่วงหน้า (ข้อ go-live ที่พบในรีวิว)
