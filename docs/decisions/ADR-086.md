- ณ 2026-11-11: l2 กำลังทำ S10-10 · หลังข้อนี้เหลือข้อ `[demo]` 8 ข้อ (S10-14 ถึง S10-21) · l3 กำลังทำ S11-09 · หลังข้อนี้เหลือ 10 ข้อ (S11-10 ถึง S11-17 · S11-24 · S11-27) และ S11-06 S11-08 ที่โค้ดเสร็จแล้วแต่ยังรอติ๊ก
- งาน AI ของสองขั้น (S10-16 Sourcing และ Negotiation Agent กับชุดประเมิน S10-19 · S11-13 Risk Agent กับชุดประเมิน S11-14) อยู่ในโมดูล AI ทั้งหมด (`src/lib/ai-config.ts` `src/server/ai` prompt และ fixture ประเมิน) ไม่แตะเงิน สิทธิ์ หรือ DOA โดยตรง และแยกจากงานหน้าจอ seed และรายงานของสายเจ้าของได้
- ถ้าสองสายเติมตารางเดียวกันใน `ai-config.ts` พร้อมกันจะเกิด conflict ทุกครั้งที่รวมงาน และ golden ของ AI ต้องเรียงเลขต่อกัน (GC-AI 96–99 ของ S10 · 100–103 ของ S11 · spec_check ตรวจว่าเลขไม่ขาด) · ให้สายเดียวเป็นเจ้าของงาน AI ทั้งสองขั้นและทำ S10 ก่อน S11 จึงไม่มีทั้ง conflict และเลขขาด
- S10-16 ต้องมี S10-09 S10-12 · S11-13 ต้องมี S11-05 S11-06 · โค้ดเหล่านี้ยังอยู่แค่ใน `p1/l2` และ `p1/l3` · l1 จึงต้องรอให้สองสายส่งงานเข้า main ก่อน
- S11-27 (heap ของ `tsc`) ไม่ย้าย: บรรทัดของข้อนี้มีแค่ใน `p1/l3` ยังไม่อยู่ใน main ถ้า l1 ติ๊กจะชนกับบรรทัดของ l3 ตอนรวม
- `.env` ของ l1 ยังไม่มี `ANTHROPIC_API_KEY` ซึ่งชุดประเมิน S10-19 และ S11-14 ต้องใช้ (main มีแล้ว)

## การตัดสินใจ

> 1. **ข้อที่ย้ายมาที่ l1 (ตามลำดับนี้):** S10-16 (`high`) → S10-19 (`high`) → S11-13 (`high`) → S11-14 (`high`) · เนื้อหา "เสร็จเมื่อ" และ effort ของแต่ละข้อไม่เปลี่ยน · สั่งในโฟลเดอร์ `.worktrees/l1` ด้วยรหัสข้อ เช่น `ทำ S10-16` (ไม่ใช่ `ทำข้อถัดไปของเส้นชัย H` เพราะคำสั่งนั้นจะเลือกข้อของ S7)
> 2. **ข้อที่ยังอยู่กับสายเดิม:** l2 = S10-10 S10-14 S10-15 S10-17 S10-18 S10-20 S10-21 · l3 = S11-06 S11-08 (ติ๊ก) S11-09 ถึง S11-12 S11-15 S11-16 S11-17 S11-24 S11-27 · l2 และ l3 ไม่ทำข้อของข้อ 1 และไม่เติมตาราง agent ใน `src/lib/ai-config.ts` (ถ้าข้อของตนต้องการ ให้บอกผู้ใช้)
> 3. **ระหว่างรอ:** l1 ยังไม่มีข้อที่เริ่มได้จนกว่า l2 ส่ง S10-10 เข้า main (ข้อ 4) · แชตของ l1 ที่เปิดก่อนนั้นจบรอบและบอกใน "รอคุณ"
> 4. **จุดส่งเข้า main ที่เพิ่ม (ผู้ใช้พิมพ์ `ส่งเข้า main ได้` ในแชตของสายนั้นเท่านั้น · ก่อนส่ง verify @demo @p1demo ผ่านตาม ADR-085 ข้อ 5):**
>    - l2 หลังติ๊ก S10-10: ทำให้ l1 เริ่ม S10-16 ได้ (ข้อ 3) และให้ l3 เพิ่ม GC-SOD-21 22 แล้วติ๊ก S11-06 S11-08
>    - l3 หลังติ๊ก S11-06 S11-08 และ S11-09: ทำให้ l1 เริ่ม S11-13 ได้
>    - l1 หลังติ๊ก S10-19: ก่อน S10-18 ของ l2 (ฉาก demo ต้องมี agent) · l1 หลังติ๊ก S11-14: ก่อน S11-15 ของ l3
> > 5. **ลำดับรอกัน:** S10-18 ของ l2 รอ S10-16 ถึง S10-19 เข้า main · S11-15 ของ l3 รอ S11-13 S11-14 เข้า main · ระหว่างรอ สายเจ้าของทำข้ออื่นของตนก่อน · ถ้าเหลือแต่ข้อที่รอ ให้จบรอบและบอกใน "รอคุณ"
> 6. **เลขที่ออกใหม่:** l1 ใช้ช่วงเลขของขั้นเจ้าของข้อ (S10 = ADR/OQ 201–219 · S11 = 221–239) และเพิ่มข้อใหม่ที่พบท้ายขั้นนั้น · เพราะสายเจ้าของอาจใช้เลขเดียวกัน ให้ตรวจเลขซ้ำกับ main และ branch ของสายเจ้าของตอนส่ง แล้วเลื่อนเลขของ l1 (แบบ ADR-080) · GC-AI ของ S10 (96–99) ต้องเข้า main ก่อนของ S11 (100–103)
> 7. **รีวิว:** ข้อ 1 ไม่มีข้อ `xhigh` จึงไม่รีวิวทันที · งานของ l1 อยู่ในการรีวิวท้ายขั้นของสายเจ้าของ (S10-21 S11-17 ใช้ `/code-review high main...HEAD` ซึ่งเห็นงานของ l1 ที่เข้า main แล้วไม่ครบ) ดังนั้นก่อนส่งงาน AI แต่ละชุด l1 รัน `/code-review high main...HEAD` ของตัวเอง แก้ข้อที่กระทบความถูกต้อง และบันทึกใน `docs/reports/p2-review-S10.md` หรือ `p2-review-S11.md` ส่วนท้าย
> 8. **key ของชุดประเมิน:** ก่อน S10-19 แชตของ l1 คัดบรรทัด `ANTHROPIC_API_KEY` จาก `E:\BCS\.env` ไปที่ `.worktrees/l1/.env` เอง ไม่พิมพ์ค่าในแชตหรือ log · ไม่มี key ใน main → หยุดและบอกผู้ใช้
> 9. **กติกาอื่นตาม ADR-085:** ฐานข้อมูลและพอร์ตของ l1 · รวม main เข้าสายก่อนทุกข้อ · ไฟล์ร่วมแก้แบบเพิ่มต่อท้าย · พักการส่งระหว่าง pentest
