# ADR-102: ผู้ตรวจคู่ขนานเป็น WorkflowVersion แยกจาก DOA

- สถานะ: เสนอ (ร่าง P1-04 · รอผู้ใช้อนุมัติใน P1-06)
- วันที่: 2026-10-11
- ที่มา: docs/sub-specs/S6.md หัวข้อ "Entity และ migration" (`WorkflowVersion` `WorkflowRule`) และ "กฎ" (BR-WF-06 ถึง BR-WF-12) · ข้อ P1-04

## บริบท

- ผู้ตรวจคู่ขนานไม่ใช่อำนาจอนุมัติตาม DOA (ผู้ตรวจไม่อนุมัติไม่ได้ · OQ-101) แต่ต้องควบคุมการเปลี่ยนแบบเดียวกับ DOA เพราะการตัดผู้ตรวจทำให้การควบคุมอ่อนลง
- FR-WF-103 ต้องมีฟอร์มตั้งค่า เวอร์ชัน และ dry-run โดยไม่มีตัวสร้างแบบลากวาง (NG-4)
- ภาคผนวก A มีค่าตั้ง `features.parallelApproval` ที่ยังไม่มีโค้ดใช้ และ ORG_ADMIN แก้ค่าตั้งได้คนเดียว

## การตัดสินใจ

> ผู้ตรวจคู่ขนานอยู่ใน `WorkflowVersion` แยกจาก DOA วงจรเดียวกับ DOA version (lint test case dry-run อนุมัติตามข้อ `DOA_CHANGE` ถอนก่อนมีผล) · เงื่อนไขใช้ภาษาเงื่อนไขของ §7.9 เพิ่มตัวแปรหมวดสินค้าและรหัสบัญชีของบรรทัดงบ และ op `anyIn` · ไม่ใช้ `features.parallelApproval` เป็นสวิตช์ (คงคีย์ใน schema แต่ไม่มีผล) เพราะสวิตช์ที่ ORG_ADMIN แก้ได้คนเดียวจะปิดผู้ตรวจโดยไม่ผ่าน 4-eyes

## ผลที่ตามมา

- เงื่อนไขใช้ภาษาเงื่อนไขเดิมของ §7.9 เพิ่ม `$lineCategories` `$budgetAccountCodes` และ op `anyIn` · lint และ test case แบบ BR-DOA-08
- อนุมัติเผยแพร่และถอนตามข้อ `DOA_CHANGE` บน subject `WORKFLOW_VERSION` ที่ต้อง step-up ทุกครั้งและตัดสินบนเว็บเท่านั้น (OQ-110)
- องค์กรที่ไม่มี workflow ฉบับที่มีผลได้เส้นทางเดิม จึงไม่ต้องมีสวิตช์ · `features.parallelApproval` คงใน schema เพื่อให้ค่าตั้งเดิม parse ผ่าน และภาคผนวก A หมายเหตุว่าไม่มีผล
- seed WF-SIMEC ฉบับ 1 จากชีต Workflow_Reviewers
