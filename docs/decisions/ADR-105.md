# ADR-105: อนุมัติเกินงบเป็นเอกสาร BudgetOverrun แยก

- สถานะ: เสนอ (ร่าง P1-04 · รอผู้ใช้อนุมัติใน P1-06)
- วันที่: 2026-10-11
- ที่มา: docs/sub-specs/S6.md หัวข้อ "State machine" (`BudgetOverrun`) "กฎ" (BR-BUD-12 ถึง BR-BUD-15 BR-BUD-18) และ "เรื่องที่ผู้ใช้ต้องตัดสิน" · ข้อ P1-04

## บริบท

- BR-BUD-02 FR-INT-007 AC2 และ G-4 กำหนดว่าคำขอที่งบไม่พอต้องไม่ถึงผู้อนุมัติคนใด แต่ FR-BUD-101 ต้องอนุมัติเกินงบตาม DOA
- รอบตรวจไขว้พบว่าแบบเส้นทางรวม (ขอซื้อก่อนแล้วเกินงบ) ทำให้ G-4 ไม่เป็นศูนย์ และพบว่าการเติมงบที่ใช้แล้วคืนไม่ได้ทำให้ยอดค้างเป็นงบว่างของคำขออื่น

## การตัดสินใจ

> อนุมัติเกินงบเป็นเอกสาร `BudgetOverrun` ที่เติมงบแล้วกันไว้ให้คำขอ คืนส่วนที่ไม่ใช้ตอนส่งคำขอหรือหมดอายุ และคืนส่วนที่ใช้แล้วเมื่อคำขอหรือ PO ของมันปล่อยกลับในธุรกรรมเดียวกัน (บรรทัด PO ของคำขอที่ยังมีส่วนค้างไม่รวมกับคำขออื่น) · ไม่มีคำขอใดเข้าเส้นทางก่อนงบพอ จึงไม่เปลี่ยนสูตร G-4 และฐานร่วมไม่มีเส้นทางรวม

## ผลที่ตามมา

- เอกสารอนุมัติก่อนคำขอเข้าเส้นทาง จึงคงนิยาม G-4 และกฎเดิม · ฐานร่วมไม่สร้างเส้นทางรวมหรือคอลัมน์ที่มาของขั้น
- คืนส่วนที่ไม่ใช้ตอนใช้และตอนหมดอายุ และคืนหลังใช้เมื่อคำขอหรือ PO ของมันคืนจองหรือคืนถือ (BR-BUD-18) · บรรทัด PO ของคำขอที่มีส่วนค้างรวมกับคำขออื่นไม่ได้
- golden GC-BUD-15 ถึง 24 และ property test INV-BUD-09 INV-BUD-10
- ถ้าผู้ใช้เลือกเส้นทางเดียวใน P1-06 ต้องแก้ G-4 BR-BUD-02 FR-INT-007 AC2 ก่อน P1-07 และเขียนชุดเกินงบของ S6 ใหม่ (OQ-104)
