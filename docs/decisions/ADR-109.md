# ADR-109: QR ตรวจสอบเอกสารออกในคำสั่ง POST และ token จาก HMAC

- สถานะ: ยอมรับ (ร่าง P1-04 · ผู้ใช้อนุมัติตามที่แนะนำใน P1-06 เมื่อ 2026-10-12)
- วันที่: 2026-10-11
- ที่มา: docs/sub-specs/S6.md หัวข้อ "Entity และ migration" (`DocumentVerification`) และ "กฎ" (BR-QR-01 BR-QR-02) · ข้อ P1-04

## บริบท

- PDF ของ PR และ PO สร้างตอนดาวน์โหลดผ่าน GET ที่ไม่เปลี่ยนอะไร (`src/server/services/documents/pdf.ts`) · §17.3 ห้าม GET ที่เปลี่ยนสถานะ
- ร่างแรกออก token ใหม่ทุกครั้งที่สร้าง PDF ซึ่งจะเป็น GET ที่เขียนข้อมูล และทำให้ใบที่พิมพ์ซ้ำขึ้นว่ามีฉบับใหม่ทั้งที่เนื้อหาไม่เปลี่ยน
- S17 ต้องสแกน QR บนใบ PO ที่พิมพ์ไว้ทั้งตอนออนไลน์และออฟไลน์

## การตัดสินใจ

> QR ตรวจสอบเอกสาร: แถว `DocumentVerification` ออกเฉพาะในคำสั่งส่ง ส่งซ้ำ และอนุมัติใบแก้ไข PO เมื่อเนื้อหาที่พิมพ์เปลี่ยน · token = HMAC ของ id แถวด้วยกุญแจที่แยกจาก `ENCRYPTION_KEY` จึงพิมพ์ซ้ำได้ token เดิมโดยเก็บเฉพาะ sha256 · GET PDF และหน้า GET สาธารณะอ่านอย่างเดียว จำกัดอัตรา และตอบเหมือนกันเมื่อ token ผิด

## ผลที่ตามมา

- แถวเกิดในธุรกรรมของการส่ง ส่งซ้ำ และอนุมัติใบแก้ไข PO (S8 เรียก `issueDocumentVerification`) เมื่อ contentSha256 เปลี่ยน · แถวก่อนตั้ง supersededAt
- token = base64url(HMAC-SHA256(K, id ของแถว)) โดย K แยกจาก `ENCRYPTION_KEY` แบบ pepper ของ PIN จึงพิมพ์ซ้ำได้ token เดิมโดยไม่ต้องเก็บ token ดิบ · ไม่ต้องมี secret ใหม่
- เปลี่ยน `ENCRYPTION_KEY` ต้องคงกุญแจเก่าไว้ใน keyring จนกว่าเอกสารเดิมหมดอายุ เพราะ keyId ของแถวชี้กุญแจที่ใช้คิด token
- เทสต์นับแถวทุกตารางก่อนหลัง GET PDF และ GET /verify
