# ADR-111: ย้อนทดสอบที่เกิน 500 เอกสารเก็บผลในตาราง BacktestRun

- สถานะ: ยอมรับ (ตัดสินในข้อ S6-07 ตามค่าเริ่มต้นที่ปลอดภัย · ไม่เปลี่ยนกฎเงินหรืออำนาจ)
- วันที่: 2026-10-14
- ที่มา: docs/sub-specs/S6.md FR-DOA-103 AC3 และ BR-WF-13 · ข้อ S6-07

## บริบท

- FR-DOA-103 AC3 ให้ย้อนทดสอบร่างเป็นงานเบื้องหลังเมื่อเอกสารในช่วง 90 วันเกิน 500 ฉบับ และห้ามเขียนข้อมูลธุรกิจ
- sub-spec ไม่ได้กำหนดว่าผลของงานเบื้องหลังเก็บที่ไหนให้หน้าร่างและผู้อนุมัติ `DOA_CHANGE` เปิดอ่านภายหลัง
- คำสั่งปกติมีเวลาธุรกรรม 20 วินาที ซึ่งไม่พอสำหรับการคำนวณเส้นทางหลายร้อยเอกสารใหม่

## การตัดสินใจ

> ย้อนทดสอบไม่เกิน 500 เอกสารคำนวณทันทีในธุรกรรมอ่านอย่างเดียว · เกินนั้นสร้างแถว `BacktestRun` (PENDING) ด้วยคำสั่ง แล้ว job `backtest-run` คำนวณแบบอ่านอย่างเดียวและบันทึกผล (DONE หรือ FAILED) ลงแถวนั้นครั้งเดียวด้วยคำสั่งของระบบ · ตารางนี้เก็บเฉพาะผลของการทดลอง ไม่ใช่ข้อมูลธุรกิจ

## ผลที่ตามมา

- migration เพิ่มตารางใหม่ต่อท้าย (`BacktestRun` และ enum `BacktestRunStatus`) พร้อม CHECK ชนิดเอกสาร DOA_VERSION หรือ WORKFLOW_VERSION
- event `backtest.requested` และ `backtest.completed` ทำให้การเปลี่ยนสถานะของแถวมีร่องรอย
- ช่วงเวลาของงานเบื้องหลังสิ้นสุด ณ เวลาที่ขอ ผลจึงตรงกับที่หน้าเว็บจะแสดง ณ ตอนนั้น
- สิทธิ์อ่านเท่ากับสิทธิ์สั่ง: ผู้ที่ทดลองร่างชนิดนั้นได้ และผู้อนุมัติของเส้นทาง `DOA_CHANGE` ของร่าง (BR-DOA-14)
