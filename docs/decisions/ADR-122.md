# ADR-122: engine จับคู่ใบแจ้งหนี้เป็น pure function ที่เทียบยอดก่อน VAT ต่อบรรทัด

- สถานะ: เสนอ (ร่าง P1-04 · รอผู้ใช้อนุมัติใน P1-06)
- วันที่: 2026-10-11
- ที่มา: docs/sub-specs/S8.md หัวข้อ "กฎ" (BR-MATCH-05 ถึง BR-MATCH-13) และ "ร่าง golden case" (matching.yaml) · ข้อ P1-04

## บริบท

- §7.14 มีแค่หลัก BR-MATCH-01 ถึง BR-MATCH-04 · spec ไม่ได้ระบุว่าเทียบราคาต่อหน่วยหรือยอดบรรทัด และไม่ได้ระบุวิธีปันส่วนลดท้ายบิล
- ราคาต่อหน่วยในใบมักมีทศนิยมมากกว่า PO และส่วนลดท้ายบิลทำให้ราคาต่อหน่วยไม่ตรงทั้งที่ยอดรวมถูก · เงินต้องเป็นสตางค์และปัดเฉพาะจุดของ BR-MONEY-02
- engine เงินของ repo อยู่ใน `src/core` แบบ pure และมี branch coverage 100% (§7.0)

## การตัดสินใจ

> engine จับคู่เป็น pure function ใน `src/core/matching`: เทียบยอดก่อน VAT ต่อบรรทัด (ไม่ใช่ราคาต่อหน่วย) หลังปันส่วนลดท้ายบิลด้วย largest remainder · คืนผลต่อบรรทัด รายการไม่ตรงในลำดับคงที่ และแผนงบ (ถือเพิ่ม ตัด คืน) ให้ service ทำตามด้วยฟังก์ชันงบเดิม · branch coverage 100%

## ผลที่ตามมา

- `src/core/matching` ไม่แตะฐานข้อมูลและเวลา · service ส่งข้อมูลบรรทัด PO GR และงบเข้าไป แล้วทำตามแผนงบที่ได้ด้วย `holdMore` `actualize` `closePo` เดิม
- รายการไม่ตรงเรียงตามเลขบรรทัดแล้วตามชนิด · `BUDGET_SHORT` เกิดเฉพาะเมื่อไม่มีชนิดอื่น · เกณฑ์มาจาก `settings.matching` และบันทึกใน `InvoiceMatch.policy`
- golden `matching.yaml` และ `invoice-vat.yaml` พร้อมตัวคำนวณอ้างอิงใน `scripts/spec_check.py`
