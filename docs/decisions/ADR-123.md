# ADR-123: กล่องอีเมลขาเข้าของใบแจ้งหนี้ผ่าน adapter โหมด mailpit

- สถานะ: เสนอ (ร่าง P1-04 · รอผู้ใช้อนุมัติใน P1-06)
- วันที่: 2026-10-11
- ที่มา: docs/sub-specs/S8.md หัวข้อ "กฎ" (BR-AP-02) และ "เรื่องที่ผู้ใช้ต้องตัดสิน" (OQ-124) · ข้อ P1-04

## บริบท

- §8.12 ให้ FR-AP-101 ระยะ 1 รับทางกล่องอีเมลและอัปโหลด · ADR-031 ครอบคลุมแค่อีเมลขาออก · ผู้ให้บริการขาเข้าของ production ยังไม่ได้เลือก (OQ-124)
- บนเครื่องมี Mailpit อยู่แล้วและทุกสายใช้ร่วมกัน · เนื้อความอีเมลอาจมีข้อมูลส่วนบุคคลที่ไม่จำเป็น

## การตัดสินใจ

> กล่องอีเมลขาเข้าผ่าน adapter `src/integrations/email-inbound` โหมด `mailpit` (บนเครื่อง เทสต์ demo · อ่าน REST API ของ Mailpit กรองตามที่อยู่ขององค์กร) และ `disabled` · production ตาม OQ-124 · กันซ้ำด้วย Message-ID · ไม่เก็บเนื้อความ · รับเฉพาะ PDF XML JPEG PNG เข้าที่เก็บ private · ไม่ส่งจับคู่เอง

## ผลที่ตามมา

- adapter `src/integrations/email-inbound` มีโหมด `mailpit` (อ่าน REST API กรองตามที่อยู่ขององค์กร) และ `disabled` · production เพิ่มเป็นข้อ go-live หลังคำตอบ OQ-124
- หนึ่งร่างต่อไฟล์แนบ · Message-ID เดิมไม่สร้างซ้ำ · ไม่เก็บเนื้อความ · ไฟล์ e-Tax อ่านด้วยตัวอ่านเดียวกับ BR-IVC-05 (FR-INTG-302)
- เทสต์ใช้ที่อยู่สุ่มต่อเทสต์เพื่อไม่ชนกับสายอื่น · ร่างไม่ถูกส่งจับคู่เอง FINANCE ต้องยืนยัน
