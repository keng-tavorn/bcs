# ADR-125: ใบแก้ไข PO มีค่าก่อนหลังและใช้ฟังก์ชันงบเดิม

- สถานะ: ยอมรับ (ร่าง P1-04 · ผู้ใช้อนุมัติตามที่แนะนำใน P1-06 เมื่อ 2026-10-12)
- วันที่: 2026-10-11
- ที่มา: docs/sub-specs/S8.md หัวข้อ "กฎ" (BR-POC-01 ถึง BR-POC-05) และ "ร่าง golden case" (po-change.yaml) · คำตัดสินของ agent หลักข้อ 11 และ 15 · ข้อ P1-04

## บริบท

- FR-AP-107 ต้องการแก้ PO หลังอนุมัติพร้อมเวอร์ชันตาม DOA `PO_CHANGE` · BR-IVC-02 บอกว่าชั้น 2 ใช้ใบแก้ไข PO แทนคำขอใหม่
- รอบ P1 ให้ S6 เป็นเจ้าของ `src/core/budget` แต่ผู้เดียว (คำตัดสินข้อ 11) · องค์กร DEMO ไม่มีข้อ `PO_CHANGE` ใน DOA และฉาก `@demo` ต้องไม่เปลี่ยน

## การตัดสินใจ

> ใบแก้ไข PO (`PoChange`) เก็บค่าก่อนและหลังต่อบรรทัด · จองส่วนเพิ่มตอนส่งแบบ BR-BUD-05 และมีผลตอนอนุมัติ โดยประกอบจากฟังก์ชันเดิมของ `src/core/budget` ไม่แก้ฟังก์ชันงบ · `PurchaseOrder.revisionNo` เพิ่มทีละ 1 พร้อม PDF ฉบับแก้ไขใหม่โดยเก็บฉบับเดิม · เปิดได้ครั้งละหนึ่งใบต่อ PO · อยู่ในโมดูล CORE และปิดไว้เมื่อ DOA ไม่มีข้อ `PO_CHANGE`

## ผลที่ตามมา

- ตาราง `PoChange` และ `PoChangeLine` เก็บค่าก่อนและหลัง · จองส่วนเพิ่มตอนส่งและถือตอนอนุมัติด้วย `submitPo` `approvePo` `rejectPo` `releaseHold` `reserve` เดิม · ตัวรัน golden `run_po_change` เป็นของ S8
- อนุมัติแล้วเพิ่ม `revisionNo` และ PDF ฉบับใหม่ ฉบับเดิมคงอยู่ · แก้เฉพาะวันส่งหรือหมายเหตุอนุมัติอัตโนมัติ
- อยู่ใน CORE: DOA ไม่มีข้อ `PO_CHANGE` → ไม่แสดงปุ่มและคำสั่งได้ `DOA_NOT_CONFIGURED` โดยไม่จองงบ
