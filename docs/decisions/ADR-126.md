# ADR-126: อีเมลถึงผู้ขายผ่านตาราง SupplierNotice

- สถานะ: ยอมรับ (ร่าง P1-04 · ผู้ใช้อนุมัติตามที่แนะนำใน P1-06 เมื่อ 2026-10-12)
- วันที่: 2026-10-11
- ที่มา: docs/sub-specs/S8.md หัวข้อ "กฎ" (BR-AP-08) และ interface กับ S9 · คำตัดสินของ agent หลักข้อ 10 · ข้อ P1-04

## บริบท

- §8.12 ให้ระยะ 1 แจ้งผู้ขายทางอีเมล (FR-AP-103 FR-PAY-103) เพราะยังไม่มีพอร์ทัล (S7) · `Notification` เดิมอ้าง Member แต่ผู้ขายไม่ใช่ Member
- ทั้ง S8 (รับใบ ปฏิเสธ พร้อมจ่าย) และ S9 (แจ้งผลการจ่าย แจ้งเปลี่ยนบัญชี) ต้องส่งอีเมลถึงผู้ขายและต้องไม่ส่งซ้ำเมื่อคำสั่งถูกส่งซ้ำ

## การตัดสินใจ

> อีเมลถึงผู้ขายใช้ตาราง `SupplierNotice` และงานส่งจาก outbox แยกจาก `Notification` (ซึ่งอ้าง Member) · กันส่งซ้ำด้วย dedupeKey · S9 ใช้ตารางและงานส่งเดียวกันด้วย templateKey `payment.advice` และ `bank_account.notice` และอ่านผลจาก event `supplier_notice.sent` `supplier_notice.failed` ไม่มี job ส่งแยก · ไม่ส่ง LINE ถึงผู้ขาย

## ผลที่ตามมา

- ตาราง `SupplierNotice` (unique ต่อ dedupeKey) และงาน `supplier-notice-send` จาก outbox เป็นทางเดียวของอีเมลถึงผู้ขาย · ไม่มีอีเมลผู้ขาย → `NO_EMAIL` และแจ้ง FINANCE
- S9 เพิ่มแม่แบบ `payment.advice` และ `bank_account.notice` แล้วอ่านผลจาก event `supplier_notice.sent` `supplier_notice.failed` · ไม่มี job ส่งแยก
- ไม่มีชื่อผู้อนุมัติภายในในอีเมล และไม่ส่ง LINE ถึงผู้ขาย
