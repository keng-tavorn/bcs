# ADR-128: บัญชีธนาคารของผู้ขายและขององค์กรเก็บในตารางเดียวและมีผลผ่านคำขอที่อนุมัติ

- สถานะ: ยอมรับ (ร่าง P1-04 · ผู้ใช้อนุมัติตามที่แนะนำใน P1-06 เมื่อ 2026-10-12)
- วันที่: 2026-10-11
- ที่มา: docs/sub-specs/S9.md หัวข้อ "Entity และ migration" และแถว "การเก็บเลขบัญชีของผู้ขาย" ใน "เรื่องที่ผู้ใช้ต้องตัดสิน" · ข้อ P1-04

## บริบท

- ระยะ 1 เปิดโมดูล `PAY` โดยไม่มี `SUPPLIER` ผู้ใช้ภายในจึงต้องดูแลบัญชีรับเงินของผู้ขายเอง และต้องผ่าน BR-SOD-05 (ผู้แก้ห้ามอนุมัติ บัญชีใหม่มีผลหลังอนุมัติ) (§4.11)
- §6.5 ตั้งชื่อ entity ไว้แล้วว่า `BankAccount` และ `BankAccountChange` · FR-SUP-103 ของ S7 (พอร์ทัลผู้ขาย) จะใช้ชุดเดียวกันต่อ
- รอบจ่ายต้องใช้บัญชีผู้จ่ายขององค์กรด้วย (ไฟล์ 1–2 ธนาคาร) ซึ่งมีความเสี่ยงแบบเดียวกัน
- เลขบัญชีของผู้ขายบุคคลธรรมดาเป็นข้อมูลส่วนบุคคล: ต้อง mask โดยค่าเริ่มต้น บันทึกการเปิดดู (NFR-PRIV-03 · BR-AUTH-04) และห้ามอยู่ใน log (NFR-SEC-09)
- การเข้ารหัสระดับคอลัมน์ต้องจัดการ key และต้องใช้ HMAC เพื่อหาบัญชีซ้ำและเทียบตอนสร้างไฟล์ · เลขผู้เสียภาษีบุคคลธรรมดาที่มีอยู่ก็เก็บแบบไม่เข้ารหัสพร้อม mask
- ตาราง `SensitiveAccessLog` ยังไม่มีในระบบ (S5-11 เป็นข้อ `[go-live]`) · คำตัดสินของ agent หลักให้ S8-01 สร้างตารางและ helper แล้ว S9 ใช้ต่อ

## การตัดสินใจ

> บัญชีธนาคารใช้ entity ตามชื่อใน §6.5: `BankAccount` (ownerKind `SUPPLIER` หรือ `ORGANIZATION`) และ `BankAccountChange` · บัญชีมีผลผ่านคำขอเปลี่ยนที่อนุมัติเท่านั้น หนึ่งบัญชี ACTIVE ต่อผู้ขาย · เลขบัญชีเก็บเป็นตัวเลขล้วนไม่เข้ารหัสระดับคอลัมน์ (แบบเดียวกับเลขผู้เสียภาษีบุคคลธรรมดา) แสดง mask 4 ตัวท้าย เปิดเต็มบันทึก `SensitiveAccessLog` (ตารางและ helper ที่ S8 สร้าง) และห้าม log (NFR-PRIV-03 NFR-SEC-09)

## ผลที่ตามมา

- ตารางเดียวรองรับทั้งบัญชีผู้ขายและบัญชีผู้จ่ายขององค์กร (CHECK ให้ `supplierId` มีเมื่อเป็น SUPPLIER) · partial unique ให้ผู้ขายมีบัญชี ACTIVE ได้หนึ่งบัญชี (INV-PAY-04)
- การเพิ่ม เปลี่ยน หรือปิดบัญชีทุกครั้งเป็น `BankAccountChange` ที่อนุมัติตาม DOA ชนิด `BANK_ACCOUNT_CHANGE` · ผู้อนุมัติและ step-up ตาม OQ-133 OQ-137 และกฎ step-up ของฐานร่วม
- เปิดเลขเต็มได้เฉพาะผู้มี `bankAccount.reveal` และทุกครั้งเขียน `SensitiveAccessLog` · event ใช้ `bankAccountId` และ 4 ตัวท้าย · มีเทสต์ redaction ของ log Event Notification และการ์ด LINE
- ถ้าลูกค้าหรือ DPO ต้องการเข้ารหัสระดับคอลัมน์ภายหลัง ต้องเขียน ADR ใหม่พร้อมแผน key และ HMAC
- ระยะ 1 บัญชีของผู้ขายมาจาก seed ขององค์กรตัวอย่าง (`sourceChangeId` ว่าง) · ข้อมูลจริงเข้าทางคำขอแบบชุดใน S9-15
