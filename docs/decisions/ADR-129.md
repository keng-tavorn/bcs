# ADR-129: แม่แบบไฟล์ธนาคารเป็นโค้ด ไม่ใช่ตารางที่แก้ได้

- สถานะ: ยอมรับ (ร่าง P1-04 · ผู้ใช้อนุมัติตามที่แนะนำใน P1-06 เมื่อ 2026-10-12)
- วันที่: 2026-10-11
- ที่มา: docs/sub-specs/S9.md หัวข้อ "กฎ" (BR-BANK-04) และ "Entity และ migration" (`BankAccount.fileTemplateCode` `fileParams`) · ข้อ P1-04

## บริบท

- BR-BANK-01 กำหนดว่าตัวสร้างไฟล์แยกต่อธนาคาร และ golden เป็นแบบ byte-exact + sha256 เทียบไฟล์ตัวอย่างที่ผ่านระบบทดสอบของธนาคาร
- รูปแบบไฟล์ของแต่ละธนาคารต่างกันมาก (ความยาวช่อง การเข้ารหัส แถวหัวท้าย) และยังไม่ได้สเปก (P0-03)
- ถ้าเก็บรูปแบบเป็นตารางที่ผู้ดูแลแก้ได้ รูปแบบจะเปลี่ยนได้โดยไม่มี golden คุม และไฟล์ที่ผิดหนึ่งไบต์อาจทำให้ธนาคารปฏิเสธหรือโอนผิด
- ค่าที่ธนาคารให้แต่ละลูกค้า (เช่น รหัสบริษัท) เป็นข้อมูลขององค์กร ไม่ใช่ของโค้ด

## การตัดสินใจ

> แม่แบบไฟล์ธนาคารเป็นโค้ด ไม่มีตาราง `BankFileTemplate`: ตัวสร้างต่อแม่แบบเป็น pure function ใน `src/core/bankfile` พร้อม golden byte-exact · บัญชีผู้จ่ายขององค์กรเลือกแม่แบบด้วย `fileTemplateCode` และค่าที่ธนาคารให้ใน `fileParams` ที่ตรวจด้วย Zod ของแม่แบบ

## ผลที่ตามมา

- ธนาคารใหม่ = ตัวสร้างใหม่ + golden + Zod ของ `fileParams` (ข้อ S9-12 หลังได้ P0-03) และต้องผ่าน `pnpm verify` ไม่มีหน้าจอแก้รูปแบบไฟล์
- ตัวสร้างไม่มีเวลาที่สร้างในเนื้อไฟล์ จึงสร้างซ้ำได้ไฟล์เดิมทุกไบต์ และเทียบ sha256 ได้
- บัญชีผู้จ่ายเปลี่ยนแม่แบบหรือ `fileParams` ผ่าน `BankAccountChange` (OQ-137) ไม่ใช่การแก้ค่าตรง
- service เป็นผู้เข้ารหัสตามแม่แบบด้วย `src/lib/encoding` และอ่านไฟล์กลับเพื่อตรวจยอด (BR-BANK-04)
