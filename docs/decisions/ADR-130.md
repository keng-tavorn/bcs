# ADR-130: ชั้น demo ใช้แม่แบบไฟล์กลางที่บอกชัดว่าไม่ใช่รูปแบบของธนาคาร

- สถานะ: เสนอ (ร่าง P1-04 · รอผู้ใช้อนุมัติใน P1-06)
- วันที่: 2026-10-11
- ที่มา: docs/sub-specs/S9.md หัวข้อ "ชั้น demo และชั้นของจริงของ 'เสร็จเมื่อ'" และ BR-BANK-05 · ข้อ P1-04

## บริบท

- "เสร็จเมื่อ" เดิมของ S9 คือการเงินอัปโหลดไฟล์ทดสอบกับธนาคารได้ แต่สเปกไฟล์และไฟล์ตัวอย่างของธนาคารยังไม่มา (P0-03)
- §17.3 ห้ามเดาเนื้อหาที่ติด OQ หรือข้อมูลที่รอลูกค้า · ไฟล์ที่เลียนรูปแบบธนาคารอาจทำให้ลูกค้าเข้าใจว่าใช้กับธนาคารได้แล้ว
- รอบ P1 ยังต้องพิสูจน์ส่วนที่ไม่ขึ้นกับธนาคาร: ยอดในไฟล์ตรงรอบจ่าย ไฟล์แก้ไม่ได้ สร้างใหม่เป็นเวอร์ชัน และ golden byte-exact

## การตัดสินใจ

> ชั้น demo ใช้แม่แบบกลาง `BCS-NEUTRAL-1` (CSV UTF-8 มี BOM บรรทัด CRLF แถว H D T · แถว H และชื่อไฟล์มี `NOT-A-BANK-FORMAT` · หน้าจอบอกว่าธนาคารไม่รับ) แทนการเดารูปแบบของธนาคาร จนกว่าได้ P0-03

## ผลที่ตามมา

- golden ของแม่แบบกลางคือ GC-BANK-12 ถึง GC-BANK-14 (bytes และ sha256) และตัวคำนวณอ้างอิงใน `scripts/spec_check.py`
- ชื่อไฟล์เป็น `BCS-NEUTRAL-1_NOT-A-BANK-FORMAT_<เลขรอบ>_v<เวอร์ชัน>.csv` และทุกหน้าที่สร้างหรือดาวน์โหลดมี Alert ว่าธนาคารจะไม่รับไฟล์นี้
- เมื่อได้ P0-03 ข้อ S9-12 เพิ่มตัวสร้างของธนาคารจริงตาม ADR-129 แล้วเปลี่ยนแม่แบบของบัญชีผู้จ่ายผ่าน `BankAccountChange` · แม่แบบกลางยังอยู่ไว้ทดสอบ
- เกณฑ์ "อัปโหลดกับธนาคารได้" เลื่อนเป็นชั้นของจริง (`[go-live]`)
