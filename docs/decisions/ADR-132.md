# ADR-132: ธงทะเบียนผู้ขายที่ระบบอ่านได้ (`Supplier.registryFlag`)

- สถานะ: เสนอ (ร่าง P1-04 · รอผู้ใช้อนุมัติใน P1-06)
- วันที่: 2026-10-11
- ที่มา: docs/sub-specs/S9.md หัวข้อ "ขอบเขต" และ BR-PAY-06 · docs/sub-specs/S8.md (S8-01 สร้างคอลัมน์ · BR-VAT-06) · คำตัดสินของ agent หลักข้อ 8 · ข้อ P1-04

## บริบท

- `Supplier.registryStatus` เดิมเป็นข้อความอิสระจากทะเบียน DBD (เช่น "ยังดำเนินกิจการอยู่") ที่ `src/server/services/suppliers` เขียนจากผลค้น จึงอ่านด้วยเครื่องไม่ได้
- BR-SUP-04 ต้องเตือนเมื่อผู้ขายเลิกกิจการหรือออกจากระบบ VAT · S8 ใช้ข้อเท็จจริงนี้ปฏิเสธ VAT ในใบแจ้งหนี้ (BR-VAT-06) และ S9 ใช้ติดธงในรอบจ่าย (§8.12)
- ร่างแรกให้ S8 อ่านข้อความและให้ S9 เพิ่ม enum ทีหลัง ทำให้มีสองแหล่งความจริงในสายเดียวกัน · คำตัดสินของ agent หลักให้ S8-01 สร้างคอลัมน์ครั้งเดียวและ S9 ใช้ต่อ

## การตัดสินใจ

> ธงทะเบียนผู้ขายเป็น enum `Supplier.registryFlag` (`NONE` `CEASED` `VAT_CANCELLED` `NOT_FOUND`) แยกจาก `registryStatus` ที่เป็นข้อความจากทะเบียน เพื่อให้การตรวจ VAT ของใบแจ้งหนี้ รอบจ่าย และ PO อ่านค่าเดียวกันโดยไม่แปลข้อความ · คอลัมน์สร้างใน migration ของ S8 และ seed จากชีต SupplierPayment · S9 อ่านอย่างเดียว · job ของ S4-16 ตั้งเมื่อใช้โหมด live

## ผลที่ตามมา

- S8-01 เพิ่ม `registryFlag` (ค่าเริ่มต้น `NONE`) และ `registryFlaggedAt` และ seed ค่าจากคอลัมน์ registryStatus ของชีต SupplierPayment (`SP0011` `SP0031` `SP0096`)
- S9 ใช้ค่า ≠ `NONE` เป็นธง `REGISTRY_CHANGED` ที่ต้องใส่เหตุผล (BR-PAY-06) และไม่สร้างหรือแก้คอลัมน์นี้
- `registryStatus` เดิมไม่เปลี่ยน ยังแสดงข้อความจากทะเบียนเหมือนเดิม
- ข้อ `[go-live]` S9-14 ให้ job `supplier-registry-recheck` ของ S4-16 ตั้งธงจากบริการจริงพร้อม event `supplier.registry_status_changed`
- ฉาก demo ที่ต้องมีใบพร้อมจ่ายของผู้ขายที่เลิกกิจการ ต้องตั้งธงหลังใบพร้อมจ่าย เพราะ BR-VAT-06 ปฏิเสธใบที่มี VAT (P1-08)
