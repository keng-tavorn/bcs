# ADR-133: รอบจ่ายเก็บ snapshot บัญชีผู้รับตอนส่งและตรวจซ้ำก่อนสร้างไฟล์

- สถานะ: ยอมรับ (ร่าง P1-04 · ผู้ใช้อนุมัติตามที่แนะนำใน P1-06 เมื่อ 2026-10-12)
- วันที่: 2026-10-11
- ที่มา: docs/sub-specs/S9.md หัวข้อ "Entity และ migration" (`PaymentRunItem`) และ BR-PAY-05 BR-BANK-06 · ข้อ P1-04

## บริบท

- ผู้อนุมัติอนุมัติการจ่ายให้บัญชีที่เห็นตอนอนุมัติ · ถ้าไฟล์อ่านบัญชีจากทะเบียน ณ ตอนสร้างไฟล์ การเปลี่ยนบัญชีหลังอนุมัติจะทำให้เงินไปบัญชีที่ไม่มีใครอนุมัติในรอบนั้น
- BR-BANK-02 ต้องตรวจก่อนส่งออกว่าบัญชีผู้รับตรงกับบัญชีที่อนุมัติในทะเบียน
- การหลอกเปลี่ยนเลขบัญชีเป็นความเสี่ยงหลักของการจ่ายเงินผู้ขาย

## การตัดสินใจ

> รอบจ่ายเก็บ snapshot บัญชีผู้รับตอนส่งอนุมัติ และตรวจกับทะเบียนอีกครั้งก่อนสร้างไฟล์ทุกเวอร์ชัน · รอบที่ส่งแล้วแก้รายการไม่ได้ ถ้าบัญชีเปลี่ยนหลังส่งต้องตีกลับหรือยกเลิกแล้วเตรียมใหม่

## ผลที่ตามมา

- `PaymentRunItem` เก็บ `bankAccountId` รหัสธนาคาร เลขบัญชี และชื่อบัญชี ณ เวลาส่ง · ไฟล์สร้างจาก snapshot นี้เท่านั้น
- ตรวจก่อนสร้างไฟล์ (BR-BANK-06) ได้ `ACCOUNT_NOT_ACTIVE` หรือ `ACCOUNT_MISMATCH` เมื่อทะเบียนเปลี่ยน แล้วไม่มีไฟล์ถูกสร้าง (GC-BANK-02 ถึง GC-BANK-04)
- หลังส่ง ยอด รายการ snapshot และลิงก์เอกสารไม่เปลี่ยน (INV-PAY-03) · ทางแก้คือตีกลับหรือยกเลิกแล้วเตรียมใหม่ ซึ่งได้เส้นทาง DOA ใหม่
- ผู้เตรียมของร่างได้แจ้งเตือนเมื่อบัญชีของผู้ขายในร่างเปลี่ยน (`payment_run.account_changed`)
