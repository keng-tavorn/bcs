# ADR-141: เรียก Claude ด้วย structured outputs และไม่ใช้ fallback ของรุ่น

- สถานะ: ยอมรับ (ร่าง P1-04 · ผู้ใช้อนุมัติตามที่แนะนำใน P1-06 เมื่อ 2026-10-12)
- วันที่: 2026-10-11
- ที่มา: docs/sub-specs/S13.md หัวข้อ "สถาปัตยกรรม" (ค่าเริ่มต้นของการเรียก) และ "กฎ" (BR-AI-11 BR-AI-23) · ข้อ P1-04

## บริบท

- BR-AI-10 ให้ใช้ structured outputs ของ Claude API กับ JSON schema ที่สร้างจาก Zod · ADR-060 ให้เรียกผ่าน AI SDK ใน `src/integrations/ai`
- วิธีเก่าทำ structured outputs ด้วยการบังคับให้โมเดลเรียก tool (`tool_choice`) ซึ่ง Claude Opus 5.5 และ Sonnet 5.5 ตอบ 400
- BR-AI-09 ให้เปลี่ยนรุ่นได้หลังผ่านชุดประเมินเท่านั้น และ gate ของ ADR-143 ผูกกับรุ่น · ถ้าคำขอถูกส่งต่อไปรุ่นอื่นอัตโนมัติ (fallback) ผลจะมาจากรุ่นที่ไม่เคยผ่านชุดประเมินโดยไม่มีใครรู้
- ราคาเขียน cache ขึ้นกับระยะเวลาเก็บ (TTL) · spec ไม่ได้ระบุ TTL

## การตัดสินใจ

> เรียก Claude ด้วย structured outputs แบบ `output_config.format` ที่สร้างจาก Zod ไม่ใช้ tool แบบบังคับ เพราะ Claude Opus 5.5 และ Sonnet 5.5 ปฏิเสธ `tool_choice` แบบบังคับ · ตั้ง effort ต่อ agent ชัดเจน · ไม่ใช้ fallback ของรุ่นทั้งฝั่ง API และฝั่งโค้ด เพราะ gate ผูกกับรุ่น · เก็บรุ่นที่ตอบจริง ไม่ตรงรุ่นที่ขอเป็น FAILED · cache ใช้ TTL 5 นาทีค่าเดียว · stop reason แบบ refusal เป็น FAILED แล้วใช้ทางกรอกเอง · ถ้า AI SDK ทำไม่ได้ใช้ `@anthropic-ai/sdk` ใน adapter เดียวกันตาม ADR-060

## ผลที่ตามมา

- S13-01 ตรวจกับเอกสารปัจจุบันของ Claude API ว่า `output_config.format` ใช้ผ่าน AI SDK ได้ ปิด fallback ของรุ่นได้ และอัตราราคาปัจจุบัน แล้วเขียนผลลง `src/lib/ai-config.ts`
- adapter คืนรุ่นที่ตอบจริงจาก response · `AgentAction.model` เก็บค่านี้ · ไม่ตรงรุ่นที่ขอ → FAILED (`AI_MODEL_MISMATCH`) แล้วผู้ใช้กรอกเอง · refusal → FAILED ไม่ลองรุ่นอื่น
- schema ที่ส่งให้ API ไม่ใช้ min max ของตัวเลข โค้ดตรวจและตัดช่วงเอง (BR-AI-16)
- ตารางราคาใช้ราคาเขียน cache ของ TTL 5 นาทีค่าเดียว (BR-AI-23)
- ถ้า AI SDK ทำไม่ได้ ใช้ `@anthropic-ai/sdk` ใน adapter เดียวกันตาม ADR-060 · เป็น dependency ใหม่จึงบอกผู้ใช้ก่อนติดตั้ง
