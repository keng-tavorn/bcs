# ADR-143: prompt ต่อ purpose และ gate ของชุดประเมินเป็นโค้ด

- สถานะ: ยอมรับ (ร่าง P1-04 · ผู้ใช้อนุมัติตามที่แนะนำใน P1-06 เมื่อ 2026-10-12)
- วันที่: 2026-10-11
- ที่มา: docs/sub-specs/S13.md หัวข้อ "สถาปัตยกรรม" (config และ integration) และ "ชุดประเมิน" · ข้อ P1-04

## บริบท

- §12.2 มี `promptVersionId` และ §6.5 มีตาราง `PromptVersion` `AiEvalRun` แต่ระยะ 1 มี prompt ไม่กี่ตัวและทีม BCS เป็นคนแก้เท่านั้น
- BR-AI-09 ให้รันชุดประเมินใหม่ทุกครั้งที่เปลี่ยน prompt หรือรุ่น จึงต้องรู้ว่าชุดไหนผ่านแล้ว
- Document Agent มีหลาย purpose (ใบเสนอราคา ใบส่งของ ใบแจ้งหนี้) และ prompt ใบแจ้งหนี้เขียนทีหลัง (S13-12) · ถ้าใช้เลขรุ่นต่อ agent การเพิ่ม prompt ใบแจ้งหนี้จะทำให้ gate ของใบเสนอราคาหลุด
- ด่านยืนยันใน `src/server/services/ai` ห้าม import `src/integrations/ai` และ `src/integrations` import ได้แค่ `src/lib` (§4.10) จึงต้องมีที่วางข้อมูลกลางที่ไม่มี I/O

## การตัดสินใจ

> prompt เก็บในโค้ดแยกต่อ purpose พร้อมเลขรุ่น `<purpose>@<n>` · ผลประเมินเก็บเป็นไฟล์ใน `docs/reports/ai-eval/` · gate เป็นรายการในโค้ดที่บอกชุด agent purpose prompt รุ่นโมเดล และชั้น (`SYNTHETIC` `REAL`) ที่ผ่าน · รุ่น prompt ปัจจุบัน gate ตารางราคา และรุ่นโมเดลต่อ agent อยู่ใน `src/lib/ai-config.ts` ที่ไม่มี I/O ให้ทั้งด่านยืนยันและ adapter import ได้ · ระยะ 1 ยังไม่สร้างตาราง `PromptVersion` `AiEvalRun` ของ §6.5

## ผลที่ตามมา

- `src/lib/ai-config.ts` เก็บรุ่น prompt ปัจจุบันต่อ purpose รุ่นโมเดลต่อ agent ตารางราคาพร้อมวันที่ตรวจ และรายการ gate (agent purpose promptVersion model ชั้น รายงาน) · ข้อความ prompt อยู่ใน `src/integrations/ai` และมีเทสต์ว่าเลขรุ่นตรงกัน
- S13-13 และ S13-14 บันทึก gate ชั้น `SYNTHETIC` · S13-16 บันทึกชั้น `REAL` · production ใช้ได้เฉพาะ `REAL`
- ผลประเมินอยู่ใน `docs/reports/ai-eval/` ตรวจย้อนได้จาก git
- ถ้าภายหลังให้ลูกค้าแก้ prompt เองหรือมี prompt มาก ค่อยสร้างตารางของ §6.5
