# ADR-147: เครื่องมือของ Insight ตรวจ scope ในตัวเครื่องมือ

- สถานะ: ยอมรับ (ร่าง P1-04 · ผู้ใช้อนุมัติตามที่แนะนำใน P1-06 เมื่อ 2026-10-12)
- วันที่: 2026-10-11
- ที่มา: docs/sub-specs/S13.md หัวข้อ "กฎ" (BR-AI-21 · เครื่องมือของ Insight) และ INV-AI-04 · ข้อ P1-04

## บริบท

- BR-AI-07 ให้ Insight เรียกได้เฉพาะฟังก์ชันที่เขียนไว้ภายใต้สิทธิ์ของผู้ถาม
- บริการอ่านเดิมบางตัวไม่ตรวจสิทธิ์เพราะหน้าจอตรวจ role ที่หน้าแทน: `listPurchaseOrders` คืน PO ทั้งองค์กร และ `searchSuppliers` คืนอีเมล โทรศัพท์ ที่อยู่ และเลขผู้เสียภาษี · ถ้าห่อตรง ๆ ผู้ขอทั่วไปจะถาม Insight แล้วได้ข้อมูลเกินสิทธิ์
- `po.view` ให้ทุก member ด้วย scope OWN และ ASSIGNED · `supplier.view` ให้ทุก member แบบ BASIC_FIELDS_ONLY

## การตัดสินใจ

> เครื่องมือของ Insight Agent ตรวจสิทธิ์และ scope ของผู้ถามในตัวเครื่องมือ · ห่อบริการอ่านเดิมเฉพาะตัวที่ตรวจ scope เองแล้ว ส่วน PO และผู้ขายใช้ query ใหม่ของ S13 ที่กรอง scope · ไม่มีเครื่องมือเขียน · ผลเครื่องมือมีเฉพาะฟิลด์ที่จำเป็น ไม่มีข้อมูลที่ถูก mask และข้อมูลติดต่อ

## ผลที่ตามมา

- ทุกเครื่องมือเรียก `authorize` ของผู้ถามเอง · ห่อบริการเดิมเฉพาะตัวที่ตรวจ scope แล้ว (เช่น `searchForMember` `boardView` `budgetDashboard`)
- query ใหม่ใน `src/server/services/ai/tools/`: `listPurchaseOrdersForAsker` กรองตาม scope ของ `po.view` (ความหมายเดียวกับ `getPoAccess`) · `findSuppliersForAsker` ใช้ `supplierAccess` และไม่คืนข้อมูลติดต่อหรือเลขของบุคคลธรรมดา
- เทสต์สิทธิ์วนผู้ใช้ seed ทุกบทบาทรวมผู้ขอทั่วไปที่ถาม PO ของผู้อื่นและข้อมูลผู้ขาย (INV-AI-04)
- เครื่องมือของใบแจ้งหนี้และรอบจ่ายอยู่นอกระยะ 1
