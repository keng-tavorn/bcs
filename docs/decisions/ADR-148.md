# ADR-148: ค่าที่ AI เติมเข้าเอกสารผ่านคำสั่งเดิมพร้อม aiAssist

- สถานะ: เสนอ (ร่าง P1-04 · รอผู้ใช้อนุมัติใน P1-06)
- วันที่: 2026-10-11
- ที่มา: docs/sub-specs/S13.md หัวข้อ "กฎ" (BR-AI-17) และ "interface กับขั้นอื่น" · ข้อ P1-04

## บริบท

- BR-AI-01 ห้าม AI เรียกคำสั่งที่เปลี่ยนเงินหรือการอนุมัติ · BR-AI-02 ให้ผลของ AI เป็นร่างที่คนยืนยัน
- ค่าที่ AI อ่านต้องเข้าเอกสารหลายชนิด (คำขอ ตรวจรับ DOA ใบแจ้งหนี้ของ S8 ร่างจากแชทของ S17) ที่หลายสายแก้พร้อมกัน
- ถ้าแต่ละเอกสารมีกลไกยืนยันของตัวเอง จะได้หลายรหัสปฏิเสธ และ AgentAction ไม่รู้ว่าคนแก้อะไร (BR-AI-04)

## การตัดสินใจ

> ค่าที่ AI เติมเข้าเอกสารผ่านคำสั่งเดิมของเอกสารนั้นที่รับ `aiAssist` ในธุรกรรมเดียวกันโดยคน · ด่าน `AI_REVIEW_PENDING` อยู่ใน `src/server/services/ai/assist-contract.ts` (P1-07 วางสัญญาและตัวว่าง S13 เติมตัวจริง) ที่ไม่ import adapter AI · AI ไม่มีคำสั่งเขียนเอกสารธุรกิจ

## ผลที่ตามมา

- คำสั่งเดิมรับ `aiAssist = { agentActionId, confirmedPaths }` แบบไม่บังคับ ผู้กระทำเป็นคนในธุรกรรมเดียวกัน · ปิด AI แล้วคำสั่งทำงานเหมือนเดิม
- P1-07 วาง `AiAssistInput` และตัวว่างของ `assertNoPendingAiReview` กับ `applyAiAssist` ใน `src/server/services/ai/assist-contract.ts` พร้อมรหัส `AI_REVIEW_PENDING` ใน §14.2 ให้ S8 เรียกได้ก่อน · S13-03 เปลี่ยนตัวว่างเป็นของจริง แล้วส่งเข้า main เร็ว
- รหัสปฏิเสธเดียว `AI_REVIEW_PENDING` (409) ทุกเอกสาร · ใบแจ้งหนี้ของ S8 ใช้ `fieldSources` แสดงแหล่งที่มาเท่านั้น
- ช่องที่คนแก้หรือลบนับว่ายืนยันแล้ว เอกสารจึงไม่ติดค้างเพราะค่าของ AI
- service ของเอกสาร import ได้เฉพาะ `assist-contract.ts` ไม่ import adapter หรือ agent (INV-AI-05)
