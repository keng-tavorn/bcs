# ADR-161: rich menu ตามบทบาทเลือกด้วย pure function

- สถานะ: เสนอ (ร่าง P1-04 · รอผู้ใช้อนุมัติใน P1-06)
- วันที่: 2026-10-11
- ที่มา: docs/sub-specs/S17.md หัวข้อ "กฎ" (BR-LINE-16 BR-LINE-17) และ golden `line-rich-menu` · ข้อ P1-04

## บริบท

- FR-LINE-303 ให้ rich menu เปลี่ยนตามบทบาท และ §8.12 ให้สลับผ่าน job `line-rich-menu` เดิม · ตอนนี้มีแค่สองชุด (ยังไม่ผูก และผูกแล้ว 4 ปุ่มตายตัวตาม FR-LINE-004 AC1)
- "ผู้อนุมัติ" ในระบบมีหลายทาง: ตำแหน่งที่ DOA ฉบับที่มีผลอ้าง (รวมกรรมการในขั้น PARALLEL) ตัวบุคคลที่ DOA ระบุแบบ `MEMBER` ผู้รักษาการ และผู้ตรวจของ workflow ของ S6 (`reviewer` `fallback`)
- ถ้าเมนูขึ้นกับจำนวนงานค้าง เมนูจะสลับไปมาบ่อยและเรียก LINE API มาก

## การตัดสินใจ

> rich menu ตามบทบาทเลือกด้วย pure function ใน `src/core/line-menu` จาก role และธงผู้อนุมัติ (ตำแหน่งหรือตัวบุคคลที่ DOA ฉบับที่มีผลอ้างรวมกรรมการ รักษาการที่ ACTIVE ผู้ตรวจหรือผู้ตรวจสำรองของ workflow ฉบับที่มีผล) ไม่ใช้จำนวนงานค้าง (เมนูไม่กระพริบ) · สร้างทุกชุดล่วงหน้า (UNLINKED + LINKED 8 ชุด) ด้วย `pnpm line:richmenu` เก็บใน `LineRichMenuVariant` · job `line-rich-menu` เดิมรับ event ของ role ตำแหน่ง รักษาการ DOA และ workflow เพิ่ม

## ผลที่ตามมา

- ธงคำนวณใน service ของ S17 โดยอ่านตารางของ S6 แบบอ่านอย่างเดียว ไม่ต้องรอฟังก์ชันใหม่จาก S6
- เมนูไม่ใช่สิทธิ์: ทุกหน้าที่ปุ่มเปิดตรวจสิทธิ์เอง (BR-AUTH-05) · ผู้ที่ได้ปุ่มงานรออนุมัติแต่ยังไม่มีงานเห็นหน้าว่าง
- ต้องแก้ FR-LINE-004 AC1 และ §9.5 พร้อมเทสต์ (ผู้ใช้อนุมัติใน P1-06)
- เพิ่ม event ที่ job ฟัง: role ตำแหน่ง รักษาการ `doa_version.*` และ `workflow_version.*` · ทุกครั้งอ่านสถานะล่าสุด ไม่เชื่อข้อมูลใน event
