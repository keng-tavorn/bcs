# ADR-162: ขอผ่านแชท LINE ร่างใน LIFF ทางเดียว และ AI เป็นส่วนเสริม

- สถานะ: เสนอ (ร่าง P1-04 · รอผู้ใช้อนุมัติใน P1-06)
- วันที่: 2026-10-11
- ที่มา: docs/sub-specs/S17.md หัวข้อ "State machine" และ "กฎ" (BR-LINE-10 ถึง BR-LINE-15) · คำตัดสินของ agent หลักเรื่องขอผ่านแชท (P1-04 รอบตรวจไขว้) · ข้อ P1-04

## บริบท

- FR-LINE-301 ให้ผู้ขอส่งข้อความหรือรูปในแชท แล้วยืนยันใน LIFF ก่อนส่ง (§8.12) และต้องทำงานได้เมื่อปิด AI (EG-1 NG-5)
- `LineWebhookEvent` เดิมไม่เก็บข้อความที่ผู้ใช้พิมพ์ (ข้อมูลส่วนบุคคล) · reply token ใช้ได้ราว 1 นาที ส่วน push นับโควตาของ OA (BR-LINE-07)
- ร่างแรกของ S13 และ S17 ออกแบบสัญญา AI กลับทิศกัน (ใครเรียก AI ใครสร้างร่าง) จึงต่อกันไม่ได้

## การตัดสินใจ

> ขอผ่านแชท: ข้อความพักใน `LineInboundMessage` (ไม่เก็บใน `LineWebhookEvent`) แล้วเข้า `ChatIntake` · ตอบด้วย reply ที่มีปุ่มเปิด LIFF ไม่มี postback (token หมดอายุ push ครั้งเดียวต่อร่าง) · webhook ไม่เรียก AI · job ของ S17 เรียก `intakeFromMessage` ของ S13 ด้วย ctx ของเจ้าของเมื่อ `isAgentAvailable` แล้วเก็บ id ของ AgentAction · ร่างคำขอเกิดเมื่อเจ้าของเลือกประเภทใน LIFF ผ่าน `request.create_draft` + `aiAssist` ทางเดียว · ไม่ส่งข้อความในแชทเมื่อ AI อ่านเสร็จ · ปิด AI ใช้ฟอร์ม LIFF

## ผลที่ตามมา

- มีทางสร้างร่างจากแชททางเดียว (`chat_intake.draft`) · S13 ไม่มีตัวสร้างร่างจากแชทและไม่ฟัง event ของ S17
- ค่าที่ AI เสนอยืนยันตามกฎของ S13 (BR-AI-16 BR-AI-17) · ยืนยันไม่ครบ `request.submit` ได้ `AI_REVIEW_PENDING`
- job เรียก AI ใน step แยกจากการเก็บ id เพื่อไม่เรียกซ้ำเมื่อ job ลองใหม่ · `ChatIntake.agentActionId` เพิ่มเมื่อ S13 อยู่ใน main แล้ว (S17-08)
- ข้อความแชทเก็บไม่เกิน 7 วันตาม OQ-162 · ไม่ log ข้อความ (NFR-SEC-09)
- โค้ดของ S17 import ได้เฉพาะ API สาธารณะของ S13 ไม่ import `src/integrations/ai` (lint)
