# ADR-163: แอป BCS Go ห่อเว็บจริงด้วย Capacitor 8

- สถานะ: ยอมรับ (ร่าง P1-04 · ผู้ใช้อนุมัติตามที่แนะนำใน P1-06 เมื่อ 2026-10-12)
- วันที่: 2026-10-11
- ที่มา: docs/sub-specs/S17.md หัวข้อ "กฎ" (BR-APP-01 BR-APP-02) และ checklist S17-09 · ข้อ P1-04

## บริบท

- ADR-017 และ ADR-061 ให้ BCS Go เป็น Capacitor ที่ห่อเว็บเดิมโดยไม่มีโค้ดธุรกิจในแอป (NG-3)
- CI เดิมรันเฉพาะ push main และ pull request · workflow ที่กดเองต้องอยู่บน default branch · keystore เป็น secret ที่ผู้ใช้ต้องใส่เอง
- ชั้น demo ใช้ Android ติดตั้งเอง ส่วน iOS อยู่ใน go-live

## การตัดสินใจ

> BCS Go: Capacitor 8 ใน `mobile/bcs-go/` โหลดเว็บจริงด้วย `server.url` ต่อ environment (ไม่ bundle หน้าเว็บ) · `allowNavigation` เฉพาะ origin · JS ของปลั๊กอินอยู่ใน dependency ของเว็บแบบ dynamic import · workflow ของ CI สร้าง APK ของ demo บน main (`workflow_dispatch` และ push ที่แตะ `mobile/**`) ด้วย keystore ของ demo จาก secret · งานของ iOS (App-Bound Domains และ AASA) อยู่ใน go-live · ช่องทาง `APP` ตรวจจาก user agent เพื่อ audit เท่านั้น

## ผลที่ตามมา

- deploy เว็บแล้วแอปได้ของใหม่ทันที ไม่ต้องส่งแอปใหม่ · แอปคือเว็บจึงใช้กฎสิทธิ์ของเว็บทุกข้อ
- ในสายตรวจได้แค่ `npx cap sync android` และไฟล์ workflow · APK บน Actions สร้างจริงหลังงานเข้า main และตรวจบนเครื่องจริงใน P1-13 (`[คน]`)
- เอกสาร Capacitor ระบุว่า `server.url` มีไว้สำหรับ live reload และแอปที่ห่อเว็บเสี่ยงถูกปฏิเสธตามแนวทางข้อ 4.2 ของ App Store · ไม่กระทบ demo ที่ติดตั้งเอง แต่ต้องตรวจใหม่ใน S17-20 ก่อนส่ง store (ทางเลือก: bundle shell ขั้นต่ำ)
- ช่องทาง `APP` ใช้ทำป้ายไทม์ไลน์และ KPI ไม่ใช้ตัดสินสิทธิ์ (user agent ปลอมได้)
