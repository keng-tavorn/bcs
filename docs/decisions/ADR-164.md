# ADR-164: ตรวจรับออฟไลน์ด้วยคิวในเครื่องและ gr.post เดิม

- สถานะ: ยอมรับ (ร่าง P1-04 · ผู้ใช้อนุมัติตามที่แนะนำใน P1-06 เมื่อ 2026-10-12)
- วันที่: 2026-10-11
- ที่มา: docs/sub-specs/S17.md หัวข้อ "State machine" (คิวตรวจรับออฟไลน์) และ "กฎ" (BR-APP-03 ถึง BR-APP-14) · ข้อ P1-04

## บริบท

- FR-PLT-301 ให้ผู้ตรวจรับบันทึกตอนไม่มีสัญญาณแล้วส่งครบไม่ซ้ำเมื่อกลับมาออนไลน์ ผ่าน command เดิมพร้อม idempotencyKey ต่อรายการ (§8.12)
- `runCommand` replay ผลจาก `CommandLog` ก่อนรันคำสั่งเมื่อ key และ input ตรงกัน และตอบ `IDEMPOTENCY_CONFLICT` เมื่อ key เดิมแต่ input ที่ parse แล้วต่างกัน (เช่นหลัง deploy ที่เพิ่มค่าเริ่มต้นใน schema)
- รูปของ `gr.post` ต้องอัปโหลดและ complete โดยผู้ส่งก่อน · ticket อัปโหลดมีอายุ 15 นาที และ complete ใช้ key ต่อ ticket จึงเรียกซ้ำได้ผลเดิม
- shell ที่ service worker เก็บไว้อาจมาจาก build เก่า จึงเรียก server action ที่เปลี่ยนชื่อหลัง deploy ไม่ได้

## การตัดสินใจ

> ตรวจรับออฟไลน์: หน้า shell `/go/receive` ที่ service worker เดิม precache · ข้อมูลใน IndexedDB ผ่าน `idb-keyval` · ตรรกะคิวเป็น pure function ใน `src/core/offline-queue` · อัปโหลดรูปและส่ง `gr.post` เดิมผ่าน route handler URL คงที่ พร้อม idempotencyKey ต่อรายการและฟิลด์ `offline` (ผู้บันทึก เวลา version ที่เห็น) · ทีละรายการต่อ PO และต่อ version · ผลยังไม่รู้ส่งซ้ำด้วย key เดิมเสมอ · `IDEMPOTENCY_CONFLICT` ถามผลที่บันทึกของ key ก่อน ไม่ส่งด้วย key ใหม่

## ผลที่ตามมา

- ผลเงินเท่าตรวจรับออนไลน์ทุกประการ (golden `offline-receiving` เทียบ GC-GR-05) · `receivedAt` ไม่เกินเวลาที่ถึงระบบ และงบหรือกำหนดเวลานับตาม `postedAt` (OQ-170)
- รายการ 1 รายการได้ GR ไม่เกิน 1 ใบ: key เดิมตลอดชีวิตของรายการ · รายการที่ผลยังไม่รู้ไม่หมดอายุ · ออกจากระบบเตือน "อาจบันทึกแล้ว"
- เพิ่ม route `GET /api/go/receiving/gr?key=` อ่านผลที่บันทึกของ key เฉพาะของผู้ส่งเอง
- key และเวลาที่บันทึกสร้างในหน้าแล้วส่งเข้า core เป็น input เพราะ core ห้ามอ่านนาฬิกาเอง (§17.3)
- PWA บน iOS อาจล้าง IndexedDB จึงขอ `navigator.storage.persist()` และเตือนเมื่อไม่ได้
