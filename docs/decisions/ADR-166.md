# ADR-166: biometric ในแอปคือ passkey ที่ตรวจในคำสั่งของ BCS

- สถานะ: เสนอ (ร่าง P1-04 · รอผู้ใช้อนุมัติใน P1-06)
- วันที่: 2026-10-11
- ที่มา: docs/sub-specs/S17.md หัวข้อ "Entity และ migration" (`MemberPasskey` `PasskeyChallenge`) และ "กฎ" (BR-AUTH-09 ถึง BR-AUTH-11) · ข้อ P1-04

## บริบท

- FR-PLT-301 และ NEW-53 ให้ตัดสินด้วย biometric ผ่าน passkey เป็นหลักฐาน step-up อีกทาง (FR-AUTH-005 AC2) โดยไม่เปลี่ยนเกณฑ์อำนาจ
- §5.5 ระบุ `@better-auth/passkey` แต่ต้องยืนยันก่อนติดตั้ง (§17.4) · ปลั๊กอินนี้เปิด endpoint ลงทะเบียนและเข้าระบบใต้ `/api/auth/*` ที่ session ใดก็เรียกได้ จึงข้ามด่านพิสูจน์ตัวตนสดแบบตั้ง PIN ได้ถ้าไม่กั้น · ระยะ 1 ไม่ใช้ passkey เข้าระบบ (OQ-168)
- คำสั่งเดิมของ PIN (`self.set_pin`) ผ่าน `runCommand` และตรวจหลักฐานจาก `proveIdentityForPin` · `recordAuthEvent` เป็นทางของเหตุการณ์เข้าระบบเท่านั้น
- WebAuthn ใน WebView ของ Android ต้องใช้ androidx.webkit และ Digital Asset Links ซึ่งทดสอบได้เมื่อมี APK และโดเมน HTTPS เท่านั้น

## การตัดสินใจ

> biometric = passkey ใน WebView ของแอป (WebAuthn ผ่าน androidx.webkit กับ Digital Asset Links บน Android) ไม่ใช้ปลั๊กอิน passkey ของ Capacitor · ลงทะเบียนและตรวจ assertion ในคำสั่งของ BCS ผ่าน `runCommand` (challenge ใช้ครั้งเดียวใน `PasskeyChallenge`) ไม่เปิด endpoint passkey ของ Better Auth · หลักฐาน step-up ชนิด `PASSKEY` UV required · เครื่องที่ไม่รองรับใช้ PIN · ลองบน Android จริงหลังส่งเข้า main ถ้า WebView ใช้ไม่ได้ใช้ PWA ใน Chrome ระหว่างรอและหยุดถามก่อนเพิ่มปลั๊กอิน

## ผลที่ตามมา

- ค่าที่แนะนำใน OQ-167 คือ `@simplewebauthn/server` แทน `@better-auth/passkey` และแก้แถว §5.5 · ถ้าผู้ใช้เลือกปลั๊กอินของ Better Auth ต้องกั้น endpoint ลงทะเบียนด้วยหลักฐานเดียวกันพร้อมเทสต์ปฏิเสธ
- passkey ผูกกับ member แบบ PIN (`MemberPasskey`) · `IDENTITY_RESET` และการปิดใช้งาน member เพิกถอนในธุรกรรมเดียวกัน
- คำสั่งตัดสินทุกตัวรับ PIN และ PASSKEY ผ่าน `DECISION_STEP_UP_METHODS` ของ P1-07 ที่เปลี่ยนที่เดียวใน S17-15 · ข้อ passkey อยู่ท้ายขั้นจึงข้ามได้ระหว่างรอ OQ-167
- ในสายทดสอบด้วย virtual authenticator ของ Chromium · การลองบน Android จริงอยู่ใน runbook ของ S17-17 และ P1-11 P1-13 · ทางสำรองคือปลั๊กอิน Credential Manager ซึ่งเป็น dependency ใหม่ต้องหยุดถามก่อน
