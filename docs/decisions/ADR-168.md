# ADR-168: โครงแอป BCS Go — ติดตั้งแยกใน `mobile/bcs-go` เครื่องหมาย `BCSGo/<เวอร์ชัน>` ใน user agent และช่องทาง `APP` ที่ `ctxFromSession`

- สถานะ: ยอมรับ (agent ตัดสินใน S17-09 ตาม ADR-163 และ BR-APP-02 · ทางที่ปลอดภัยและดูแลง่าย · ผู้ใช้ทบทวนได้ใน P1-10)
- วันที่: 2026-10-16
- ที่มา: spec §16.18 ข้อ S17-09 · BR-APP-01 BR-APP-02 · ADR-163 ADR-166

## บริบท

- ADR-163 ให้แอปเป็น Capacitor 8 ที่เปิดเว็บด้วย `server.url` และตรวจช่องทาง `APP` จาก user agent แต่ไม่ได้กำหนดเครื่องหมาย จุดที่แปลงเป็นช่องทาง หรือวิธีติดตั้งแพ็กเกจของแอป
- หน้าเว็บทุกหน้าสร้าง ctx ด้วย `ctxFromSession(state, 'WEB', now)` (143 จุด) และช่องทาง `PWA` ไม่เคยถูกตั้งจากคำขอจริง
- repo เป็นแพ็กเกจเดียว (`pnpm-workspace.yaml`) · CI ของเว็บไม่ควรต้องติดตั้ง Capacitor CLI และ Android
- ตัดสิน policy ใน policy-decide.ts รับเฉพาะ `WEB` และ `LIFF` จึงตัดสินในแอปไม่ได้ถ้าไม่แก้ (BR-APP-02)

## การตัดสินใจ

> แอปอยู่ใน `mobile/bcs-go` เป็นแพ็กเกจแยกที่มี lockfile ของตัวเอง ติดตั้งด้วย `pnpm install --ignore-workspace` (เว็บไม่ติดตั้ง Capacitor CLI) และไม่อยู่ใน TypeScript project ของเว็บ · `capacitor.config.ts` อ่าน `BCS_GO_SERVER_URL` (https เท่านั้น ยกเว้น http ของเครื่องผู้พัฒนาผ่าน emulator) ตั้ง `allowNavigation` เป็น host นั้น และ `appendUserAgent` เป็น `BCSGo/<semver>` · เว็บอ่านเครื่องหมายเป็น token ของตัวเองใน user agent (`isAppUserAgent` ของ `src/lib/app-client.ts`) ตอน `resolveSession` แล้ว `ctxFromSession` เปลี่ยน `WEB` เป็น `APP` ที่จุดเดียว (หน้า LIFF คง `LIFF`) · เทสต์ถาวร `tests/unit/app-channel.test.ts` อ่านทุกไฟล์ใน `src` และล้มเมื่อรายการ ชนิด หรือการเทียบช่องทางใดรับ `WEB` แต่ไม่รับ `APP` (ข้อยกเว้นต้องเขียนเหตุผล) · `StepUpChannel` รับ `APP` ตั้งแต่ข้อนี้ (S17-15 เพิ่ม passkey) · KPI G-5 คงนิยามของ §11 (แชท LINE และ LIFF) ส่วนแผงการควบคุมของหน้า insights มีแท่ง `APP` ของตัวเอง · Android ไม่สำรองหรือย้ายข้อมูลของแอป (`allowBackup=false` และ `data_extraction_rules.xml` ตัดทุกโดเมน) เพราะ WebView เก็บ cookie ของ session และคิวตรวจรับ (BR-APP-03) · app id ของ demo คือ `th.bcs.go` (id บน store ตัดสินใน S17-20 · OQ-166) · `/.well-known/assetlinks.json` ตอบจาก `BCS_GO_ANDROID_PACKAGE` และ `BCS_GO_ANDROID_CERT_SHA256` (ไม่ครบ = 404)

## ผลที่ตามมา

- ช่องทาง `APP` เป็นข้อมูลที่ผู้ส่งบอกเอง (user agent ปลอมได้) จึงใช้ทำป้ายไทม์ไลน์ audit และ KPI เท่านั้น ไม่มีจุดใดให้สิทธิ์เพิ่มเพราะเป็น `APP` (BR-APP-02)
- หน้าเว็บเดิมทั้ง 143 จุดไม่ต้องแก้ · ป้าย `PWA` เปลี่ยนเป็น "BCS Go บนเว็บ (PWA)" และ `APP` เป็น "แอป BCS Go"
- workflow `bcs-go-apk.yml` ติดตั้งและตรวจชนิดเฉพาะใน `mobile/bcs-go` · โปรเจกต์ Android ที่ `cap add android` สร้างอยู่ใน git (ยกเว้นไฟล์ที่ `cap sync` สร้างใหม่) และอยู่นอก lint ของเว็บ
- เพิ่มปลั๊กอิน (push S17-10 กล้องและ ML Kit S17-13 S17-14) ต้องเพิ่มทั้งใน `mobile/bcs-go/package.json` (ส่วน native) และ dependency ของเว็บ (JS แบบ dynamic import) ด้วยเวอร์ชันเดียวกัน
