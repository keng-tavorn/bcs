# ADR-184: หน้าพอร์ทัลใช้ชุดคอมโพเนนต์เบาแบบ LIFF มือถือก่อน

- สถานะ: ยอมรับ (ร่าง ADR-075 · ผู้ใช้อนุมัติตามที่แนะนำเมื่อ 2026-11-01)
- วันที่: 2026-11-01
- ที่มา: docs/sub-specs/S7.md หัวข้อ "หน้าจอ" และ "สถาปัตยกรรม" · คำสั่งในบรีฟระยะ 2 ให้ตัดสินชุดคอมโพเนนต์ของพอร์ทัลและความสัมพันธ์กับ ADR-052 · ADR-075

## บริบท

- "เสร็จเมื่อ" ของ S7 คือ "ผู้ขายสมัครเองบนมือถือได้" (§16.8) · ผู้ขายเปิดลิงก์จากอีเมลบนมือถือผ่าน 4G โดยไม่มี cache และไม่ใช่พนักงานที่ฝึกใช้ระบบ
- Workspace ใช้ shadcn/ui ชุดเต็มกับ `cmdk` `recharts` `react-dropzone` `input-otp` `react-day-picker` และ `tailwind-merge` (§5.5 §9.10) · หน้า LIFF ถูกห้ามใช้ชุดนั้นและมีงบ JavaScript 200 KB gzip (ADR-052 · §4.10)
- §9.9 ห้ามปนภาษา ห้ามฟอร์มยาวหน้าเดียวเกิน 8 ช่อง และบังคับตัวอักษร 16 px บนมือถือ · พอร์ทัลต้องมีภาษาอังกฤษสำหรับผู้ติดต่อต่างชาติโดยไม่ต้องรอฟอร์มสองภาษาแบบตั้งค่าได้ของ S10 (FR-INT-201)

## การตัดสินใจ

> หน้าพอร์ทัล `/portal/*` ใช้ชุดคอมโพเนนต์เบาแบบ LIFF ใน `src/ui/portal` (ขยายจาก ADR-052): ไม่ใช้ `cmdk` `recharts` `react-dropzone` `input-otp` `react-day-picker` `@xyflow/react` และคอมโพเนนต์ Workspace ที่พา `tailwind-merge` · งบ JavaScript เริ่มต้น ≤ 200 KB gzip ชั่งทุกหน้าใน e2e · ออกแบบมือถือก่อน (375 px · ตัวอักษร 16 px · ปุ่มหลักติดล่างจอ) · ข้อความไทยและอังกฤษสลับตาม `SupplierContact.locale` · S10 S11 เพิ่มหน้าใต้ `/portal/*` ด้วยชุดนี้

- ชุด `src/ui/portal`: ปุ่ม ช่องกรอก ช่องไฟล์ (`<input type="file" accept="application/pdf,image/*">`) ช่องรหัส OTP (`inputmode="numeric" autocomplete="one-time-code"`) ขั้นตอน รายการ ป้ายสถานะ กล่องยืนยัน แถบปุ่มติดล่าง · ใช้ token ของ §9.9 §9.10 ไม่มี hex สี · ตัวต่อ class แบบเบาเหมือน LIFF · นำของ `src/ui/liff` มาใช้ซ้ำเมื่อ export ได้
- ฟอร์มสมัคร 6 ขั้น (บริษัท · ภาษี · ผู้ติดต่อ · บัญชีธนาคาร · เอกสาร · ตรวจและส่ง) ขั้นละไม่เกิน 8 ช่อง บันทึกได้ทีละขั้น
- ข้อความใน `messages/src/{th,en}/portal.json` ส่งเฉพาะ namespace ที่พอร์ทัลใช้ (แบบ ADR-052 ข้อ 2) · ปุ่มสลับภาษาเก็บลง `SupplierContact.locale`
- ทุกหน้าผ่านรายการ "สิ่งที่ห้ามใช้" §9.9 screenshot 375 และ 1440 px และ axe (S7-18)

## ผลที่ตามมา

- lint boundary: `src/app/portal/**` และ `src/ui/portal/**` ห้าม import ไลบรารีและคอมโพเนนต์ตามรายการข้างบน (ขยายแถว `src/app/liff/**` ของ §4.10)
- e2e ของพอร์ทัลชั่งงบ JS ทุกหน้าแบบเข้มเหมือน LIFF · เพิ่มคอมโพเนนต์ต้องดูผลการชั่ง
- Workspace ฝั่งภายใน (หน้าใบสมัคร เชิญ แท็บผู้ขาย) ใช้ shadcn/ui ชุดเต็มตาม §9.10 ตามปกติ · ฟอร์ม 6 ขั้นมีสองหน้าตา (พอร์ทัลเบา · Workspace เต็ม) แต่เรียก service เดียวกัน
- S10 (ยื่นข้อเสนอ RFx) และ S11 (ตอบแบบประเมิน) ได้ชุดคอมโพเนนต์พร้อมใช้และกติกาเดียวกัน
- ถ้าผู้ใช้เลือกใช้ shadcn/ui ชุดเต็มในพอร์ทัล: ง่ายกว่าตอนเขียน แต่หน้าสมัครบนมือถือจะโหลดช้ากว่าและต้องยกเว้นงบ 200 KB
