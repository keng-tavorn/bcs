# ADR-185: engine เอกสารผู้ขาย: วันหมดอายุ การยืนยัน และการสแกนไฟล์

- สถานะ: ยอมรับ (ร่าง ADR-075 · ผู้ใช้อนุมัติตามที่แนะนำเมื่อ 2026-11-01)
- วันที่: 2026-11-01
- ที่มา: docs/sub-specs/S7.md หัวข้อ "กฎ" (BR-SDOC-01 ถึง BR-SDOC-07 BR-PORTAL-07) และ "ร่าง golden case" (suite supplier-documents) · §8.12 แถว FR-SUP-102 · ADR-075

## บริบท

- §6.5 จอง `SupplierDocument` (ประเภท เลขที่ ผู้ออก ขอบเขต วันออก วันหมดอายุ ผู้ยืนยัน สถานะ) และ `SupplierDocumentType` (อายุที่องค์กรตั้งต่อประเภท วันเตือน) · §8.12 บังคับว่าใบรับรองต้องมีคนยืนยันหนึ่งครั้ง และระบบขอเอกสารใหม่ก่อนหมดอายุ
- spec ไม่ได้ระบุว่า "อายุ 180 วัน" นับรวมวันหมดอายุไหม และวันเตือนนับอย่างไรเมื่อสั้นกว่าอายุ · เอกสารไทย (หนังสือรับรอง) มักยอมรับเมื่อออกไม่เกิน 6 เดือน ส่วนใบรับรอง ISO มีวันหมดอายุพิมพ์บนเอกสารและใช้ได้ถึงวันนั้น
- §9.8 บังคับให้ไฟล์ที่ผู้ขายอัปโหลดผ่านการสแกนไวรัส (`scanStatus = CLEAN`) ก่อนผู้ใช้ภายในดาวน์โหลด · `FileObject.scanStatus` มีค่า `PENDING` `CLEAN` `INFECTED` อยู่แล้ว แต่ยังไม่มี adapter และบริการสแกนใน stack (§5.5)
- S11 ต้องใช้เอกสารตอบคำถาม "ตอบด้วยหลักฐาน" เมื่อใบยังไม่หมดอายุและขอบเขตครอบคลุม (§8.12 FR-RSK-201) · S10 คัดคุณสมบัติผู้ยื่น

## การตัดสินใจ

> เอกสารผู้ขาย: engine pure `src/core/supplier-docs` คำนวณ `expiresOn = issuedOn + (validityDays − 1)` (เอกสารใช้ได้ถึงวันหมดอายุรวมวันนั้น) และ `remindOn = max(expiresOn − reminderDaysBefore, issuedOn)` ตามวันปฏิทิน Asia/Bangkok · ประเภทไม่มีอายุใช้วันบนเอกสาร · ใบรับรองต้องมีคนยืนยันหนึ่งครั้ง ฉบับใหม่ supersede ฉบับเดิม · ไฟล์จากผู้ขายต้อง `scanStatus = CLEAN` ก่อนผู้ใช้ภายในเปิด ผ่าน adapter `src/integrations/scanner` โหมด `stub`/`live` (OQ-191) · S7 ให้ `supplierDocumentStatus` แก่ S10 S11 และไม่บล็อก PO เอง

- สถานะ: `PENDING → VERIFIED → EXPIRED` และ `REJECTED` `SUPERSEDED` (เพิ่มจาก §6.5) · `today > expiresOn` ตาม Asia/Bangkok → EXPIRED · `today ≥ remindOn` → เตือนครั้งเดียวต่อฉบับ (golden GC-SUP-34 ถึง 47 และ 52 ถึง 53)
- supersede ต่อประเภท **และขอบเขต**: ประเภท `singleInstance = true` (หนังสือรับรอง ภ.พ.20 สมุดบัญชี บัตร หนังสือจดทะเบียนต่างประเทศ) มี VERIFIED ได้ฉบับเดียวต่อผู้ขาย ฉบับใหม่แทนฉบับเดิมโดยไม่สน `scope` · ประเภท `singleInstance = false` (ISO_CERT) มีหลายฉบับคนละ `scope` พร้อมกันได้ (ISO 9001 และ ISO 14001) ฉบับใหม่แทนเฉพาะ `scope` เดียวกัน (เทียบหลัง trim และตัวพิมพ์เล็ก) · partial unique บน `(org, supplierId, documentTypeCode, scopeKey) WHERE status = 'VERIFIED'` · `supplierDocumentStatus` คืนหลายแถวต่อประเภทเมื่อ `singleInstance = false` ให้ S11 จับคู่ "ขอบเขตครอบคลุมงานที่จ้าง" ของ §8.12 FR-RSK-201 (ตรวจไขว้กับ S11)
- ประเภทมี `validityDays` → วันบนเอกสารเก็บเป็น `statedExpiresOn` อย่างเดียว · ประเภทไม่มีอายุต้องกรอก `expiresOn` (`EXPIRY_REQUIRED`)
- job `supplier-document-expiry` รายวัน 07:00 เตือนและตั้ง EXPIRED · ผู้ขายอัปโหลดฉบับใหม่ได้ตั้งแต่ได้รับเตือน ฉบับเดิมใช้ได้จนหมดอายุหรือถูก supersede
- สแกน: โหมด `stub` ใช้ denylist sha256 และสตริงทดสอบ EICAR บนเครื่องและเทสต์ · โหมด `live` กับ ClamAV (หรือบริการที่ลูกค้าเลือก) เป็นข้อ `[go-live]` S7-22 หลังผู้ใช้ยืนยัน dependency · ผู้ใช้ภายในเปิดได้เมื่อ CLEAN เท่านั้น (`FILE_NOT_SCANNED` `FILE_INFECTED`)

- ขอบเขต (`scope`) เทียบด้วย `normalizeScope(s)` ที่นิยามครั้งเดียวใน `src/core/supplier-docs` (NFC · trim · ตัวพิมพ์เล็ก · ยุบช่องว่างซ้ำเป็นช่องเดียว · null → `''`) และ `SupplierDocument.scopeKey = normalizeScope(scope)` ไม่ใช่ค่าดิบ · export ให้ S10 S11 ใช้จับคู่ `workScopes` (GC-SUP-52 GC-SUP-54)
- job `file-scan` เป็นงานกลางของ `FileObject`: ทริกเกอร์ทุกไฟล์ `scanStatus = PENDING` ไม่สน `FileLink.kind` ตั้ง `scanStatus` และปล่อย event กลาง `file.scanned` (`fileId` `result` `linkKinds[]`) เท่านั้น · ผลต่อ `SupplierDocument` (`supplier_document.scanned` · REJECTED เมื่อ INFECTED) เขียนโดย listener `supplier-document-scanned` ของ S7 ที่ฟังเฉพาะ `SUPPLIER_DOC` · S10 S11 ฟัง `file.scanned` ของ kind ตนแบบเดียวกัน
- สถานะรวมมี 2 รูปที่คืน shape เดียวกัน: `supplierDocumentStatus(ctx, supplierId)` (ตรวจ `supplier.document.view` หรือ actor SUPPLIER ของตน) และ `supplierDocumentStatusInTx(tx, organizationId, supplierId, now)` (ระดับธุรกรรม ไม่ตรวจ capability ให้ service และ job ของ S10 S11) · ทั้งสองคำนวณสถานะจากวันที่ ณ `now` ตาม BR-SDOC-02 ไม่ใช่คอลัมน์ `status` อย่างเดียว
- ผู้ตรวจความเสี่ยงของ S11 (ผู้ถือ slot · ไม่ใช่ role `REVIEWER_*`) ดาวน์โหลดเอกสารที่ผูกคำตอบใน domain ของตนผ่าน `supplierDocument.requestDownload` ด้วย `grantedBy: 'RISK_REVIEW'` (BR-SDOC-05)

## ผลที่ตามมา

- ค่าตั้งต้น 6 ประเภทของ SIMEC (BR-SDOC-01 · OQ-183) อยู่ในชีต `Supplier_Document_Types` · ลูกค้าแก้ที่ `/admin/supplier-document-types` โดยไม่ deploy
- `supplierDocumentStatus(ctx, supplierId)` คืน OK EXPIRING EXPIRED MISSING PENDING ต่อประเภทบังคับ และ `linkedRiskQuestionCodes` ให้ S11 · ด่านก่อน PO เป็นของ S11 (FR-RSK-203 · BR-SUP-04 ชั้น 3) หน้า PO ภายในของ S7 แสดงป้ายอย่างเดียว
- บัตรประชาชน (`sensitive`) ไม่ส่ง AI ไม่แสดงตัวอย่าง และดาวน์โหลดลง `SensitiveAccessLog` (NFR-PRIV-02 NFR-PRIV-03)
- ถ้าผู้ใช้เลือก "ไม่รวมวันหมดอายุ" (ใช้ได้ถึงวันก่อนหน้า): เปลี่ยนสูตรที่เดียวใน core และ golden GC-SUP-34 ถึง 46 ต้องคำนวณใหม่ · ถ้าเลือกไม่สแกนไวรัส: ขัด §9.8 ไม่แนะนำ
