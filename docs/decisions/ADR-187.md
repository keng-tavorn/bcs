# ADR-187: SLA ของใบสมัครด้วย engine §7.8 และสูตร G-7

- สถานะ: ยอมรับ (ร่าง ADR-075 · ผู้ใช้อนุมัติตามที่แนะนำเมื่อ 2026-11-01)
- วันที่: 2026-11-01
- ที่มา: docs/sub-specs/S7.md หัวข้อ "กฎ" (BR-SUP-12 BR-SUP-13) และ "ร่าง golden case" (GC-SUP-26 ถึง GC-SUP-33) · §8.12 แถว FR-SUP-101 · §1.3 G-7 · ADR-075

## บริบท

- §8.12 บังคับว่าผู้ขายที่สมัครค้างได้รับการเตือนพร้อมรายการที่ยังขาด และส่งต่อจัดซื้อเมื่อเกินจำนวนวันทำการที่ตั้งไว้ ด้วย engine SLA (§7.8) และ Inngest เดิม
- G-7 (§1.3) = มัธยฐานวันจากส่งคำเชิญถึงอนุมัติผู้ขาย ลดลง ≥ 50% · §11.4 ให้ sub-spec S7 นิยาม · BR-RPT-03 ของ S6 ใช้ "ตัวกลางล่าง" เป็นค่ากลางของรายงาน workflow แล้ว
- ใบสมัครก่อน SUBMITTED ไม่มีงานอนุมัติ จึงใช้ `approval-task-sla` เดิมไม่ได้ · หลัง SUBMITTED งานอนุมัติใช้ SLA ของ DOA ตามเดิม (BR-SLA-01 ถึง 04)
- จำนวนวันเป็นเรื่องของลูกค้า (OQ-184) ต้องเป็นค่าตั้งไม่ใช่ตัวเลขในโค้ด

## การตัดสินใจ

> SLA ของใบสมัครใช้ engine §7.8 และปฏิทินขององค์กรกับ Inngest `supplier-application-sla` (sleepUntil · cancelOn): เตือนพร้อมรายการที่ขาดเมื่อนิ่ง 3 วันทำการ ส่งต่อจัดซื้อที่ 10 วันทำการนับจากคำเชิญ หมดอายุที่ 30 วันปฏิทิน (ค่าตั้ง `settings.supplier` · OQ-184) · KPI G-7 = ตัวกลางล่าง (BR-RPT-03) ของวันทำการจาก `invitedAt` ถึง `decidedAt` ของใบ APPROVED kind NEW ทศนิยม 1 ตำแหน่ง แยกคอลัมน์กรอกแทน คำนวณด้วยโค้ด

- `applicationSla` ใน core: `remindAt = addBusinessMinutes(lastActivityAt, reminderBusinessDays × 540)` · `escalateAt = addBusinessMinutes(invitedAt, escalateBusinessDays × 540)` · `expiresAt = invitedAt + expireDays วัน` (golden GC-SUP-26 ถึง 29 ด้วยปฏิทินของ suite `workflow-reports`)
- ความเคลื่อนไหว = `supplier_application.updated` `supplier_document.uploaded` `portal_session.signed_in` ของใบนั้น → job ตัวใหม่แทนตัวเดิม (cancelOn event เดียวกัน)
- การเตือนเป็น `SupplierNotice` ที่ระบุฟิลด์และประเภทเอกสารที่ยังขาดพร้อมลิงก์เข้าระบบใหม่ · การส่งต่อแจ้งผู้เชิญและ PROCUREMENT แบบ IMMEDIATE · หมดอายุ → EXPIRED และเชิญซ้ำได้
- `g7BusinessDays` = `businessMinutesBetween ÷ 540` ปัด half-up 1 ตำแหน่ง · `g7Median` = ตัวกลางล่าง (GC-SUP-30 ถึง 33) · ไม่มีใบ → null · ใบ EXISTING REJECTED EXPIRED ไม่นับ

## ผลที่ตามมา

- ไม่มี engine เวลาใหม่ · `src/core/sla` ต้อง export `addBusinessMinutes` `businessMinutesBetween` ให้ core อื่น (มีอยู่แล้วสำหรับ S6) · `lowerMedian` ย้ายเป็น export ถ้ายัง private โดยไม่เปลี่ยนผล GC-RPT-08
- ค่าตั้ง `applicationReminderBusinessDays` `applicationEscalateBusinessDays` `applicationExpireDays` อยู่ใน `OrgSettingsSchema.supplier` และชีต Settings ของ SIMEC · เปลี่ยนไม่ต้อง deploy
- seed ของใบสมัคร APPROVED 3 ใบให้ G-7 = 3.6 วันทำการ (ฉาก 7 ของ demo) · `inputs:check` ตรวจตัวเลขนี้ด้วยตัวคำนวณ Python
- ผู้ขายกรอกได้ทุกวัน (ความเคลื่อนไหวนับทุกวัน) เฉพาะกำหนดเตือนที่นับวันทำการขององค์กร
- ถ้าผู้ใช้เลือกนับ G-7 เป็นวันปฏิทิน: เปลี่ยน `g7BusinessDays` ที่เดียวและ golden GC-SUP-30 ถึง 32 คำนวณใหม่ · baseline ของลูกค้า (P0-09) ต้องวัดด้วยหน่วยเดียวกัน
