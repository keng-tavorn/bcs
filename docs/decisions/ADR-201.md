# ADR-201: RFx เป็นเอกสารแยกของโมดูล SOURCING ที่สร้างจากบรรทัดคำขอที่อนุมัติแล้ว

- สถานะ: ร่าง ADR-075 (2026-11-01) รอผู้ใช้อนุมัติ
- วันที่: 2026-11-01
- ที่มา: docs/sub-specs/S10.md หัวข้อ "ขอบเขต" "Entity และ migration" และ "State machine" · ผู้ใช้สั่งออกแบบระยะ 2 ก่อนจบ A3 และ C (ADR-075)

## บริบท

- §16.8 ให้ S10 ทำ "RFQ เทียบราคา 3 ราย แล้วขยายเป็น RFP และ RFI" (FR-SRC-201) และ §6.5 จองชื่อ `RfxEvent` `RfxInvite` `RfxQuestion` `Bid` `BidLine` `Scorecard` `ScoreCriterion` `AwardDecision` `PreferredSupplier` ไว้แล้ว
- ชั้น 1 มีใบเสนอราคาแบบข้อมูล (`RequestQuotation` · BR-FORM-06) ที่ผู้ขอแนบกับคำขอเอง และกองคำขอ (§7.10) ที่จัดซื้อเลือกผู้ขายทีละบรรทัดด้วย `procurement.assign_supplier` แล้วรอบรวม PR สร้างร่าง PO · ไม่มีที่ให้ผู้ขายหลายรายยื่นราคาแข่งกันในระบบ
- ถ้าทำ RFx เป็นสถานะใหม่ของคำขอ จะต้องแก้ state machine ของ `Request` และ PO ของชั้น 1 ซึ่ง §16.13 ห้ามเปลี่ยนผลเดิม และคำขอหลายใบที่ซื้อของเดียวกันจะแข่งราคารวมกันไม่ได้

## การตัดสินใจ

> RFx เป็นเอกสารแยกของโมดูล `SOURCING`: `RfxEvent` ชนิด RFQ RFP RFI ในตารางเดียว สร้างจากบรรทัดคำขอที่อนุมัติแล้วและยังไม่มีผู้ขายในกอง (หลายคำขอ หมวดเดียว) หรือจากความต้องการที่ยังไม่มีคำขอ · วงจร DRAFT → OPEN → CLOSED → EVALUATING → AWARDED (RFI → CONCLUDED) และ CANCELLED · ปิดรับตามปฏิทินทำการ §7.8 · แก้ไขหลังเปิดเป็นฉบับ (`RfxAmendment`) ที่แจ้งทุกรายและให้ยืนยันซ้ำ · บรรทัดคำขอที่อยู่ใน RFx ถูกล็อกจากการเลือกผู้ขายทางอื่น (`LINE_IN_RFX`)

- ที่มาสองแบบ: `sourceKind = REQUEST_LINES` (บรรทัดจาก `freeLines` ของกองที่ `supplierId` ว่างและราคาไม่รวม VAT · `RfxLineSource` ชี้บรรทัดคำขอ · `RequestLine.rfxEventId` เป็น projection) และ `NEED` (จัดซื้อหรือหน่วยงานกรอกบรรทัดเอง · ผลไม่สร้าง PO แต่สร้างราคาตกลงและผู้ขายที่แนะนำ · ADR-206)
- RFx หนึ่งใบรับบรรทัดหมวดเดียว (`categoryCode` · `MIXED_CATEGORY`) เพื่อให้ `PreferredSupplier` ต่อหมวดมีความหมาย (ADR-207) · จำนวนผู้ขายขั้นต่ำคำนวณจากยอดประมาณเทียบ `quoteThresholdGross` ของ BR-FORM-04 (OQ-08) · เปิดด้วยน้อยกว่าเกณฑ์ต้องกรอกเหตุผล
- เวลา: `earliestCloseAt = addBusinessMinutes(openedAt, minOpenBusinessDays[kind] × 540)` ด้วย engine §7.8 · ยื่นที่วินาทีปิดรับพอดีถือว่าสาย · ปิดรับโดย job `rfx-close` แบบ `sleepUntil` · เลื่อนได้เฉพาะช้าลง
- amendment เพิ่ม `revisionNo` บันทึก `RfxAmendment` แจ้งทุกคำเชิญ และติดป้าย `needsReconfirm` ให้ใบที่ยื่นก่อนฉบับใหม่ (จัดซื้อตัดสิทธิ์ได้พร้อมเหตุผล) · ห้ามแก้ Scorecard หลังล็อกยกเว้นเพิ่มหรือถอนผู้ประเมิน
- RFI ไม่มีราคา ไม่มี Scorecard ไม่มีผล จบที่ `CONCLUDED` ด้วยสรุปของจัดซื้อ

## ผลที่ตามมา

- ตารางใหม่ `RfxEvent` `RfxLine` `RfxLineSource` `RfxInvite` `RfxQuestion` `RfxAmendment` ใน migration เดียวของ S10-01 · คอลัมน์ `RequestLine.rfxEventId` ใต้บล็อก `// --- S10 ---`
- จุดแก้เดียวในโค้ด S4: `procurement.assign_supplier` ปฏิเสธบรรทัดที่ `rfxEventId` ไม่ว่าง (`LINE_IN_RFX`) · คอลัมน์ว่างในข้อมูลเดิม เทสต์เดิมจึงไม่เปลี่ยน · รอบรวม PR ข้ามบรรทัดใน RFx อยู่แล้วเพราะไม่มีผู้ขาย (BR-CONS-03)
- state machine และ `Request` ของชั้น 1 ไม่เปลี่ยน · คำขอหลายใบแข่งราคาร่วมกันได้ และ PO ที่ได้ยังแยกตามกติกา BR-CONS-01 (ผู้ขาย สถานที่ส่ง ชนิด)
- ถ้าผู้ใช้เลือกให้ RFx เป็นสถานะของคำขอแทน: ต้องเพิ่มสถานะใน `RequestStatus` และแตะ `request.*` `po.*` หลายจุด ไม่แนะนำ
