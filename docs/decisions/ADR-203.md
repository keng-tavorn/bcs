# ADR-203: ผู้ขายใหม่เข้าร่วม RFx ผ่านใบสมัครของ S7 แต่ยื่นราคาได้เมื่ออนุมัติเป็นผู้ขายแล้ว

- สถานะ: ยอมรับ (ร่าง ADR-075 · ผู้ใช้อนุมัติตามที่แนะนำเมื่อ 2026-11-01)
- วันที่: 2026-11-01
- ที่มา: docs/sub-specs/S10.md หัวข้อ "กฎ" (BR-RFX-03 BR-RFX-07) และ "เรื่องที่ผู้ใช้ต้องตัดสิน" (OQ-202) · บรีฟของ ADR-075 ที่ให้ S10 ตัดสินว่า "ต้องสมัครให้ APPROVED ก่อนยื่น?"

## บริบท

- S7 ให้ผู้ขายใหม่สมัครผ่านพอร์ทัลเป็น `SupplierApplication` ที่ต้องผ่านการยืนยันเอกสารและ DOA `SUPPLIER_APPROVAL` ก่อนเป็น `Supplier` ACTIVE (ADR-181 · BR-SUP-11) · ผู้ติดต่อของใบสมัครมี session ของพอร์ทัลตั้งแต่ยังเป็น DRAFT
- การจัดหามักต้องการราคาจากผู้ขายรายใหม่ที่ยังไม่อยู่ในทะเบียน ถ้าต้องรอสมัครให้เสร็จก่อนเชิญจะช้า แต่ถ้ารับราคาจากรายที่ยังไม่ผ่านการตรวจ อาจมอบงานให้ผู้ขายที่ไม่ผ่านคุณสมบัติ
- `procurement.assign_supplier` ของ S4 รับเฉพาะผู้ขาย ACTIVE อยู่แล้ว ผลมอบงานจึงสร้าง PO ให้ผู้ขายที่ไม่ ACTIVE ไม่ได้ (ADR-206)

## การตัดสินใจ

> ผู้ขายใหม่เข้าร่วม RFx ผ่านใบสมัครของ S7: `RfxInvite` ผูก `applicationId` ของใบสมัครที่เปิดอยู่ได้ ผู้ติดต่อเห็น RFx และถามคำถามผ่าน session ของพอร์ทัล S7 แต่ `bid.submit` ต้องมี `Supplier` ACTIVE (`SUPPLIER_NOT_APPROVED`) · ใบสมัครผ่าน DOA ก่อนปิดรับ → คำเชิญย้ายไป `supplierId` อัตโนมัติ ไม่ทันปิดรับ → EXPIRED · ไม่สร้างทางลัดอนุมัติผู้ขายใน S10

- `RfxInvite` มี `supplierId?` หรือ `applicationId?` (อย่างน้อยหนึ่ง) · คำเชิญผ่านใบสมัครใช้ผู้ติดต่อหลักของใบและลิงก์ `RFX_INVITE` เดียวกัน
- listener ของ S10 ฟัง event `supplier_application.approved` ของ S7 (มี `supplierId` ใน data) แล้วอัปเดตคำเชิญ (`rfx_invite.supplier_linked`) · ใบที่ APPROVED หลังปิดรับไม่ย้อนเปิดคำเชิญ
- ผู้ขาย ACTIVE ที่ถูกธง `registryFlag` CEASED หรือ VAT_CANCELLED (BR-SUP-04) เชิญไม่ได้ (`SUPPLIER_FLAGGED`) · เอกสารบังคับไม่ครบ (`supplierDocumentStatus` ของ S7) เป็นคำเตือนใน `supplierSnapshot` ไม่บล็อก เพราะการบล็อกเป็นของ S11 · เมื่อเปิด `RISK` ผล `supplierRiskStatus` ของ S11 (อ่านผ่าน provider ที่ S11 ลงทะเบียน) เก็บลง `supplierSnapshot` และเตือนตอนเชิญผู้ขาย HIGH ที่ยังไม่ประเมิน ไม่บล็อก (BR-RFX-03)
- เชิญได้ขณะ RFx DRAFT และ OPEN ก่อน `closesAt` (เชิญเพิ่มหลังเปิดสร้างลิงก์และอีเมล `rfx.invited` ให้รายใหม่ทันทีในธุรกรรมเดียว · CLOSED ขึ้นไป → `INVALID_STATE_TRANSITION`) · ฉาก 12 ของ demo เชิญใบสมัคร `SUBMITTED` ที่อยู่ใน seed ของ S7 เข้า RFQ ที่ OPEN แล้ว
- ลิงก์ `RFX_INVITE` ใช้ครั้งเดียวและมี `PortalInviteLink.expiresAt = RfxEvent.closesAt` (คอลัมน์เดิมต่อแถวของ S7 · ไม่ใช้ `inviteLinkDays` 7 วัน เพราะ RFP เปิดรับ ≥ 10 วันทำการ · เลื่อน `closesAt` แล้วตั้งใหม่ให้ลิงก์ที่ยังไม่ใช้) · ผู้ติดต่อที่ใช้ลิงก์แล้วเข้าซ้ำด้วยลิงก์เข้าระบบจาก `/portal/[org]/login` (`portal.requestLink` ของ S7) ซึ่งอีเมลเชิญบอกไว้
- อีเมลเชิญถึงใบสมัครที่ยังไม่มีแถว `Supplier` ใช้ `SupplierNotice.supplierId` nullable + `applicationId?` `contactId?` และ context `locale` ที่ S7-01/S7-04 ทำ (S7.md Entity และ BR-NOTI-09) · S10 ไม่เพิ่มเอง

## ผลที่ตามมา

- จัดซื้อเชิญผู้ขายใหม่ได้ทันทีที่เชิญสมัคร (ฉาก 12 ของ demo) และกำหนดวันปิดรับให้พอกับการสมัคร
- ไม่มีราคาจากรายที่ยังไม่ผ่านการตรวจเข้าตารางเทียบ จึงไม่มีทางมอบงานให้รายที่ไม่ ACTIVE · `assignSupplierInTx` ตรวจ ACTIVE ซ้ำอยู่แล้ว
- S10 เพิ่มค่า `RFX_INVITE` ใน enum purpose ของ `PortalInviteLink` ของ S7 ตามที่ S7 จองไว้ (migration ของ S10-01)
- ถ้าผู้ใช้เลือกให้ยื่นได้ก่อนอนุมัติ: ต้องรับราคาจากรายที่ไม่มี `Supplier` และตารางเทียบต้องมีผู้ขายที่ไม่มี id ซึ่งกระทบ ADR-206 ไม่แนะนำ
