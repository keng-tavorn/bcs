# ADR-209: Sourcing และ Negotiation Agent ระดับ L0–L1 ที่เขียนข้อความจาก facts ของโค้ด

- สถานะ: ร่าง ADR-075 (2026-11-01) รอผู้ใช้อนุมัติ
- วันที่: 2026-11-01
- ที่มา: docs/sub-specs/S10.md หัวข้อ "กฎ" (BR-AI-30 BR-AI-31) "FR และ AC" (FR-AI-305) และ "ร่าง golden case" (GC-AI-96 ถึง GC-AI-99) · §8.11 FR-AI-305 "Sourcing และ Negotiation Agent (ทำพร้อม S10 เมื่อเปิดโมดูล AI)"

## บริบท

- §12 กำหนดว่า AI ไม่อนุมัติแทนคน ไม่เรียก command ที่เปลี่ยนสถานะเงินหรือการอนุมัติ (BR-AI-01) ตัวเลขมาจากโค้ด (BR-AI-03) ผลเป็นร่างใน `AgentAction` (BR-AI-02) และเปิดได้เฉพาะ L0–L1 (ADR-004) · S13 มีตัวตรวจข้อความ `ai-text` (BR-AI-27) และ `applyAiAssist` (BR-AI-17)
- "Negotiation Agent" ที่ส่งข้อความหาผู้ขายหรือเสนอราคาแทนองค์กรเป็นการกระทำที่มีผลต่อคู่ค้า ไม่ใช่การเตรียมงาน · e-Auction เป็น FR-SRC-301 ของ S15
- ราคาในซองปิดต้องไม่รั่วก่อนปิดรับ (ADR-204) และ AI ไม่ควรให้คะแนนแทนผู้ประเมิน (ADR-205)

## การตัดสินใจ

> Sourcing และ Negotiation Agent (FR-AI-305) ระดับ L0–L1 ในโมดูล AI: `RFX_DRAFT` (L1) ร่างข้อความและชนิดของ RFx จากบรรทัดคำขอเข้าร่างผ่าน `rfx.update` + `aiAssist` · `BID_SUMMARY` และ `NEGOTIATION_POINTS` (L0) เป็นข้อความที่ค่าทุกตัวมาจาก facts ของโค้ด (`compareBids` `priceAnomalyFlags` คะแนน) ผ่านตัวตรวจ `ai-text` profile `SOURCING` เรียกได้หลังปิดรับเท่านั้น · ไม่ส่งข้อความถึงผู้ขาย ไม่ให้คะแนน ไม่สร้างผล ไม่เลือกผู้ที่ควรเชิญ (BR-AI-01 BR-AI-03 BR-AI-27) · credits ขององค์กร · ชุดประเมินชั้น demo ด้วย RFx สังเคราะห์ · ปิด AI ทุกอย่างทำงานครบ (EG-1)

- agent `SOURCING` purpose `RFX_DRAFT` (L1): ร่าง `title` `titleEn` `description` `descriptionEn` และคำอธิบายอังกฤษของบรรทัด ชนิด RFQ/RFP และเกณฑ์จาก `defaultWeightsBp` · schema ไม่มีราคา จำนวน รหัสผู้ขาย หรือรายชื่อที่ควรเชิญ (การเชิญเป็นการกระทำที่มีผลต่อผู้ขาย คนเลือกเอง) · การแยกร่างต่อหมวด ชนิด และ `minInvites` คำนวณด้วยโค้ด (`rfxDraftFromLines` · GC-AI-99) · ค่าเข้าร่างผ่าน `applyAiAssist` purpose `RFX_DRAFT` → subject `RFX_EVENT` ที่ `services/sourcing/ai-assist.ts` ลงทะเบียนด้วย `registerAssistSubject('RFX_EVENT', { purposes: ['RFX_DRAFT'], final: false, read })` (registry ของ `assist-contract.ts` · ไม่มีตารางให้ขยายและไม่แก้ไฟล์ของ S13 · ถ้อยคำ BR-AI-17 เพิ่มเพียงรายการ) · `rfx.open` ที่ยังมีค่ารอตรวจ → `AI_REVIEW_PENDING`
- purpose `BID_SUMMARY` `NEGOTIATION_POINTS` (L0): เรียกได้เมื่อ RFx CLOSED ขึ้นไปและผู้เรียกมี `sourcing.view` · facts = จำนวนใบ ต่ำสุด สูงสุด ช่วง ใบรวม VAT ใบไม่จด VAT ใบต่างชาติ ธงราคาผิดปกติต่อบรรทัด ส่วนต่างรายเดิมกับต่ำสุด ราคาตกลง/ค่ากลางที่ใช้เทียบ และคะแนนที่ REVEALED · `spreadBp` และ `gapBp` ใช้ฐานเดียวคือยอดต่ำสุด (`roundHalfUpDiv(ส่วนต่าง × 10000, lowestNet)` · ฉาก 9 ทั้งคู่ = 151) และเป็น kind `integer` ในตัวตรวจ · facts มีเฉพาะตัวเลขและรหัส: ไม่มีข้อความอิสระของผู้ขาย (`Bid.note` `RfxQuestion.question`) ไม่มีข้อมูลผู้ติดต่อ และผู้ขายบุคคลธรรมดาแทนชื่อด้วย "ผู้ขายบุคคลธรรมดา <code>" (BR-AI-08 · เทสต์ redaction) · ข้อความ ≤ 6 ประโยคผ่าน `ai-text` profile `SOURCING` `{ maxSentences: 6, maxChars: 160 }` (ห้ามตัวเลขนอก `{{v:…}}` ห้ามคำแนะนำให้ตัดสินหรือมอบงาน — เพิ่มคำ `ควรมอบงาน` `แนะนำให้มอบงาน` `ควรเลือก` `should award` `recommend award` ใน `DECISION_ADVICE_WORDS` และ fixture · GC-AI-96 ถึง 98) · job `rfx-ai-summary` สร้างสรุปล่วงหน้าหลัง CLOSED/REVEALED
- ข้อห้าม: ไม่ส่งข้อความถึงผู้ขาย ไม่เปิดรอบเสนอราคาใหม่ ไม่แก้ข้อเสนอ ไม่เติม `ScoreEntry` ไม่สร้าง `AwardDecision` · boundary INV-AI-05: `src/server/services/sourcing` ไม่ import `src/integrations/ai`
- credits ขององค์กร (BR-AI-23) · อัตรา BR-AI-11 · เปิดปิดด้วย `settings.sourcing.aiAssist` และ `AiAgentSetting` (BR-AI-05) · ชุดประเมินชั้น demo ด้วย RFx สังเคราะห์ 10 ชุด (S10-19) ชั้น REAL เมื่อมีข้อมูลจริง (S10-23)

## ผลที่ตามมา

- enum Prisma `AiAgent.SOURCING` `AiPurpose.RFX_DRAFT` `BID_SUMMARY` `NEGOTIATION_POINTS` ใน migration S10-01 · `src/lib/ai-config.ts` เติมใน S10-16 · `AgentAction.subjectType = RFX_EVENT`
- BR-AI-17 แก้ถ้อยคำเพิ่ม `RFX_DRAFT` → RFx (หัวข้อ F ของ spec-additions) · `ai-text` เพิ่ม profile `SOURCING` และตัวคำนวณ `run_ai_text` ของ S13 รับ profile ใหม่
- ปิด AI (ระบบ โมดูล agent หรือ `sourcing.aiAssist = N`) ปุ่มทั้งสามหาย ตารางเทียบ ธง คะแนน และผลทำงานครบ (EG-1) · ฉาก demo ผ่านทั้งเปิดและปิด AI
- ROPA ของลูกค้าเพิ่ม agent `SOURCING` (ข้อมูลที่ส่ง: บรรทัดคำขอ ราคาที่ยื่น ชื่อผู้ขายนิติบุคคล · ผู้ขายบุคคลธรรมดาส่งเป็นรหัส · ไม่ส่งข้อความอิสระของผู้ขายและไม่มีข้อมูลผู้ติดต่อ ตามที่ BR-AI-31 บังคับ · BR-AI-08) ใน S10-22
- ถ้าผู้ใช้ต้องการให้ AI ติดต่อผู้ขายหรือเสนอราคารอบใหม่: เป็นงานหลัง L1 ที่ต้องผ่านชุดประเมินและ e-Auction ของ S15 ไม่อยู่ในร่างนี้
