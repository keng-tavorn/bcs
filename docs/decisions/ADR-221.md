# ADR-221: แบบประเมินความเสี่ยงเป็นเอกสารแยกจากผู้ขาย และเลือกชุดคำถามจากคำตอบคัดกรองของคำขอ

- สถานะ: ยอมรับ (ร่าง ADR-075 · ผู้ใช้อนุมัติตามที่แนะนำเมื่อ 2026-11-01)
- วันที่: 2026-11-01
- ที่มา: docs/sub-specs/S11.md หัวข้อ "ขอบเขต" "Entity และ migration" และ "State machine" · ผู้ใช้สั่งออกแบบระยะ 2 ก่อนจบ A3 และ C (ADR-075)

## บริบท

- §6.5 จองชื่อ `RiskQuestionnaire` `RiskAssessment` `RiskTier` `ReviewTask` `RiskReview` ไว้สำหรับ S11 แต่ไม่ได้บอกว่าแบบประเมินผูกกับอะไร · §8.12 FR-RSK-201 บังคับให้ "เลือกชุดคำถามจากคำตอบคัดกรองในคำขอ (BR-FORM-05) ไม่ใช่จากประเภทผู้ขายอย่างเดียว"
- คำตอบคัดกรอง (`processesPersonalData` `accessesSystems` `accessesPremises`) อยู่ใน `Request.formData` (Json คำตอบฟอร์ม · ชื่อคอลัมน์จริงใน `prisma/schema.prisma` · ไม่มีคอลัมน์ `fields`) ของคำขอ ไม่ใช่ที่ผู้ขาย: ผู้ขายรายเดียวอาจเป็นความเสี่ยงต่ำในงานหนึ่งและสูงในงานถัดไป
- ถ้าเก็บคำตอบบนแถว `Supplier` โดยตรง จะไม่มีประวัติ ไม่มีรอบประเมินซ้ำ และระดับจะเปลี่ยนทันทีที่แก้คำตอบโดยไม่ผ่านผู้ตรวจ · S7 ตัดสินแบบเดียวกันกับใบสมัคร (ADR-181)
- ผู้ขายต้องตอบเองได้ในพอร์ทัลของ S7 (FR-RSK-201 · ADR-183 ADR-184) โดยไม่สร้างตัวตนหรือ session ใหม่

## การตัดสินใจ

> แบบประเมินความเสี่ยงเป็นเอกสาร `RiskAssessment` + `RiskAnswer` แยกจาก `Supplier`: เปิดจาก PO ที่ติดด่าน คำขอ หรือหน้าผู้ขาย โดยคัดลอกคำตอบคัดกรอง BR-FORM-05 ของคำขอต้นทางทุกบรรทัดของ PO (ค่าใดเป็น Y ถือ Y) หมวดของบรรทัด และประเภทผู้รับเงินเป็นบริบทของใบ · ชุดคำถามและระดับตั้งต้นคำนวณจากบริบทนั้น (BR-RSK-01 BR-RSK-03) · ฉบับแบบประเมินแช่แข็งตอนเปิด ระดับและคะแนนแช่แข็งตอนส่ง (BR-RSK-04) · ใบที่เปิดอยู่ใบเดียวต่อผู้ขาย (INV-RSK-02) · ประเมินซ้ำ = ใบใหม่ที่ supersede ใบเดิม · `Supplier` ถือเฉพาะ projection (`riskTier` `riskStatus` `riskValidUntil` `currentRiskAssessmentId`) · ผู้ขายตอบในพอร์ทัลของ S7 ด้วย action ใหม่ของ `portalAuthorize` และลิงก์ `PortalInviteLink` purpose `RISK_QUESTIONNAIRE` หรือจัดซื้อกรอกแทน (source `ON_BEHALF`)

- สถานะของใบ: `DRAFT → IN_REVIEW → COMPLETED` และ `RETURNED` `SUPERSEDED` `CANCELLED` ตามตารางใน sub-spec (ไม่มี `SUBMITTED` เพราะ submit ไป IN_REVIEW หรือ COMPLETED ในธุรกรรมเดียว · ตัดออกในรอบตรวจของขั้น) · ไม่มีข้อผู้ตรวจที่ตรง → `COMPLETED` ทันทีตอนส่ง · CHECK ของตารางให้ใบ COMPLETED และ SUPERSEDED มี `completedAt` `tier` `validUntil` ครบ
- บริบทคัดกรองเก็บใน `RiskAssessment.screening` `categoryCodes` `payeeType` `workScopes` และใช้ซ้ำตอนด่าน PO ตรวจว่าใบที่มีอยู่ "ครอบ" PO ใหม่หรือไม่ (ADR-225 · reason `SCOPE_EXPANDED`)
- คำตอบของใบที่ COMPLETED/SUPERSEDED แก้ไม่ได้ (trigger `risk_answer_frozen` · INV-RSK-03) และคำนวณซ้ำได้จาก `scoringSnapshot`
- ใบไม่มียอดเงิน ไม่มีเส้นทาง DOA (การอนุมัติข้ามเป็นเอกสารแยก · ADR-226)

## ผลที่ตามมา

- `Supplier` ยังเป็นตารางหลักที่ S8 S9 S10 อ่าน · S10 อ่านระดับผ่าน `supplierRiskStatus` ไม่อ่านตารางใบ
- เปิดใบจากหน้าผู้ขายโดยไม่มีคำขอต้องให้จัดซื้อตอบคัดกรอง 3 ข้อเอง (`SCREENING_REQUIRED`) จึงไม่มีใบที่ "ไม่รู้บริบท"
- พอร์ทัลของ S7 ขยาย `portalDb` และ lint รายการ model (INV-SUP-01 นับ query ใหม่เอง) · S11 ไม่สร้าง session OTP หรือ cookie ของตัวเอง
- ถ้าผู้ใช้เลือกให้ระดับอยู่บนแถว `Supplier` และแก้ได้ตรง: ไม่มีประวัติ ไม่มีรอบ และต้องกันคนแก้ระดับเองด้วยสิทธิ์ซ้อน จึงไม่แนะนำ
