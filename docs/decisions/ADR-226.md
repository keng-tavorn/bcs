# ADR-226: ชนิดเอกสาร DOA RISK_OVERRIDE มียอดเป็นเพดานของ PO มีวันหมดอายุ และไม่มีปุ่มในแชท

- สถานะ: ร่าง ADR-075 (2026-11-01) รอผู้ใช้อนุมัติ
- วันที่: 2026-11-01
- ที่มา: docs/sub-specs/S11.md หัวข้อ "กฎ" (BR-RSK-10 BR-RSK-11 BR-DOA-28 BR-SOD-15) "Entity และ migration" (`RiskOverride`) และ "เรื่องที่ผู้ใช้ต้องตัดสิน" · บรีฟระยะ 2 ถามว่ายอดของชนิดนี้คืออะไร (OQ-224) ต้อง step-up ไหม และ S9 รับ `riskOverrides` อย่างไร

## บริบท

- FR-RSK-203 ให้ "มีผู้อนุมัติข้ามตาม DOA" · บรีฟจองชนิด `RISK_OVERRIDE` และ subject `RISK_OVERRIDE` ไว้ และ §4.11 ข้อ 7 ให้เปิดโมดูล `RISK` ต้องมีข้อของชนิดนี้ (BR-DOA-24)
- `DOC_TYPE_TRAITS` รับยอด REQUIRED OPTIONAL NONE (BR-DOA-20) · ชนิดที่ไม่มี VAT ส่ง `vatSatang = 0` (BR-DOA-21 · แบบ `PAYMENT_RUN` `BUDGET_TRANSFER`) · ถ้าไม่มียอด ผู้อนุมัติจะไม่เห็นขนาดเงินที่เสี่ยง และ DOA แยกช่วงวงเงินไม่ได้
- §8.12 ให้การอนุมัติข้ามมีวันหมดอายุ และ S9 มีธง `RISK_OVERRIDE_EXPIRED` ที่รับ `riskOverrides: [{ expiresOn }]` เป็น input โดยเขียนว่า "S11 เพิ่มแหล่งข้อมูลโดยไม่แก้ engine" (GC-PAY-30 GC-PAY-31)
- ADR-068 กำหนด adapter ต่อ subject และ `channels` `sodContext` · BR-DOA-25 ให้บัญชีธนาคาร step-up ทุกครั้ง แต่การอนุมัติข้ามความเสี่ยงไม่ใช่เงินออกโดยตรง

## การตัดสินใจ

> ชนิดเอกสาร `RISK_OVERRIDE` (BR-DOA-28): `DOC_TYPE_TRAITS` = ยอด `REQUIRED` ไม่มี VAT (`{ netSatang: capGrossSatang, vatSatang: 0 }`) ไม่ใช่ข้อกำกับ subject `RISK_OVERRIDE` บังคับมีข้อเมื่อเปิด `RISK` · ยอด = **เพดานยอดรวม VAT สะสมของ PO ทุกใบที่ยอมให้ออกภายใต้การอนุมัตินี้** (`RiskOverride.capGrossSatang` > 0 · `usedGrossSatang` สะสม · `usedCount` = จำนวน PO ที่ไม่ซ้ำกันซึ่ง `PurchaseOrder.riskOverrideId` อ้างรายการนี้ เพิ่มครั้งเดียวต่อ PO · OQ-224 · เพดานต่อใบจะให้จัดซื้อออก PO ใต้เพดานได้ไม่จำกัดจำนวน) · เอกสาร `RiskOverride` ขอโดย PROCUREMENT มี `expiresOn` ≥ วันส่ง ภายใน `settings.risk.overrideMaxDays` (90) ผูก PO เดียวหรือทั้งผู้ขาย รายการเปิดอยู่รายการเดียวต่อผู้ขาย · ผู้ขายที่ติดธงทะเบียนขอไม่ได้ (ADR-225) · adapter `subjects/risk-override.ts` ตาม ADR-068: `channels: { chatButton: () => RiskPolicy.overrideChatButton (false · ADR-229), emailLink: false, liff: true }` · step-up ตามยอดเทียบ `stepUpThreshold` เหมือนชนิดอื่น (ไม่อยู่ใน `ALWAYS_STEP_UP_SUBJECTS` · OQ-225) · `allowsRequestInfo: false` (ตีกลับแทน) · `sodContext` = ผู้ขอ ผู้สร้าง PO ที่อ้าง ผู้กรอกแทนของใบประเมินที่อ้าง (BR-SOD-15) · PO ผ่านด่านด้วยรายการนี้เมื่อ `expiresOn ≥ วันของ PO` และ `usedGrossSatang − priorGrossSatang(PO_CHANGE) + grossSatang ≤ capGrossSatang` (ล็อกแถว FOR UPDATE · `po_change` ที่เพิ่มยอดผ่านด่านซ้ำ ADR-225) · S9 รับแหล่งข้อมูลผ่าน `riskOverridesForPayment(tx, ctx, supplierIds)` ที่คืน `[{ expiresOn: 'YYYY-MM-DD' }]` ของรายการ APPROVED/EXPIRED ของผู้ขายที่ยังไม่มีใบ COMPLETED ที่ใช้ได้ แทนค่า `riskOverrides: []` ใน `itemFlagsNow(tx, input)` ของ `src/server/queries/payment-runs.ts` (เพิ่มใน input และให้ `services/payments/runs.ts` กับ query ของหน้ารอบจ่ายส่งค่าเข้า) โดยไม่แก้ `itemFlags`

- ข้อร่างของ SIMEC: RO-01 `(0, 1,000,000.00]` → COO · RO-02 เกิน → CEO (ข้อมูล demo · ลูกค้ายืนยัน OQ-224 ในเส้นชัย B) · golden GC-DOA-81 ถึง 86 ใน fixture `doa-versions-p2.yaml` ต่อท้าย `RFX_AWARD` ของ S10 (ADR-069) · expect ตามรูปแบบตัวรัน `run_doa` (`rule` ช่วงเดิม + `escalatedTo` · ยอด 0 คืน `{ error: VALIDATION_FAILED }`) · `AMOUNT_REQUIRED` ของ `scripts/spec_check.py` เพิ่ม `RISK_OVERRIDE`
- เคสขอบของเพดานสะสมและ `usedCount`: GC-RSK-67 (สะสมเท่าเพดาน) GC-RSK-68 (เกิน 1 สตางค์) GC-RSK-69 (`po_change` เพิ่มยอด) · integration test ของ S11-08: PO 2 ใบพร้อมกัน → `usedCount 2` · submit แล้ว send ใบเดียว → `usedCount 1` event `risk_override.used` ครั้งเดียว · seed ของ SIMEC มี `RO-2569-00001` ของ `SP0141` ที่ใช้กับ H047 แล้ว EXPIRED
- ลำดับใน `DOA_DOCUMENT_TYPES`: SUPPLIER_APPROVAL → RFX_AWARD → RISK_OVERRIDE ตามที่ S7 ประกาศ · `scripts/spec_check.py`: `DOC_ORDER` เพิ่มท้าย · `MODULE_DOCS["RISK"] = ("RISK_OVERRIDE",)`
- หมดอายุ → job รายวันตั้ง EXPIRED และสร้าง `RiskReview` reason `OVERRIDE_EXPIRED` เมื่อผู้ขายยังไม่มีใบใช้ได้ (ADR-227)
- การอนุมัติไม่ปิดใบประเมินที่เปิดอยู่ · G-9 นับ PO ที่ผ่านด้วยการอนุมัติข้ามเป็น "ไม่ประเมิน" (ADR-229)

## ผลที่ตามมา

- ลูกค้าแบ่งอำนาจข้ามด่านตามขนาดเงินได้ด้วย DOA เดิม (lint ตารางผลที่ขอบทำงาน) และต้องเผยแพร่ข้อ RO ก่อนทีม BCS เปิดโมดูล (NG-12)
- S9 แก้ 1 บรรทัดและเทสต์ GC-PAY-30 GC-PAY-31 ไม่เปลี่ยน · ข้อ S11-08 เป็น `xhigh` รีวิวทันที
- ถ้าผู้ใช้เลือกเพดานต่อ PO (ทางเลือก (ข) ของ OQ-224): จัดซื้อออก PO ใต้เพดานได้ไม่จำกัดใบภายในอายุ ยอดที่เสี่ยงจริงไม่มีขอบ จึงไม่แนะนำ · ถ้าเลือกยอด NONE (ทาง (ค)): การอนุมัติข้ามครั้งเดียวใช้กับ PO ทุกขนาด และผู้อนุมัติไม่เห็นขนาดความเสี่ยง · ถ้าเลือก step-up ทุกครั้ง (OQ-225 ทาง ค): เพิ่ม `RISK_OVERRIDE` ใน `ALWAYS_STEP_UP_SUBJECTS` 1 บรรทัดโดยไม่กระทบอื่น
