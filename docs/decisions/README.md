# บันทึกการตัดสินใจ (ADR)

ADR (Architecture Decision Record) คือบันทึกสั้น ๆ ว่าตัดสินใจเรื่องสำคัญอะไร เพราะอะไร และมีผลอะไรตามมา ไฟล์ ADR-001 ถึง ADR-035 สร้างจากตาราง spec §18.1 ส่วน ADR-036 ถึง ADR-042 บันทึกระหว่าง demo build แล้วเพิ่มแถวใน §18.1 (NEW-01 · ADR-041 ระหว่างแก้ S1-05 รอบที่ 3 · ADR-042 ระหว่างทำ S2-16) · §18.1 กำหนดว่าแต่ละข้อต้องมีไฟล์ `docs/decisions/ADR-nnn.md`

- ลำดับความสำคัญ: `spec.md` > `docs/decisions/ADR-*.md` > `docs/sub-specs/S*.md` > comment ในโค้ด (§0.1) · ถ้า ADR ขัดกับ spec ให้ยึด spec และแก้ spec ผ่าน PR พร้อมบันทึก ADR
- สถานะ (§18.1): `ตัดสินแล้ว` · `เสนอ` = เสนอโดย spec (ADR-018 ถึง ADR-030) หรือโดย agent ระหว่าง demo build (ADR-037 ADR-039 ADR-040 ADR-041 ADR-042) ใช้ได้ทันทีเว้นแต่มีผู้คัดค้าน · ยังไม่มี GitHub (ADR-038 ข้อ 2) จึงแจ้ง ADR ที่ agent เสนอในสรุปตอนจบรอบแทน PR · `ยังไม่ตัดสิน` = ระหว่างรอใช้ค่าชั่วคราวที่ระบุในข้อนั้น · ถ้าตัดสินเพียงบางส่วน ให้เขียนขอบเขตไว้ในสถานะ (เช่น ADR-032) · ไฟล์และดัชนีนี้อาจต่อท้ายสถานะด้วยผู้ตัดสินและวันที่ เช่น `ตัดสินแล้ว (ผู้ใช้ 2026-10-02)` ส่วนตาราง spec §18.1 ใช้สถานะสั้น
- ที่มา: ADR-001 ถึง ADR-016 มาจากตารางเรื่องที่ต้องตัดสินใจในเอกสารต้นทาง (ภาคผนวก C: เอกสารต้นทางหัวข้อ 14 "เรื่องที่ต้องตัดสินใจ") · ADR-017 ADR-034 และ ADR-035 เป็นการตัดสินใจของเจ้าของโปรเจกต์ · ADR-018 ถึง ADR-030 เสนอโดย spec · ADR-031 และ ADR-033 ยังไม่ตัดสินใน spec · ADR-032 ผู้ใช้ตัดสินเฉพาะ staging (2026-10-02) · ADR-036 ถึง ADR-042 บันทึกระหว่าง demo build (2026-10-02 ถึง 2026-10-03): ADR-036 และ ADR-038 เป็นการตัดสินใจของผู้ใช้ ส่วน ADR-037 ADR-039 ADR-040 ADR-041 ADR-042 agent เสนอ
- วันที่: วันที่ 2026-10-01 ใน ADR-001 ถึง ADR-035 คือวันที่ของ spec ฉบับ 0.2 ที่บันทึกข้อนั้นไว้ (1 ต.ค. 2026) ไม่ใช่วันที่ตัดสินหรือเสนอจริง ซึ่ง spec ไม่ได้ระบุ · วันที่ 2026-10-02 คือวันที่ผู้ใช้ตัดสิน วันที่ agent บันทึก ADR ใหม่ (ADR-037 ADR-039 ADR-040 และ ADR-041 ADR-042 ที่บันทึก 2026-10-03) หรือวันที่เพิ่มหมายเหตุ ตามที่เขียนไว้ในบรรทัดวันที่ของไฟล์นั้น
- เขียน ADR ใหม่เมื่อมีการตัดสินใจเชิงสถาปัตยกรรม (NFR-MNT-03 · §17.2 ข้อ 5 · §17.5) เช่น API ของ Prisma ที่ติดตั้งต่างจากตัวอย่างใน §5.2

- ADR-032 ตัดสินเฉพาะ staging (Vercel สิงคโปร์ sin1) · hosting ของ production ยังรอยืนยัน · spec §18.1 และแถว Hosting ใน §5.1 ปรับแล้วใน NEW-01
- ADR-025 และ ADR-033 มีหมายเหตุ (2026-10-02) ว่าที่เก็บไฟล์บนเครื่องใช้ RustFS แทน MinIO ตาม ADR-036 · ADR-031 มีหมายเหตุ (2026-10-02) ว่าผู้ใช้ยังไม่ได้เลือกผู้ให้บริการอีเมลของ staging
- ADR ใหม่ตั้งแต่ ADR-036 เขียนตามรูปแบบด้านล่างเมื่อมีการตัดสินใจใหม่ (§17.2 ข้อ 5) และต้องเพิ่มแถวในตารางนี้ทุกครั้ง

## รูปแบบไฟล์

```markdown
# ADR-nnn: <ชื่อสั้น>

- สถานะ: ตัดสินแล้ว | เสนอ | ยังไม่ตัดสิน
- วันที่: YYYY-MM-DD
- ที่มา: <ใครตัดสิน หรือมาจากส่วนไหนของ spec>

## บริบท
## การตัดสินใจ
## ผลที่ตามมา
## หมายเหตุ (YYYY-MM-DD)
## อ้างอิง
```

- `## การตัดสินใจ` ขึ้นต้นด้วยบรรทัด `>` ซึ่งคัดจากตาราง spec §18.1 คำต่อคำ ยกเว้น ADR-032 ADR-036 และ ADR-038 ที่เป็นคำตัดสินของผู้ใช้ · ถ้าคำตัดสินมาจากที่อื่น ให้บอกที่มาในวงเล็บต้นบรรทัด เช่น `> (ผู้ใช้ตัดสิน 2026-10-02) ...`
- `## หมายเหตุ (YYYY-MM-DD)` ไม่บังคับ ใช้เมื่อมีข้อมูลใหม่หลังบันทึก วางหลัง `## ผลที่ตามมา` และก่อน `## อ้างอิง` แล้วเพิ่ม `(เพิ่มหมายเหตุ YYYY-MM-DD)` ต่อท้ายบรรทัดวันที่

เขียนเป็นภาษาไทยแบบง่าย ใช้ศัพท์เทคนิคภาษาอังกฤษเมื่อจำเป็น อ้าง § และรหัส (FR BR INV OQ NG P0) ของ spec ทุกครั้ง และถ้า spec ไม่ได้ระบุเรื่องใดให้เขียนว่า "spec ไม่ได้ระบุ" แทนการเดา
