# Design review — หน่วย b: กล่องงาน หน้าตัดสิน และไทม์ไลน์ติดตามสถานะ (S2-12)

ขั้นตอนตาม spec §9.9: (1) แผนสั้นต่อหน้า (2) ตรวจแผนกับรายการ "สิ่งที่ห้ามใช้" ก่อนเขียนโค้ด (3) เขียนด้วย token
(4) screenshot 375 px และ 1440 px แล้วตรวจอีกรอบ (5) axe ไม่มี serious หรือ critical · ตารางผลตรวจอยู่ท้ายไฟล์

หลักที่ใช้ทุกหน้า: งานของฉันก่อน (หลัก 1) · สถานะแบบติดตามพัสดุ (หลัก 4) · ตัดสินได้ในจอเดียว (หลัก 5) · จุดเด่นเดียวคือ
ไทม์ไลน์แบบตราประทับที่บอกชื่อ ตำแหน่ง เวลา ช่องทาง และ DOA ข้อที่ใช้ ส่วนอื่นเรียบและเงียบ

## 1. แผนต่อหน้า

### A. `/` หน้าแรก

- ต้องบอก: งานที่รอฉันตัดสิน (นับรวม เกินกำหนดหรือไม่ ค้างมากี่ชั่วโมงทำการ) แล้วคำขอของฉัน (สถานะและตอนนี้อยู่ที่ใคร)
- ลำดับ: คำทักทาย → ปุ่มหลัก "ขอซื้อ / ขอจ้าง" → "งานรอคุณตัดสิน" 5 งานแรกที่ครบกำหนดก่อน → "คำขอของฉัน" 5 รายการล่าสุด
- โครงหน้า: คอลัมน์เดียวกว้างไม่เกิน 64rem · รายการคั่นด้วยเส้น ไม่ใช้การ์ด · แต่ละแถวเป็นลิงก์ไปที่งานหรือคำขอนั้น
- หน้าว่าง: งาน → บอกว่างานจะมาเมื่อไรพร้อมลิงก์ "ดูความคืบหน้าของคำขอของฉัน" · คำขอ → บอกวิธีเริ่มพร้อมลิงก์ "เริ่มขอซื้อหรือขอจ้าง"
- ตัวเลขทุกตัวพาไปที่รายการ ("ดูงานรออนุมัติทั้งหมด (n งาน)" "ดูคำขอทั้งหมด (n รายการ)")

### B. `/tasks` งานรออนุมัติ

- ต้องบอก: ทุกงานที่รอฉันและงานที่ฉันรับแทนผู้อื่น (หรือที่ผู้รักษาการรับแทนฉัน) เรียงที่ครบกำหนดก่อน
- ต่อแถว: เลขที่และชื่อคำขอ (ลิงก์) · ผู้ขอและแผนก · ยอดรวม VAT ชิดขวา tabular-nums พร้อมป้าย "ยอดรวม VAT" · สถานะเป็นไอคอนคู่ข้อความ
  (ค้างมา x ชั่วโมงทำการ · ครบกำหนด · เกินกำหนด · รอผู้ขอตอบ) · ป้ายข้อความ "คุณรับแทน …" หรือ "… รักษาการแทนคุณ"
- เวลาที่ค้าง = เวลาทำการตั้งแต่งานมาถึง ไม่นับช่วงที่รอผู้ขอตอบคำถาม (BR-SLA-03) จึงตรงกับเวลาที่ SLA ใช้ไปจริง
- งานเชิงนโยบาย (DOA และโครงสร้างอำนาจ) บอกสิ่งที่ขออนุมัติ วันมีผล และ "ต้องใส่รหัสจากแอปยืนยันตัวตน"
- หน้าว่าง: "ยังไม่มีงานรออนุมัติ" + คำอธิบายว่างานจะมาเมื่อไร + ลิงก์ "ไปที่คำขอของฉัน"
- มือถือ: แถวเดียวกันเรียงซ้อน ยอดเงินอยู่บรรทัดของหัวแถวชิดขวา ไม่มีตาราง

### C. `/tasks/[id]` หน้าตัดสิน

- ต้องบอกในจอเดียว (หลัก 5): เลขที่ ชื่อ ผู้ขอ แผนก · ยอดก่อน VAT · VAT · ยอดรวม (ชิดขวา ทศนิยม 2) · บรรทัดงบและสถานะงบ
  (จองแล้วเท่าไร) · DOA ฉบับและข้อ พร้อมคำอธิบายว่าทำไมงานมาถึงฉัน · รายการ · รายละเอียดฟอร์ม (ยอดเงินในฟอร์มชิดขวา) ·
  ไฟล์แนบ (เปิดได้ผ่านที่อยู่อายุสั้น) · คำถามและคำตอบ · ไทม์ไลน์
- ลำดับ: หัวเรื่องและสถานะงาน (ค้างมาเท่าไร ครบกำหนดเมื่อไร รับแทนใคร) → ยอดเงินและงบ → เหตุผลของเส้นทาง → รายการ
  → รายละเอียดและไฟล์ → ไทม์ไลน์
- โครงหน้า: จอกว้าง 2 คอลัมน์ เนื้อหาซ้าย แถบขวา 24rem มีกล่องตัดสินแล้วไทม์ไลน์ · มือถือคอลัมน์เดียว
- ปุ่มตัดสิน: "อนุมัติ" เป็นปุ่มหลักสีเดียว (primary) · ตีกลับและไม่อนุมัติอยู่อีกส่วน แยกจากปุ่มอนุมัติด้วยหัวข้อและเส้น
  ต้องเลือกผล ใส่เหตุผล และติ๊กยืนยัน ปุ่มไม่อนุมัติเป็นขอบสีแดง (danger) ไม่เหมือนปุ่มอนุมัติ · "ขอข้อมูลเพิ่ม" แยกอีกส่วน
- อนุมัติย้อนไม่ได้ จึงต้องยืนยันในหน้าเดียวกัน (ไม่ใช้ modal): "อนุมัติ" → แถบยืนยันที่บอกเลขที่และยอด → "ยืนยันอนุมัติ"
- มือถือ: แถบอนุมัติติดล่างจอ (ปุ่มอนุมัติ + ลิงก์ "ตีกลับ ไม่อนุมัติ หรือขอข้อมูลเพิ่ม" ที่พาไปส่วนนั้น) เนื้อหามีที่ว่างด้านล่างพอให้แถบไม่บัง
- งานที่ตัดสินแล้ว: ไม่มีปุ่ม บอก "อนุมัติแล้วโดย … เมื่อ …" · กดซ้ำจากหน้าที่เปิดค้างได้ "ดำเนินการแล้วโดย … เมื่อ …"
  (ชื่อตามภาษาของผู้อ่าน)
- ข้อความ error ของช่องหายทันทีที่ผู้ใช้แก้ช่องนั้น ไม่ค้างจนกดส่งรอบถัดไป
- DOA ref ("DOA-DEMO ฉบับ 1 ข้อ PR-02"): เป็นลิงก์ไปฉบับนั้นเฉพาะผู้ที่เปิดหน้าผู้ดูแล DOA ได้ (ORG_ADMIN) คนอื่นเห็นเป็นป้ายข้อความแบบเดียวกัน
  จึงไม่มีลิงก์ที่พาไปเจอหน้าปฏิเสธ (ใครควรอ่านฉบับ DOA ได้อีก เป็นคำถามที่รอผู้ใช้ตัดสิน)
- งานเชิงนโยบาย: กล่อง "สิ่งที่ขออนุมัติ" (ประโยคบอกการเปลี่ยน ผู้เสนอ วันมีผล เหตุผล ผลกระทบ) · อนุมัติหรือไม่อนุมัติเท่านั้น
  ทั้งสองต้องใส่รหัส 6 หลักจากแอปยืนยันตัวตน (BR-DOA-15) · ไม่อนุมัติต้องมีเหตุผลและติ๊กยืนยัน
- งานอนุมัติ DOA ฉบับใหม่: ผู้อนุมัติอ่านได้ครบในหน้านี้ เพราะหน้าผู้ดูแลเป็นของ ORG_ADMIN
  "เปลี่ยนจาก DOA-DEMO ฉบับ 1 ที่มีผลอยู่" (นโยบายที่เปลี่ยน · ข้อที่แก้ พร้อม "เดิม … · ใหม่ …" ของช่วงวงเงิน ผู้อนุมัติ SLA ·
  ข้อที่เพิ่มหรือลบ) → "ข้อของฉบับนี้ (n ข้อ)" แต่ละข้อบอกประเภทเอกสาร ผู้อนุมัติ SLA และช่วงวงเงินชิดขวา พร้อมป้ายข้อความ
  "ข้อใหม่" หรือ "เปลี่ยน: ช่วงวงเงิน" → "นโยบายของฉบับ" · ลิงก์ไปหน้าผู้ดูแลแสดงเฉพาะผู้ที่เปิดได้ · จำนวนงานที่ค้างภายใต้ฉบับเดิม
  (BR-DOA-13) แสดงเฉพาะตอนฉบับยังรออนุมัติ
- งานที่ไม่ใช่ของฉัน: บอกว่าไม่อยู่ในรายการของคุณ พร้อมทางไปต่อ

### D. `/requests` คำขอของฉัน

- ต้องบอก: คำขอที่ฉันส่งหรือติดตาม สถานะ (ไอคอน + ข้อความ) ตอนนี้อยู่ที่ใคร (ชื่อ ตำแหน่ง หรือ "… (รักษาการแทน …)"
  ค้างมากี่ชั่วโมงทำการ) และยอดรวม
- ค้นหาและกรอง (FR-INT-008 AC3): ช่องเลขที่เอกสารหรือชื่อ + ตัวเลือกสถานะ + ปุ่ม "แสดงคำขอที่ตรงกัน" (GET ไม่เปลี่ยนสถานะ)
  + ลิงก์ "ล้างตัวกรอง" · บอก "พบ x จาก y คำขอ" · ถ้ารายการตัดที่ 100 รายการล่าสุด บอกว่าให้ค้นหรือกรองเพื่อหาคำขอที่เก่ากว่า
- โครงหน้า: หัวข้อ + ปุ่มหลัก "ขอซื้อ / ขอจ้าง" · ฟอร์มค้นหา · รายการแถวคั่นเส้น (จอกว้างจัดเป็นคอลัมน์ใต้หัวคอลัมน์
  มือถือซ้อนกันและมีป้าย "ยอดรวม VAT (บาท)" ใต้ยอด ไม่มีตารางเลื่อนแนวนอน)
- หน้าว่าง 2 แบบ: ยังไม่มีคำขอ → บอกวิธีเริ่มพร้อมปุ่ม · ค้นไม่พบ → บอกวิธีค้นใหม่พร้อม "ล้างตัวกรอง"

### E. `/requests/[id]` รายละเอียดคำขอ

- ต้องบอก: ตอนนี้อยู่ที่ใครและค้างมานานเท่าไร (ด้านบนสุด) · สิ่งที่ผู้ขอต้องทำ (ตอบคำถาม แก้ไขแล้วส่งอีกครั้ง) ·
  "อนุมัติภายใต้ DOA-DEMO ฉบับ 1 ข้อ PR-02" (ลิงก์ไปฉบับนั้นสำหรับผู้ที่เปิดได้) · ยอดก่อน VAT VAT ยอดรวม · งบที่จอง ·
  เส้นทางจริงและเหตุผล (ขั้นที่ตีกลับใช้ไอคอนตีกลับแบบเดียวกับไทม์ไลน์) · รายการ รายละเอียด ไฟล์แนบ · ไทม์ไลน์แบบตราประทับ
  (รวมขั้น "แก้ไขคำขอ" ของผู้ขอหลังถูกตีกลับ บันทึกหลายครั้งติดกันนับเป็นขั้นเดียว)
- ลำดับ: หัวเรื่อง + สถานะ + ตอนนี้อยู่ที่ใคร → การกระทำที่รอผู้ขอ (ตอบคำถาม · เหตุผลที่ตีกลับ + แก้ไข + ส่งอีกครั้ง) → ยอดและงบ →
  เส้นทางอนุมัติ → รายการ → รายละเอียด → ไฟล์ → ยกเลิกคำขอ (ท้ายสุด ต้องใส่เหตุผลและติ๊กยืนยัน)
- กล่อง "สิ่งที่ต้องทำ" หายไปเมื่อคำขอปิดแล้ว (ยกเลิก ไม่อนุมัติ เสร็จสิ้น) จึงไม่มีข้อความเก่าค้าง
- ผู้ติดตามเห็นสถานะ ตอนนี้อยู่ที่ใคร และขั้นปัจจุบันเหมือนผู้ขอ แต่ไม่เห็นการกระทำของผู้ขอ
- โครงหน้า: จอกว้างเนื้อหาซ้าย แถบขวา 24rem คือไทม์ไลน์ · มือถือคอลัมน์เดียว ไทม์ไลน์อยู่หลังเส้นทางอนุมัติ
- ผู้ที่ไม่มีสิทธิ์ดู: บอกว่าไม่มีสิทธิ์ และให้ติดต่อผู้ขอหรือผู้ดูแลระบบขององค์กร (สิ่งที่ทำได้จริง) พร้อมลิงก์กลับหน้าแรก

## 2. ตรวจแผนกับรายการ "สิ่งที่ห้ามใช้" ก่อนเขียนโค้ด

| ข้อห้าม | แผนรับมือ |
| --- | --- |
| ไล่สี · สีม่วงเป็นสีหลัก | ใช้ token `primary` `warn` `danger` `info` `ink` `line` `surface` เท่านั้น ไม่มี gradient |
| การ์ดมนเงาเดียวกันทุกใบ · เงาหนา · glass | รายการคั่นด้วยเส้น `border-line` · กล่องมีเฉพาะกล่องตัดสินและตราประทับ ไม่มีเงา |
| ป้ายตัวพิมพ์ใหญ่อังกฤษเหนือหัวข้อ · เน้นคำเดียวในหัวข้อ | หัวข้อใช้ขนาดและน้ำหนักเท่านั้น ไม่มีป้ายเหนือหัวข้อ |
| ตัวเลขลำดับ 01/02 กับสิ่งที่ไม่ใช่ขั้นตอน | "ขั้นที่ n" ใช้เฉพาะขั้นของเส้นทางอนุมัติซึ่งเป็นขั้นตอนจริง · ข้อ DOA ใช้รหัสข้อของฉบับ (PR-01) |
| ลูกศรท้ายปุ่มหรือลิงก์ · monospace | ไม่มีลูกศร ลิงก์เป็นข้อความขีดเส้นใต้ ตัวเลขใช้ tabular-nums ไม่ใช้ monospace |
| animation ตกแต่ง | ใช้แค่ transition สีของปุ่ม 150 ms |
| hero · ภาพประกอบ · emoji | ไม่มี ไอคอนจาก lucide คู่ข้อความเสมอ |
| dashboard ตัวเลขใหญ่ | หน้าแรกเป็นรายการงาน ตัวเลขทุกตัวเป็นลิงก์ไปรายการ |
| สถานะด้วยสีอย่างเดียว | สถานะทุกจุดเป็นไอคอน + ข้อความ · ไทม์ไลน์มี statusLabel · ข้อ DOA ที่เปลี่ยนมีป้ายข้อความ ไม่ใช่สีอย่างเดียว |
| contrast ต่ำ · ตัวอักษรเล็ก | ตัวอักษรรอง `text-base md:text-sm` (16 px มือถือ 14 px เว็บ) สีจาก token ที่ผ่าน 4.5:1 |
| modal ซ้อน · ฟอร์มยาวเกิน 8 ช่อง · error ใน toast | ไม่มี modal · ฟอร์มยาวสุด 3 ช่อง · error อยู่ในหน้าข้างฟอร์ม (`Notice` role=alert) และหายเมื่อแก้ช่อง |
| อนุมัติกับไม่อนุมัติเหมือนกันหรือชิดกัน · ย้อนไม่ได้โดยไม่ยืนยัน | อนุมัติ = primary ทึบ อยู่กล่องบน · ไม่อนุมัติ = ขอบแดง อยู่อีกส่วนพร้อมเหตุผลและติ๊กยืนยัน · อนุมัติยืนยันอีกครั้ง |
| ตารางเลื่อนแนวนอนบนมือถือ | รายการคำขอ งาน และข้อ DOA เป็นแถวที่ซ้อนกันบนมือถือ ไม่มี `<table>` กว้าง |
| ไอคอนเปล่าสำหรับคำสั่งสำคัญ | ทุกปุ่มมีข้อความ |

สิ่งที่แก้หลังดู screenshot รอบแรก: `<dl>` ของยอดเงินมีแถวหัวคอลัมน์อยู่ข้างใน (axe definition-list) → ย้ายหัวคอลัมน์ออกนอก `<dl>` ·
หน้าตัดสินบนมือถือมีข้อมูลผู้ขอซ้ำกับหัวเรื่องจนยอดเงินตกไปใต้จอ → หน้าตัดสินแสดงเฉพาะวันส่งและความเร่งด่วนแบบ 2 คอลัมน์ ยอดเงินจึงอยู่ในจอแรก ·
เส้นคั่นซ้อนสองเส้นใต้รายการ → ตัดเส้นล่างของรายการที่ปิดท้ายส่วน · ปุ่มยกเลิกการยืนยันเดิม "ยังไม่อนุมัติ" อ่านคล้าย "ไม่อนุมัติ" →
เปลี่ยนเป็น "กลับไปตรวจก่อน" · แท็บที่เปิดค้างแล้วกดอนุมัติซ้ำ เดิมยังเห็นปุ่มอนุมัติ → แสดง "ดำเนินการแล้วโดย … เมื่อ …" แล้วโหลดหน้าเป็นสถานะจริง ·
คำอธิบายช่องค้นหาบนมือถืออยู่ใต้ปุ่ม → ย้ายไปใต้ช่องค้นหา · หัวเรื่องการเปลี่ยนนโยบายซ้ำในส่วน "สิ่งที่ขออนุมัติ" → ตัดออก

สิ่งที่แก้หลังการตรวจทาน (adversarial review): ยอดใน "คำขอของฉัน" บนมือถือไม่บอกว่าเป็นยอดอะไร → ป้าย "ยอดรวม VAT (บาท)" ใต้ยอด ·
ยอดเงินในรายละเอียดฟอร์มชิดซ้าย → แสดงแบบยอดเงินชิดขวา tabular-nums · หลังยกเลิกคำขอยังเห็น "ส่งขออนุมัติอีกครั้งแล้ว" ค้าง → กล่อง
"สิ่งที่ต้องทำ" หายเมื่อคำขอปิด · error ของช่องค้างจนกดส่งรอบถัดไป → หายเมื่อแก้ช่อง · ขั้นที่ตีกลับใช้ไอคอนนาฬิกา (อ่านว่า "รอ") →
ไอคอนตีกลับสีเตือนแบบไทม์ไลน์ · คำแนะนำในหน้าไม่มีสิทธิ์ให้ขอเป็นผู้ติดตาม ซึ่งยังทำไม่ได้ → ให้ติดต่อผู้ขอหรือผู้ดูแลระบบ ·
DOA ref เป็นลิงก์ที่ผู้ขอและผู้อนุมัติเปิดแล้วเจอหน้าปฏิเสธ → ลิงก์เฉพาะผู้ที่เปิดได้ คนอื่นเห็นเป็นป้ายข้อความ · งานอนุมัติ DOA ฉบับใหม่
ไม่แสดงข้อและความต่าง (ลิงก์ไปหน้าที่ CEO เปิดไม่ได้) → แสดงความต่าง ทุกข้อ และนโยบายในหน้าตัดสิน ·
งานที่ผู้รักษาการถืออยู่แสดงผู้รักษาการเหมือนเป็นผู้ดำรงตำแหน่ง → "สมหญิง (รักษาการแทน ดำรง · ผู้จัดการฝ่าย ฝ่ายก่อสร้าง)" ·
เวลาที่ค้างนับช่วงที่รอผู้ขอตอบ → ไม่นับ (BR-SLA-03)
