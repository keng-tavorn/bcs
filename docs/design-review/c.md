# Design review — หน่วย c: ผังองค์กร การเปลี่ยนโครงสร้างอำนาจ และ DOA (S2-13)

ขั้นตอนตาม spec §9.9: (1) แผนสั้นต่อหน้า (2) ตรวจแผนกับรายการ "สิ่งที่ห้ามใช้" ก่อนเขียนโค้ด (3) เขียนด้วย token
(4) screenshot 375 px และ 1440 px แล้วตรวจอีกรอบ (5) axe ไม่มี serious หรือ critical · ตารางผลตรวจอยู่ท้ายไฟล์

ผู้ใช้ของทุกหน้าคือ ORG_ADMIN · หน้า DOA และการเปลี่ยนโครงสร้างอำนาจไม่เคยเปลี่ยนอำนาจเอง: ทุกการเปลี่ยนส่งให้ผู้อนุมัติตาม DOA (4 ตา)

## 1. แผนต่อหน้า

### A. `/admin/org` ผังองค์กร: แผนก

- ต้องบอก: แผนกไหนอยู่ใต้แผนกไหน (ผังทั้งองค์กร) รหัส ชนิด และจำนวนศูนย์ต้นทุนของแต่ละแผนก · เพิ่มแผนกใหม่ · แก้ชื่อไทยและอังกฤษ · การย้ายแผนกต้องเสนอผ่านการเปลี่ยนโครงสร้างอำนาจ
- ลำดับความสำคัญ: ผังแผนก → แก้ชื่อรายแผนก → เพิ่มแผนก → ลิงก์เสนอย้ายแผนก
- โครงหน้า: หัวข้อและคำอธิบายหนึ่งบรรทัด · แถบย่อยสามหน้า (แผนก · ศูนย์ต้นทุน · ตำแหน่งและผู้ดำรงตำแหน่ง) เป็นลิงก์ที่บอกหน้าปัจจุบันด้วยเส้นใต้และตัวหนา · จอกว้าง: ผังด้านซ้าย ฟอร์มเพิ่มแผนกด้านขวา 24rem · มือถือ: ผังก่อน แล้วฟอร์ม · ผังเป็นรายการซ้อนตามระดับ ย่อหน้าด้วยเส้นแนวตั้งต่อระดับ ไม่ใช้การ์ด
- แก้ชื่อ: ปุ่ม "แก้ชื่อ <แผนก>" เปิดฟอร์มเล็กในแถวนั้น ปุ่ม "บันทึกชื่อใหม่" และ "ยกเลิก"

### B. `/admin/org/cost-centers` ศูนย์ต้นทุน

- ต้องบอก: ศูนย์ต้นทุนทุกตัว แผนกเจ้าของ ใช้งานอยู่หรือปิดแล้ว · เพิ่ม แก้ชื่อ ปิดและเปิดใช้งานอีกครั้ง · ย้ายแผนกไม่ได้ (ADR-042 ข้อ 5)
- โครงหน้า: รายการด้านซ้าย (รหัส ชื่อ แผนก สถานะเป็นไอคอนคู่ข้อความ) ฟอร์มเพิ่มด้านขวา · มือถือเป็นคอลัมน์เดียว
- ปิดใช้งานย้อนได้จากหน้าเดียวกัน จึงไม่ต้องยืนยัน แต่ข้อความผลบอกวิธีเปิดคืน

### C. `/admin/org/positions` ตำแหน่งและผู้ดำรงตำแหน่ง

- ต้องบอก: ตำแหน่งแต่ละตำแหน่ง ใครดำรงในแผนกไหน ตั้งแต่เมื่อไร และ DOA อ้างถึงหรือมีงานค้างจากตำแหน่งนี้หรือไม่ (ถ้าใช่ เปลี่ยนผู้ดำรงได้เฉพาะการเสนอที่ผ่านการอนุมัติ)
- ลำดับ: ตำแหน่งที่มีอำนาจก่อน (บอกเหตุผลเป็นข้อความคู่ไอคอน) แล้วตำแหน่งที่ไม่มีอำนาจ
- ตำแหน่งที่ไม่มีอำนาจ: ฟอร์ม "กำหนดผู้ดำรงตำแหน่ง" ในแถว และปุ่ม "สิ้นสุดการดำรงตำแหน่งของ <ชื่อ>" ที่ต้องกดยืนยันอีกครั้ง (มีผลทันทีกับคนจริง)
- ตำแหน่งที่มีอำนาจ: ลิงก์ "เสนอแต่งตั้ง…" และ "เสนอสิ้นสุด…" ไปหน้าเสนอพร้อมกรอกตำแหน่งและแผนกไว้ให้

### D. `/admin/org-authority` การเปลี่ยนโครงสร้างอำนาจ

- ต้องบอก: การเปลี่ยนที่กำลังดำเนินการ (รออนุมัติ · อนุมัติแล้วรอมีผล) แล้วประวัติ · ต่อรายการ: สิ่งที่เปลี่ยนเป็นประโยคเดียว (ไม่มีป้ายชนิดเหนือประโยค เพราะประโยคบอกชนิดอยู่แล้ว) สถานะ (ไอคอน + ข้อความ) วันมีผล เหตุผล ผู้เสนอ ผลกระทบ และเส้นทาง (ผู้อนุมัติ ข้อ DOA ที่ใช้ และผลการตัดสิน)
- วันมีผล: มีผลแล้ว → "มีผลแล้วเมื่อ …" (เวลาที่มีผลจริง) · ส่งแบบ "มีผลทันทีเมื่ออนุมัติ" และรีเซ็ตตัวตน → "มีผลทันทีเมื่ออนุมัติ" · รักษาการแทนผู้อื่น → "บันทึกเมื่อผู้มีอำนาจอนุมัติ และเริ่มรักษาการตามเวลาที่กำหนด" · ที่เหลือ → วันเวลาที่กำหนด (ไม่แสดงเวลาที่ส่งราวกับเป็นวันมีผล)
- ผลกระทบ: "งานค้างที่ย้าย N งาน" เมื่อมีผู้ดำรงคนใหม่ · "งานค้าง N งานยังอยู่กับ <ผู้ดำรงเดิม>" เมื่อตำแหน่งว่าง
- ปุ่มหลัก "เสนอการเปลี่ยนโครงสร้างอำนาจ" ด้านบน · หน้าว่างบอกขั้นต่อไปพร้อมปุ่มเดียวกัน
- โครงหน้า: คอลัมน์เดียวกว้างไม่เกิน 56rem รายการคั่นด้วยเส้น ไม่ใช้การ์ด

### E. `/admin/org-authority/new` เสนอการเปลี่ยน

- ขั้นจริง 3 ขั้น (ใช้ตัวเลขขั้นได้เพราะเป็นขั้นตอนจริง): 1 เลือกชนิด 2 กรอกรายละเอียด 3 ตรวจผลกระทบแล้วส่ง
- ขั้น 1: ห้าชนิดเป็นรายการลิงก์พร้อมคำอธิบายหนึ่งบรรทัด
- ขั้น 2: ฟอร์มของชนิดนั้น ไม่เกิน 8 ช่อง (รักษาการแทนผู้อื่นมากที่สุด 7 ช่อง: รักษาการเริ่มตามเวลาเริ่มของตัวเอง จึงไม่มีช่องวันมีผล) · วันมีผล: "มีผลทันทีเมื่ออนุมัติ" หรือ "กำหนดวันและเวลา (เวลาไทย)" · เหตุผลบังคับ
- ขั้น 3: สรุปสิ่งที่จะเปลี่ยน · ผู้ที่ได้อำนาจ · ผู้ที่เสียอำนาจ · งานค้าง: จำนวนที่จะย้ายไปผู้ดำรงคนใหม่ หรือจำนวนที่จะยังอยู่กับผู้ดำรงเดิมเมื่อตำแหน่งว่าง (ไม่บอกว่า "ย้าย" ในเมื่อไม่มีผู้รับ) · ผู้อนุมัติตาม DOA · คำเตือนตำแหน่งว่างแต่ละข้อมีช่องติ๊กของตัวเอง · ปุ่ม "ส่งขออนุมัติ" (ผล "ส่งขออนุมัติแล้ว") และ "กลับไปแก้รายละเอียด"
- วันเวลา: ช่อง datetime-local ของเบราว์เซอร์แสดงปฏิทินตามเบราว์เซอร์ (ค.ศ.) จึงมีบรรทัดใต้ช่องที่บอกเวลาที่เลือกเป็นวันที่ไทย พ.ศ. ("เวลาที่เลือก: 2 พ.ย. 2569 09:00 น. (เวลาไทย)") ก่อนเลือกบอกว่าเป็นเวลาไทย
- ไม่ได้รับคำตอบจากระบบ (เครือข่ายหลุด): ฟอร์มบอกในหน้าว่ายังไม่ได้รับคำตอบ ให้กดอีกครั้ง และใช้ idempotency key เดิม จึงไม่สร้างรายการซ้ำ
- error บอกในหน้า ข้างฟอร์ม ไม่ใช้ toast

### F. `/admin/doa` อำนาจอนุมัติ (DOA)

- ต้องบอก: ทุกฉบับพร้อมสถานะและช่วงเวลามีผล · นำเข้าฉบับใหม่จาก YAML พร้อมเหตุผลการเปลี่ยน · ดาวน์โหลดฉบับใดก็ได้เป็น YAML · ถ้ายังไม่มี DOA บอกว่าฉบับแรกส่งเป็นชุดตั้งต้นให้ผู้มีอำนาจลงนามตามสัญญา
- โครงหน้า: จอกว้างรายการฉบับด้านซ้าย ฟอร์มนำเข้าด้านขวา · มือถือรายการก่อนแล้วฟอร์ม · หน้าว่างบอกให้นำเข้าฉบับแรก

### G. `/admin/doa/[versionId]` รายละเอียดฉบับ

- ต้องบอก: สถานะ ช่วงเวลามีผล เหตุผลการเปลี่ยน ผู้นำเข้า ผู้ส่ง ผู้อนุมัติ · สิ่งที่เปลี่ยนจากฉบับก่อนหน้า (diff) · ข้อของฉบับแยกตามประเภทเอกสาร (ช่วงวงเงิน ผู้อนุมัติ SLA) · นโยบายของฉบับ · ตารางผลที่ขอบ · ฉบับร่าง: ผลตรวจ (error แยกรหัสและช่วงที่ผิด · warning ติ๊กทีละข้อ) และปุ่มส่ง · องค์กรที่ยังไม่มี DOA: ชุดตั้งต้นสองขั้น (แผน H)
- ฉบับที่เผยแพร่แล้วไม่มีปุ่มแก้ใด ๆ (แก้ได้ด้วยการนำเข้าฉบับใหม่เท่านั้น)
- โครงหน้า: จอกว้างเนื้อหาด้านซ้าย (diff ข้อ นโยบาย) แถบขวา (สถานะ วันมีผล ผู้เกี่ยวข้อง ดาวน์โหลด และการส่ง) ตาม §9.9 "หน้าเอกสาร" · มือถือ: หัวข้อ สถานะ การส่ง แล้วเนื้อหา
- เงินชิดขวา `tabular-nums` ทศนิยม 2 ตำแหน่ง · ตารางข้อเป็นรายการที่จัดคอลัมน์ด้วย grid บนจอกว้าง จึงไม่มีการเลื่อนแนวนอนบนมือถือ

### H. ชุดตั้งต้นขององค์กร (ในหน้า G เมื่อองค์กรยังไม่มี DOA · BR-DOA-19)

- ต้องบอก: ฉบับแรกส่งพร้อมรายชื่อผู้ดำรงตำแหน่งที่ฉบับอ้าง ให้ผู้มีอำนาจลงนามตามสัญญา (ชื่อ) อนุมัติ · รายชื่อเริ่มจากผู้ดำรงปัจจุบัน · ตำแหน่งที่ฉบับอ้างแต่ยังไม่มีในรายชื่อ · เหตุผล · คำเตือนที่ต้องติ๊กทีละข้อ (ถ้าบริการตอบมา)
- ขั้นจริง 2 ขั้น (เดิมเป็นหน้าเดียวที่มี select 3 ช่องต่อแถว × 8 แถว = 24 ช่อง ขัดกฎ 8 ช่อง): (1) ตรวจรายชื่อผู้ดำรงตำแหน่ง: รายการหนึ่งบรรทัดต่อคน (ชื่อ · ตำแหน่ง ของ แผนก) กับปุ่ม "แก้ <ตำแหน่ง ของ แผนก>" หนึ่งปุ่ม · แก้ เพิ่ม หรือนำออกได้ทีละแถวในตัวแก้ 3 ช่อง (ตำแหน่ง แผนก ผู้ดำรง) · ปุ่ม "ถัดไป: ใส่เหตุผลและส่ง" (2) เหตุผลและการส่ง: จำนวนผู้ดำรงในชุด ปุ่มกลับไปแก้รายชื่อ ช่องเหตุผล คำเตือน และปุ่ม "ส่งชุดตั้งต้นให้ผู้มีอำนาจลงนามอนุมัติ"
- error ของแถว (ตำแหน่งซ้ำ ตำแหน่งที่ฉบับไม่อ้าง ใส่ตัวเอง) กลับไปขั้น 1 ที่แถวนั้น · ผู้ดำรงที่ขาดกลับไปขั้น 1 พร้อมรายชื่อตำแหน่งที่ขาด · lint และคำเตือนอยู่ขั้น 2
- เปลี่ยนขั้นแล้วโฟกัสไปหัวข้อของขั้น (คีย์บอร์ดและโปรแกรมอ่านหน้าจอตามได้)

## 2. ตรวจแผนกับรายการ "สิ่งที่ห้ามใช้" (ก่อนเขียนโค้ด)
