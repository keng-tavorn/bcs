# Design review — หน่วย i: กระดานเอกสารค้าง บันทึกการตรวจสอบ รายงาน และ KPI (S4-10 · S4-11 · S5-12 · ฉาก demo 9)

ขั้นตอนตาม spec §9.9: (1) แผนสั้นต่อหน้า (2) ตรวจแผนกับรายการ "สิ่งที่ห้ามใช้" ก่อนเขียนโค้ด (3) เขียนด้วย token
(4) screenshot 375 px และ 1440 px แล้วตรวจอีกรอบ (5) axe ไม่มี serious หรือ critical · ตารางผลตรวจต่อหน้าอยู่ท้ายไฟล์

หลักที่ใช้: งานของฉันก่อน (หลัก 1 — กระดานเริ่มจากคนที่มีงานเกินกำหนด) · สถานะแบบติดตามพัสดุ (หลัก 4 — บอกชื่อคนที่ถือและ
ค้างมากี่ชั่วโมงทำการ) · ตัวเลขอ่านง่าย (หลัก 6 — ตัวเลขชิดขวา tabular-nums) · ปุ่มบอกผล (หลัก 7) · หน้าว่างบอกขั้นต่อไป
(หลัก 8) · และข้อห้าม "dashboard ตัวเลขใหญ่ที่ไม่พาไปทำงานต่อ": ทุกตัวเลขบนกระดานและหน้า KPI เป็นลิงก์ไปรายการที่นับ

## 1. แผนต่อหน้า

### A. `/board/pending` เอกสารค้างที่ใคร (board.pending.view · FR-VIS-001 AC1)

- ต้องบอก: ใครถือเอกสารที่รอตัดสิน กี่ฉบับ เกินกำหนด (SLA) กี่ฉบับ รอผู้ขอตอบกี่ฉบับ ค้างนานสุดและเฉลี่ยกี่ชั่วโมงทำการ ·
  ขอบเขตที่เห็น (ทั้งองค์กร / คำขอที่ตั้งเบิกแผนกที่ดูแล ตาม docs/sub-specs/S4.md / ของตัวเอง) · นับเวลาถึงเมื่อไร
- ลำดับ: หัวข้อ + ประโยคบอกว่าหน้านี้ทำอะไร + บรรทัดขอบเขต + "นับเวลาถึง … · ดูตัวเลขล่าสุด" → ตัวกรอง (GET: แผนกของ
  ผู้รับงาน · ชนิดเอกสาร · ปุ่ม "แสดงตามตัวกรอง" · "ล้างตัวกรอง") → "ผู้ที่มีเอกสารค้าง n คน" + คำแนะนำ "กดชื่อหรือตัวเลข…"
  → ตาราง/รายการ (คนที่มีเอกสารเกินกำหนดก่อน แล้วค้างนานสุด)
- โครงหน้า: จอกว้าง (≥ 1024 px) เป็นตารางจริง (caption, หัวคอลัมน์, ชื่อเป็นหัวแถว) ตัวเลขชิดขวา · มือถือเป็นรายการ ชื่อเป็นลิงก์
  แล้วคู่ ป้าย–ตัวเลข ไม่มีตารางที่เลื่อนแนวนอน
- สถานะ: เกินกำหนดเป็นไอคอนวงกลมตกใจ + ตัวเลขสี danger + คำ (sr-only) "เกินกำหนด" และหัวคอลัมน์ "เกินกำหนด (SLA)" ·
  รอผู้ขอตอบเป็นไอคอนคำถาม + คำ
- ทุกตัวเลขเป็นลิงก์ไปหน้าเอกสารของคนนั้น (aria-label บอก "เกินกำหนด 2 ฉบับที่ วีระ ปฏิบัติการ: ดูเอกสาร")
- หน้าว่าง: ไม่มีเอกสารค้าง → บอกว่าจะขึ้นเมื่อไร + ลิงก์ "ไปที่งานรออนุมัติ" · กรองแล้วไม่พบ → บอกให้เปลี่ยนตัวกรอง + "ล้างตัวกรอง"
- ไม่มีสิทธิ์ (บัญชีไม่ใช้งาน): ข้อความ + ลิงก์กลับหน้าแรก

### B. `/board/pending/[memberId]` เอกสารที่ค้างที่ <ชื่อ> (FR-VIS-001 AC2)

- ต้องบอก: เอกสารแต่ละฉบับ (เลขที่ + เรื่อง เป็นลิงก์ไปหน้าเอกสาร หรือหน้าตัดสินถ้าเป็นงานของผู้อ่านเอง) · ชนิดและเวลามอบงาน ·
  ค้างมากี่ชั่วโมงทำการ · ครบกำหนด/เกินกำหนดเมื่อไร หรือ "รอผู้ขอตอบคำถาม" · ปุ่มส่งเตือนและกติกา "ชั่วโมงละครั้งต่อเอกสาร"
- ลำดับ: "กลับไปกระดานเอกสารค้าง" → หัวข้อ "เอกสารที่ค้างที่ <ชื่อ>" → สรุป (รอตัดสิน / เกินกำหนด / รอผู้ขอตอบ · ค้างนานสุด
  และเฉลี่ย) → กติกาการเตือน → รายการ (เก่าสุดก่อน)
- ปุ่ม "ส่งเตือน <ชื่อ>" เป็นปุ่มรอง (ไม่ใช่การกระทำหลักของหน้า) ชื่อเต็มสำหรับโปรแกรมอ่านจอ "ส่งเตือน <ชื่อ> เรื่อง <เอกสาร>"
  · ผล: "ส่งเตือนแล้วเมื่อ … · ส่งเตือนเอกสารนี้ได้อีกครั้งหลัง …" · ภายในชั่วโมงเดียวกัน: ปฏิเสธเป็นคำ "ยังส่งเตือนไม่ได้ เพราะมีคน
  เตือนเอกสารนี้ไปแล้วภายใน 1 ชั่วโมง ส่งเตือนได้อีกครั้งหลัง …" ข้างปุ่ม (ไม่ใช่ toast) · เอกสารที่รอผู้ขอตอบไม่มีปุ่ม
- การเตือนย้อนไม่ได้แต่ไม่ทำลายอะไร (ส่งข้อความหนึ่งฉบับ) จึงไม่ถามซ้ำ — ปุ่มบอกชัดว่าจะส่งถึงใคร
- ปุ่มมีเฉพาะงานที่ผู้อ่านส่งเตือนได้จริง (service ตรวจซ้ำ): ผู้ตรวจสอบอ่านอย่างเดียว (BR-AUTH-04) จึงไม่มีปุ่มกับเอกสารที่เห็น
  ในฐานะผู้ตรวจสอบ และมีประโยคใต้กติกาบอกเหตุผล · ถ้าระบบไม่ว่าง (ไม่ใช่กติกาชั่วโมงละครั้ง) ข้อความบอกให้รอสักครู่แล้วกดใหม่
  ไม่ใช่ "มีคนเตือนไปแล้ว"

### C. `/audit` บันทึกการตรวจสอบ (audit.view · FR-VIS-004 · FR-DOA-005 AC3)

- ต้องบอก: เหตุการณ์ตามเงื่อนไข ใหม่ไปเก่า หน้าละ 100 · เวลา ลำดับที่ (ตรงกับคอลัมน์ seq ของไฟล์) เหตุการณ์เป็นคำไทย (การตัดสิน
  ต่อท้ายผล "อนุมัติ" / "ไม่อนุมัติ") เอกสาร (เลขที่ เป็นลิงก์ถ้าผู้อ่านเปิดได้) ผู้กระทำและ "ทำแทน …" ช่องทาง และ DOA ที่อ้าง
  "DOA-DEMO ฉบับ 1 ข้อ PR-02"
- ลำดับ: หัวข้อ + ประโยคบอกว่าบันทึกอะไร → ฟอร์มค้นหา (เลขที่เอกสาร · ผู้กระทำ · ประเภทเหตุการณ์จัดกลุ่มตามเรื่อง · ช่องทาง ·
  ตั้งแต่วันที่ · ถึงวันที่ = 6 ช่อง) ปุ่ม "ค้นหาบันทึก" + "ล้างเงื่อนไข" → ส่งออกผลการค้นหานี้ (ผู้ตรวจสอบเท่านั้น: "ส่งออก
  Excel" "ส่งออก CSV" และคำอธิบายว่าไฟล์มีคอลัมน์อะไรและการส่งออกถูกบันทึก · ผู้ดูแลองค์กรเห็นประโยคว่าส่งออกได้เฉพาะผู้ตรวจสอบ)
  → ผลการค้นหา (จำนวน · ตาราง/รายการ · "ดูรายการที่เก่ากว่า" "กลับไปรายการล่าสุด")
- โครงหน้า: จอ ≥ 1280 px เป็นตาราง 6 คอลัมน์ (เหตุการณ์เป็นหัวแถว) · ต่ำกว่านั้นเป็นรายการ: เหตุการณ์ตัวหนา เวลา·ลำดับ แล้วคู่
  ป้าย–ค่า (เอกสาร ผู้กระทำ ช่องทาง DOA) ไม่เลื่อนแนวนอน
- ผลส่งออก: "ส่งออกแล้ว n แถว ไฟล์กำลังดาวน์โหลด" + "ค่าตรวจสอบไฟล์ (SHA-256): …" (ตัดบรรทัดได้ ไม่ใช้ monospace) + ปุ่มลิงก์
  "ดาวน์โหลดไฟล์นี้อีกครั้ง" · error ข้างปุ่มเป็นคำบอกวิธีแก้ (เกิน 50,000 แถว → ให้ทำเงื่อนไขให้แคบลง)
- หน้าว่าง: ยังไม่มีบันทึก → บอกว่าจะขึ้นเมื่อมีการทำเอกสาร · ค้นแล้วไม่พบ → "ไม่พบบันทึกของเอกสาร …" + วิธีแก้ + "ล้างเงื่อนไข"
- ค้นตามเลขที่เอกสาร: ได้ทั้งเหตุการณ์ของเอกสาร การตัดสิน และการจอง ถือ หรือคืนงบที่อ้างเอกสารนั้น (แถวบอก "บรรทัดงบ …")
- เมื่อกรองช่วงวันที่ ใต้หัวข้อผลการค้นหามีบรรทัด "ช่วง 6 ส.ค. 2569 ถึง 4 ต.ค. 2569" เป็น พ.ศ. เสมอ เพราะช่องวันที่ของเบราว์เซอร์
  อาจแสดง ค.ศ.
- ไม่มีสิทธิ์ (เช่น CEO): ข้อความว่าเปิดได้เฉพาะผู้ตรวจสอบและผู้ดูแลองค์กร + ติดต่อใคร

### D. `/reports` รายงาน (report.view · FR-VIS-002 AC1 AC3)

- ต้องบอก: รายงานที่ระบบมี (KPI ตอนนี้) · รายงาน 7 ฉบับของข้อเสนอเดิมรอรายชื่อจากลูกค้า (ไม่เดา) · ขอบเขตที่รายงานอ่าน (ทั้งองค์กร /
  แผนกที่ดูแล) · ตัวกรอง (ช่วงวันที่) · ผลเป็นตาราง · ส่งออก Excel พร้อมค่าตรวจสอบ · การส่งทางอีเมลตามรอบ (FINANCE EXECUTIVE)
- ลำดับ: หัวข้อ + ประโยค + บรรทัดขอบเขต → "รายงานที่มี" (รายการคั่นเส้น ชื่อเป็นลิงก์ ฉบับที่เปิดอยู่มี aria-current) + ประกาศเรื่อง
  R-01 ถึง R-07 → ชื่อรายงาน + ตัวกรอง (GET) + บรรทัด "ช่วง … · ขอบเขต · อ่านเมื่อ" + ตาราง + ลิงก์ไปหน้า KPI (เฉพาะผู้เห็นทั้ง
  องค์กร) + ส่งออก → ส่งรายงานทางอีเมลตามรอบ (รายการรอบที่ตั้งไว้ + ฟอร์ม 4 คำถาม: รายงาน ส่งเมื่อไร ไฟล์แบบ ส่งถึง)
- ตาราง: จอ ≥ 768 px เป็นตาราง (สิ่งที่วัดเป็นหัวแถว ตัวเลขชิดขวา) · มือถือเป็นรายการ "G-5 · สิ่งที่วัด" แล้วคู่ ป้าย–ค่า · ค่าที่
  ยังคำนวณไม่ได้เป็นขีดที่โปรแกรมอ่านจออ่านว่า "ยังคำนวณไม่ได้"
- ผู้รับอีเมลเลือกได้เฉพาะผู้ที่ดูรายงานทั้งองค์กรได้เอง (บอกเหตุผลใต้หัวข้อ) · ปุ่ม "ตั้งส่งรายงานทางอีเมล" · ผล "ตั้งส่งรายงานแล้ว:
  ทุกวันจันทร์ 08:00 น. ถึงผู้รับ 1 คน" · error ข้างฟอร์ม · service ตรวจกติกาเดียวกันทั้งตอนตั้งและทุกรอบที่ส่ง (ผู้ที่เสียสิทธิ์
  ไม่ได้รับไฟล์อีก) · ถ้าผู้รับบางคนดูรายงานเองไม่ได้แล้ว ข้อความบอกให้โหลดหน้าใหม่แล้วเลือกจากรายชื่ออีกครั้ง
- หัวคอลัมน์มาจากข้อความของหน้าจอ (ไทย/อังกฤษ) · เวลาเป็นชั่วโมงทำการทศนิยมหนึ่งตำแหน่งเหมือนหน้า KPI · จำนวนมีหน่วย "รายการ" ·
  ไฟล์ Excel/CSV มีชื่อสิ่งที่วัดเป็นไทยแบบเดียวกับหน้าจอ หน่วย และรหัส (สองคอลัมน์หลังอยู่ในไฟล์เท่านั้น)
- ไม่มีสิทธิ์: บอกว่าหน้ารายงานสำหรับใคร และให้ติดต่อหัวหน้าแผนก

### E. `/kpi` ตัวชี้วัด (report.view ขอบเขตทั้งองค์กร · FR-VIS-003 AC2 AC3)

- ต้องบอก: G-1 ถึง G-5 ของช่วงที่เลือก (เริ่มที่ 60 วันของรอบรีวิว) · แต่ละตัว: ชื่อ สูตรเป็นคำ ค่าในช่วงนี้ (สัดส่วนพร้อม "x จาก y"
  เวลาเป็นชั่วโมงทำการ จำนวน) ค่าตั้งต้นจาก Phase 0 (ยังไม่ได้บันทึก — บอกตรง ๆ ไม่สร้างตัวเลขเอง) และเป้าที่เสนอใน spec · G-5 รวม
  และแยกตามชนิดเอกสาร · ส่งออก CSV ของช่วง
- ลำดับ: หัวข้อ + ประโยค + "ช่วง … ถึง … (60 วัน)" + เวลาที่อ่าน → ตัวเลือกช่วง (GET) → ประกาศ "ยังไม่มีค่าตั้งต้นให้เทียบ" →
  "ตัวชี้วัดในช่วงนี้" (ตาราง: กลุ่มตามเป้าหมาย G-1 … G-5 เป็นหัวกลุ่ม · คอลัมน์ ตัวชี้วัดและสูตร / ค่าในช่วงนี้ / ค่าตั้งต้น / เป้าที่
  เสนอ) → ส่งออกสำหรับรอบรีวิว 60 วัน
- ไม่ใช่ dashboard ตัวเลขใหญ่: ค่าเป็นขนาดตัวอักษรปกติ ตัวหนา อยู่ในตาราง และทุกค่าเป็นลิงก์ไป `/kpi/<ตัวชี้วัด>` (aria-label บอก
  ชื่อ ค่า และ "x จาก y") ยกเว้นค่าที่ไม่มีอะไรอยู่เบื้องหลัง (สัดส่วนที่ไม่มีตัวหาร มัธยฐานที่ไม่มีข้อมูล จำนวนที่เป็น 0) ซึ่งเป็นข้อความธรรมดา · ไม่มีกราฟ
- ค่าตั้งต้น: อ่านจากที่เดียว `kpiBaseline()` ซึ่งยังไม่มีค่าเพราะที่เก็บและผู้บันทึกรอผู้ใช้ตัดสิน (NEW-36) · เมื่อมีค่า แต่ละแถวแสดง
  "25.0% (วัดเมื่อ 30 มิ.ย. 2569)" ในหน่วยของตัวชี้วัดนั้น · แถว G-5 แยกตามชนิดเอกสารเทียบกับค่าตั้งต้นของชนิดนั้นเท่านั้น ·
  สัดส่วนที่ไม่มีตัวหารไม่แสดงเป็น 0.0%
- มือถือ: ส่วนต่อเป้าหมาย หัวข้อพื้น surface แล้วรายการตัวชี้วัด แต่ละตัวมีสูตรและคู่ ป้าย–ค่า
- ไม่มีสิทธิ์: หัวหน้าแผนกได้ข้อความว่า KPI เป็นตัวเลขทั้งองค์กร + ลิงก์ "ไปที่หน้ารายงาน" (รายงาน KPI ของแผนก) · คนอื่นได้ข้อความว่า
  หน้านี้สำหรับใคร

### F. `/kpi/[measure]` รายการที่นับในตัวชี้วัด

- ต้องบอก: ชื่อตัวชี้วัดและสูตร · ช่วง · "นับ x จาก y รายการ" · เอกสารแต่ละรายการ (ลิงก์) ใครตัดสินหรือถือ ทำแทนใคร เมื่อไร
  ช่องทาง DOA ที่อ้าง และนับหรือไม่นับเพราะอะไร (ไอคอน + คำ)
