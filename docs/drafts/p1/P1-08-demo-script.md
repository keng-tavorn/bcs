### 3.3 สิ่งที่ `validate_inputs.py --profile p1` ตรวจ

ย้ายแนวจากส่วน "สคริปต์ demo" ของ profile demo (`validate_inputs.py:376-397`) มาใช้กับข้อมูลระยะ 1 · ทุกข้อเป็น PASS หรือ FAIL พร้อมวิธีแก้แบบเดิม

1. ทุกรหัสที่แถวอ้าง (ผู้ใช้ ประเภทคำขอ แผนก budgetKey สถานที่ ผู้ขาย รายการ historyRef docSample) มีในชีต
2. `net` = `qty × unitPrice` · `vat` และ `gross` ตามอัตราใน Settings ปัดตาม BR-MONEY-02 · ผู้ขายที่ไม่จด VAT มี VAT 0 (BR-VAT-04)
3. เส้นทาง DOA ของทุกฉากที่ส่งเอกสาร: ใช้ตัวคำนวณ `route()` ที่ validator มีแล้ว ขยายให้รับชนิดเอกสาร BUDGET_TRANSFER OVER_BUDGET INVOICE_EXCEPTION PAYMENT_RUN และ WORKFLOW ตามชีต DOA ฉบับ 1 · ผลต้องตรง `expectedRule` `expectedApprover`
4. ผู้ตรวจคู่ขนาน: เงื่อนไข `whenJson` ของชีต Workflow_Reviewers กับยอดของฉาก ตามฉบับที่มีผลตามลำดับฉาก (ฉาก 3 เปลี่ยนเกณฑ์) · ผลต้องตรง `expectedReviewers`
5. คำขอซ้ำและแตกยอด: ฉากที่ area ไม่ใช่ `DUPLICATE` ต้องไม่ชนประวัติตามกฎ BR-DUP-03 และ BR-DUP-04 ภายใน `duplicateCheck.windowDays` (ข้อ 1.1) · ฉาก `DUPLICATE` ชนเฉพาะใบแรกของฉากเอง
6. งบพอเรียงตามลำดับฉาก รวมผลของฉากโอนงบ (ฉาก 4 เพิ่ม P07-SUB · ลด P07-RENT) · ฉาก `OVER_BUDGET` ต้องขาดจริง
7. ใบแจ้งหนี้: `historyRef` เป็นแถวที่ตรวจรับแล้วและยังไม่มีใบ (`invoiceScenario = MISSING`) และไม่ใช่ H065 · `invoiceNo` ไม่ซ้ำเลขเดิมของผู้ขายเดียวกัน · ฉากอีเมลใช้ผู้ขายที่ `eTaxIssuer = FULL` · ส่วนต่างราคาเทียบเกณฑ์ `matching.priceTolBp` และ `matching.priceTolAmount` ด้วยสูตรเดียวกับ `src/core/matching` (คำนวณอิสระใน validator)
8. ภาษีหัก: อัตราจาก WHT_Types ตาม `whtIncomeType` ของผู้ขายหรือรายการ · ยอดไม่ถึง `wht.minimumBase` ไม่หัก · `expectedTransfer` = ยอดที่ต้องจ่าย − ภาษีหัก (− เงินประกันผลงานถ้าเป็นงานจ้างเหมา)
9. ฉาก AI: `docSample` มีไฟล์ใน `tests/fixtures/ai-docs/manifest.json` และมีคำตอบที่บันทึกไว้ของ purpose นั้น · ยอดของแถวตรงชีต DocSamples
10. เรื่องที่ขึ้นกับปีงบ (ฉาก 6 และ 14): ตรวจกับวันที่รันว่ายังจริง ถ้าไม่จริงให้ FAIL พร้อมบอกว่าเกิดจากปีงบ (ข้อ 1.5)
11. ทุกหัวข้อในรายการของ P1-08 มีอย่างน้อยหนึ่งฉาก core = Y
