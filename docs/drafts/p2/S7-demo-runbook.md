# Runbook ย่อ ฉาก demo ของ S7 ผู้ขายและพอร์ทัล (ร่าง S7-17 · ADR-191)

ร่างของขั้นในสาย l1 · ข้อมูลทุกตัวมาจาก `docs/inputs/BCS_inputs_p1.xlsx` ชีต `Demo_Script_P2` (แถวของ S7 สร้างจาก `scripts/inputs_p1/p1_suppliers_portal.py`) · e2e ของฉากอยู่ที่ `tests/e2e/p2demo/` แท็ก `@p2demo`

## ก่อนวัน demo

1. ล้างและ seed ด้วยไฟล์ระยะ 1: `pnpm db:reset:p1` (SIMEC · โมดูล SUPPLIER เปิดใน profile p1 · ประวัติคำขอ การจ่าย และใบสมัครผู้ขาย 9 ใบ)
2. `pnpm inputs:check` ผ่าน (บรรทัด "เอกสารใกล้หมดอายุภายใน 30 วัน: 12 ราย" และ "G-7 มัธยฐาน 3.6 วันทำการ")
3. เปิด Mailpit (`http://localhost:8025`) ไว้หนึ่งแท็บ: อีเมลเชิญ รหัส 6 หลัก และอีเมลเตือนของผู้ขายไปที่นี่
4. มือถือหรือหน้าต่าง 375 px สำหรับฝั่งผู้ขาย · เดสก์ท็อปสำหรับฝั่งภายใน · ผูก LINE ของ `dm_proc` ก่อนเริ่ม (การ์ดอนุมัติในแชทต้องการ token ที่ออกตอนมอบงาน)
5. ทดสอบทั้งชุดก่อนวัน: `pnpm test:e2e --grep @p2demo` (ฐาน `bcs_e2e_p2demo` ของตัวเอง ไม่ต่อจาก `@p1demo`)

## ถ้าติด

- รหัส 6 หลักไม่มาที่ Mailpit: งานส่งแจ้งผู้ขาย (Inngest dev) ไม่ทำงาน · เปิด `pnpm dev` พร้อม Inngest dev ก่อน
- การ์ดไม่มาที่ LINE ของ `dm_proc`: ผูก LINE หลังมอบงานแล้ว · ยกเลิกแล้วส่งเข้าเส้นทางใหม่ หรืออนุมัติบนเว็บ
- ทะเบียนยืนยันผู้ขายไม่ได้ (โหมด stub): แนบหลักฐานแล้วกดอีกครั้งตาม BR-SUP-03
