| 4 | rate limit ของการเพิ่ม passkey นับก่อน `runCommand` จึงปฏิเสธการส่งซ้ำด้วย key เดิมหลังคำตอบหาย และนับซ้ำสองครั้งต่อการเพิ่ม | แก้: นับที่จุดเริ่มพิธี (ขอ options) เท่านั้น |
| 5 | schema บอกว่ามี job รายชั่วโมงลบ challenge เก่า แต่ไม่มี | แก้ข้อความ: ลบแถวเก่ากว่า 1 วันของ member ตอนออก challenge ใหม่ให้คนนั้น |
| 6 | ขอ challenge ของการตัดสินงานได้ไม่จำกัด | แก้: ไม่เกิน 30 ครั้งต่อนาทีต่อ member (`RATE_LIMITED`) พร้อมเทสต์ |
| 7 | พารามิเตอร์ `channel` `requestId` `correlationId` ของ `grantStepUpByPasskey` ไม่ได้ใช้ | แก้: เอาออก |
| 8 | comment ค้างเหนือ `TX_OPTIONS` | แก้: เอาออก |
| 9 | ฟอร์มพิสูจน์ตัวตนของ passkey เขียนซ้ำกับของ PIN | ไม่แก้: แยกเป็นคอมโพเนนต์ร่วมในรีวิวท้ายขั้น (S17-18) ถ้ายังมีเวลา เพราะต้องแตะหน้าตั้ง PIN เดิมและเทสต์ของมัน |
| 10 | ขั้นของ e2e ที่ไม่ยืนยันผู้ใช้ไม่ได้รอคำปฏิเสธของอุปกรณ์ | แก้: รอคำตอบของ server action แล้วจึงตรวจ |
| 11 | หน้า `/tasks/[id]` อ่านว่ามี passkey หลังข้อมูลอื่น | ไม่แก้: query เดียวที่เล็ก |

ตรวจเพิ่มโดยไม่พบปัญหา: ไม่มี endpoint passkey ใต้ `/api/auth/*` (เทสต์ยิงแล้วได้ 404) · เพิ่ม passkey ต้องมีหลักฐานพิสูจน์ตัวตนสดทั้งตอนขอ options และตอนเพิ่ม · challenge ใช้ครั้งเดียวและผูกกับ member และเอกสาร · assertion จาก origin หรือ RP ID อื่น ลายเซ็นผิด ไม่มี UV credential ของคนอื่น หมดอายุ หรือใช้แล้ว ไม่ได้ grant (เทสต์ทีละข้อด้วย authenticator ในเทสต์) · grant แบบเดียวกับ PIN (เอกสารเดียว 5 นาที ใช้ครั้งเดียว แล้วเปลี่ยน session id) · ทุกชนิดเอกสารที่ต้อง step-up รับ passkey และ PIN ยังใช้ได้ · `IDENTITY_RESET` ทั้งสองทางและการปิดใช้งานเพิกถอน passkey ในธุรกรรมเดียวกัน
