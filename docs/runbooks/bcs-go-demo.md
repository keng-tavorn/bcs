## ค่าที่จะได้และใส่ที่ไหน

ใส่ค่าทันทีที่ได้ในแต่ละขั้น · **Vercel** คือ project `bcs-staging` → **Settings** → **Environment Variables** environment **Production** (วิธีอยู่ในหัวข้อ "วิธีเพิ่ม environment variable ใน Vercel" ของ [p0-08-vercel.md](p0-08-vercel.md)) · **GitHub** คือ repo → **Settings** → **Secrets and variables** → **Actions** ระดับ repository (แท็บ **Secrets** ปุ่ม **New repository secret** · แท็บ **Variables** ปุ่ม **New repository variable**) ไม่ใช่ environment `staging` ของ [github-setup.md](github-setup.md) เพราะงานสร้าง APK ไม่ได้ผูกกับ environment

| ค่า | ใส่ที่ | ได้จาก |
| --- | --- | --- |
| `PUSH_PROVIDER` = `fcm` | Vercel | พิมพ์เอง |
| `FCM_PROJECT_ID` | Vercel | ส่วนที่ 1 ข้อ 3 |
| `FCM_SERVICE_ACCOUNT_JSON_B64` | Vercel · ค่าลับ | ส่วนที่ 1 ข้อ 6 |
| `BCS_GO_GOOGLE_SERVICES_JSON_B64` | GitHub · secret | ส่วนที่ 1 ข้อ 5 |
| `BCS_GO_KEYSTORE_B64` `BCS_GO_KEYSTORE_PASSWORD` `BCS_GO_KEY_ALIAS` `BCS_GO_KEY_PASSWORD` | GitHub · secret | ส่วนที่ 2 |
| `BCS_GO_SERVER_URL` | GitHub · variable (ไม่ใช่ secret) | ส่วนที่ 3 |
| `BCS_GO_ANDROID_PACKAGE` = `th.bcs.go` | Vercel | พิมพ์เอง |
| `BCS_GO_ANDROID_CERT_SHA256` | Vercel | ส่วนที่ 4 ข้อ 5 |

บนเครื่องของคุณไม่ต้องใส่ค่าเหล่านี้ใน `.env` เทสต์ e2e ใช้ fake FCM ของเครื่อง (`PUSH_PROVIDER=fake`) เอง ถ้าจะลอง push จากเว็บบนเครื่องกับมือถือจริง ให้ใส่ `PUSH_PROVIDER` `FCM_PROJECT_ID` และ `FCM_SERVICE_ACCOUNT_JSON_B64` ใน `.env` ด้วยค่าเดียวกับข้างบน

## ส่วนที่ 1 · Firebase project ของ BCS (push · ADR-165)

1. เปิด <https://console.firebase.google.com/> แล้ว login ด้วยบัญชี Google ของบริษัท
2. กด **Create a project** (หรือ **Add project**) ตั้งชื่อ `bcs-go-demo` · หน้า Google Analytics เลือก **ไม่เปิด** (demo ไม่ใช้) แล้วกด **Create project**
3. เปิด project → ไอคอนเฟือง **Project settings** → แท็บ **General** → คัดลอก **Project ID** (เช่น `bcs-go-demo` หรือมีตัวเลขต่อท้าย) → `FCM_PROJECT_ID`
4. แท็บเดียวกัน ส่วน **Your apps** → กดไอคอน Android → **Android package name:** `th.bcs.go` (พิมพ์ให้ตรงทุกตัว เป็นค่า `appId` ของ `mobile/bcs-go/capacitor.config.ts`) · App nickname `BCS Go demo` · ช่อง SHA-1 เว้นได้ → **Register app**
5. กด **Download google-services.json** แล้วแปลงเป็น base64 ด้วย PowerShell ที่โฟลเดอร์ที่ดาวน์โหลดไฟล์ไว้ (ค่าไปอยู่ใน clipboard ไม่แสดงบนจอ):
   ```powershell
   [Convert]::ToBase64String([IO.File]::ReadAllBytes("$PWD\google-services.json")) | Set-Clipboard
   ```
   วางใน GitHub secret `BCS_GO_GOOGLE_SERVICES_JSON_B64` · ขั้นที่เหลือของหน้า Firebase (เพิ่ม SDK) กด **Next** ข้ามได้ แอปมี plugin แล้ว
6. **Project settings** → แท็บ **Service accounts** → **Generate new private key** → **Generate key** ได้ไฟล์ JSON แปลงเป็น base64 แบบเดียวกับข้อ 5 (เปลี่ยนชื่อไฟล์ในคำสั่ง) แล้ววางใน Vercel `FCM_SERVICE_ACCOUNT_JSON_B64` · ไฟล์นี้คือกุญแจส่ง push ของทั้ง project
7. แท็บ **Cloud Messaging** ตรวจว่า **Firebase Cloud Messaging API (V1)** เป็น **Enabled** (project ใหม่เปิดให้แล้ว) ถ้าเป็น Disabled ให้กดเมนูสามจุดแล้ว **Manage API in Google Cloud Console** → **Enable**
8. ใส่ `PUSH_PROVIDER` = `fcm` ใน Vercel · ลบไฟล์ JSON ทั้งสองไฟล์ออกจากเครื่องเมื่อใส่ค่าครบแล้ว (เก็บสำเนาในโปรแกรมจัดการรหัสผ่านได้)

## ส่วนที่ 2 · keystore ของ demo (ลายเซ็นของ APK)

APK ทุกตัวต้องเซ็นด้วย keystore เดิม ถ้าทำหาย แอปที่ติดตั้งไว้อัปเดตไม่ได้ ต้องถอนแล้วติดตั้งใหม่ และ passkey ในแอปต้องลงทะเบียนใหม่ จึงเก็บไฟล์และรหัสไว้ในโปรแกรมจัดการรหัสผ่าน

1. ติดตั้ง Java (ถ้ายังไม่มีคำสั่ง `keytool`) ใน PowerShell: `winget install EclipseAdoptium.Temurin.21.JDK` แล้วปิดและเปิด PowerShell ใหม่
2. ไปที่โฟลเดอร์นอก repo เช่น `cd $HOME\Documents` แล้วสร้าง keystore (ระบบจะถามรหัสผ่านสองครั้ง และชื่อ หน่วยงาน ประเทศ ให้ตอบตามจริง ประเทศใส่ `TH`):
   ```powershell
   keytool -genkeypair -v -keystore bcs-go-demo.jks -alias bcs-go-demo -keyalg RSA -keysize 2048 -validity 10000
   ```
3. ใส่ใน GitHub เป็น repository secret:
   - `BCS_GO_KEYSTORE_B64` = ไฟล์ `bcs-go-demo.jks` เป็น base64 (คำสั่งเดียวกับส่วนที่ 1 ข้อ 5 เปลี่ยนชื่อไฟล์)
   - `BCS_GO_KEYSTORE_PASSWORD` และ `BCS_GO_KEY_PASSWORD` = รหัสผ่านที่ตั้งในข้อ 2 (keytool รุ่นใหม่ใช้รหัสเดียวกันทั้งสองค่า)
   - `BCS_GO_KEY_ALIAS` = `bcs-go-demo`

## ส่วนที่ 3 · เว็บที่แอปเปิด

GitHub → **Settings** → **Secrets and variables** → **Actions** → แท็บ **Variables** → **New repository variable** → ชื่อ `BCS_GO_SERVER_URL` · ค่าคือโดเมนของ staging แบบ origin เช่น `https://bcs-staging-demo.vercel.app` (ขึ้นต้น https ไม่มี `/` หรือ path ต่อท้าย)

ค่านี้ต้องเป็น origin เดียวกับ `APP_URL` ของ staging ทุกตัวอักษร เพราะ QR บน PO เป็นลิงก์ของ `APP_URL` และ passkey ผูกกับ origin นี้ (BR-AUTH-09) ถ้าต่างกัน สแกน QR แล้วจะขึ้นว่าไม่ใช่ลิงก์ของ BCS และยืนยันด้วยลายนิ้วมือไม่ได้

## ส่วนที่ 4 · สร้าง APK

1. GitHub → แท็บ **Actions** → ซ้ายมือเลือก **bcs-go-apk** → ปุ่ม **Run workflow** → branch `main` · ช่อง "เว็บที่แอปเปิด" เว้นว่าง (ใช้ค่าของส่วนที่ 3) → **Run workflow**
2. รอประมาณ 10 นาทีจนวงกลมเป็นเครื่องหมายถูกสีเขียว ถ้าเป็นกากบาทสีแดงพร้อมข้อความ "ยังไม่ได้ตั้ง: …" ให้ใส่ค่าที่ขาดตามข้อความแล้วกด **Re-run jobs**
3. ถ้าเห็นหมายเหตุ "ไม่มี secret BCS_GO_GOOGLE_SERVICES_JSON_B64" แปลว่า APK นี้ไม่รับ push ให้กลับไปทำส่วนที่ 1 ข้อ 5 แล้วสร้างใหม่
4. เปิด run ที่ผ่าน → ส่วน **Artifacts** → ดาวน์โหลด `bcs-go-demo-apk` (ไฟล์ zip ข้างในคือ `app-release.apk` · เก็บไว้ 30 วัน)
5. หน้า **Summary** ของ run เดียวกันมีบรรทัด `BCS_GO_ANDROID_CERT_SHA256` → คัดลอกค่า (ตัวอักษรคั่นด้วย `:`) ไปใส่ใน Vercel ตัวแปรชื่อเดียวกัน ค่านี้คงเดิมตราบที่ใช้ keystore เดิม

## ส่วนที่ 5 · ให้ staging รู้จักแอป และ deploy

1. ใน Vercel ใส่ `BCS_GO_ANDROID_PACKAGE` = `th.bcs.go` และตรวจว่ามีค่าครบตามตาราง "ค่าที่จะได้และใส่ที่ไหน" ส่วน Vercel แล้ว
2. ค่าใหม่ใช้ได้หลัง deploy ใหม่ บอก agent ในแชตว่า "ใส่ค่า BCS Go ใน Vercel แล้ว" agent จะขออนุญาตก่อน deploy ทุกครั้ง
3. หลัง deploy เปิด `https://<โดเมน staging>/.well-known/assetlinks.json` ในเบราว์เซอร์ ต้องเห็น `th.bcs.go` และค่า SHA-256 จากส่วนที่ 4 ข้อ 5 (ถ้าเห็น 404 แปลว่ายังขาดค่าใดค่าหนึ่งในข้อ 1) · ไฟล์นี้ทำให้ WebView ของแอปใช้ passkey ของโดเมนนี้ได้

## ส่วนที่ 6 · เปิดโมดูล BCS Go ขององค์กร

องค์กร `SIMEC` ของข้อมูลระยะ 1 เปิด BCS_GO มาแล้วจาก seed ข้ามส่วนนี้ได้ · องค์กรอื่นให้ทีม BCS เปิด: login ด้วยบัญชีทีม BCS → `/platform/tenants` → **จัดการโมดูลของ <องค์กร>** → **เปิดโมดูล แอป BCS Go** → ใส่เลขอ้างอิงสัญญาและเหตุผล → ยืนยัน (ผู้ดูแลองค์กรเห็นแบบอ่านอย่างเดียวที่ `/admin/modules`) · ปิดโมดูลแล้ว push หยุดและกลับไปส่ง LINE และอีเมล ส่วนคิวตรวจรับที่ค้างในเครื่องยังส่งได้ (FR-PLT-301 AC10)

## ส่วนที่ 7 · ติดตั้งแอปบนมือถือ

1. ส่งไฟล์ zip จากส่วนที่ 4 ข้อ 4 ไปที่มือถือ (เช่น ดาวน์โหลดจาก GitHub บนมือถือโดยตรง) แล้วแตก zip ด้วยแอป Files
2. แตะ `app-release.apk` → Android ถามว่าอนุญาตให้แอป Files หรือ Chrome ติดตั้งแอปไหม → **Settings** → เปิด **Allow from this source** → กลับมาแตะ **Install**
3. Google Play Protect อาจเตือนว่าไม่รู้จักแอปนี้ (APK ของ demo ไม่ได้มาจาก store) ให้แตะ **More details** → **Install anyway**
4. เปิดแอป **BCS Go** จะเห็นหน้า login ของ staging → ใส่อีเมล `<รหัสพนักงาน>@simec.bcs.local` รหัสผ่าน `SEED_DEV_PASSWORD` ของ staging และรหัส 6 หลัก (TOTP) ของคนนั้น
   - รหัส 6 หลักของ staging สร้างด้วยคำสั่งในข้อ 5 ของ [DEMO_RUNBOOK.md](../DEMO_RUNBOOK.md) เปลี่ยนรายชื่อท้ายคำสั่งเป็นคนของขั้นนี้: `ceo pm_p07 store_p07 se_p01a vp_ops dm_coni proc_officer dm_proc fm_p07 admin`

## ส่วนที่ 8 · เปิดแจ้งเตือนในแอป (FR-PLT-301 AC1)

ทำในแอปบนมือถือของคนที่ต้องได้ push (ฉาก 4 คือ `ceo`)

1. เมนู → **ตั้งค่าของฉัน** → **ตั้งค่าการแจ้งเตือน** (`/settings/notifications`) → เปิดสวิตช์ **รับแจ้งเตือนในแอป**
2. Android ถามสิทธิ์แจ้งเตือน → **Allow**
3. ต้องเห็น "เปิดรับแจ้งเตือนในแอปแล้ว โทรศัพท์เครื่องนี้ลงทะเบียนแล้ว" และเครื่องอยู่ในตาราง พร้อมอีเมลแจ้งเจ้าของว่ามีเครื่องใหม่ · ถ้าขึ้นว่า "เปิดได้ในแอป BCS Go เท่านั้น" แปลว่าเปิดหน้านี้ในเบราว์เซอร์ ไม่ใช่ในแอป

## ส่วนที่ 9 · ลงทะเบียน passkey และลองลายนิ้วมือ (FR-PLT-301 AC3 AC4 · ADR-166)

1. ในแอป เมนู → **ตั้งค่าของฉัน** → **PIN ยืนยันธุรกรรม** (`/settings/pin`) → **เพิ่ม passkey บนเครื่องนี้**
2. ใส่รหัสผ่านอีกครั้ง (หรือรหัส 6 หลัก) และชื่อเครื่อง เช่น "โทรศัพท์ demo" → **ยืนยันและเพิ่ม passkey** → สแกนลายนิ้วมือหรือใบหน้า
3. ต้องเห็น "เพิ่ม passkey แล้ว ระบบส่งอีเมลแจ้งคุณด้วย" และเครื่องอยู่ในรายการ
4. ถ้าขึ้นข้อผิดพลาดแทน หรือแตะปุ่มแล้วไม่มีหน้าต่างสแกนนิ้ว ให้จดข้อความบนจอแล้วบอก agent (WebView ของ Android อาจส่ง origin ของแอปแทนโดเมน ซึ่งกฎ BR-AUTH-09 ไม่รับ · การเปลี่ยนกฎต้องให้คุณตัดสินก่อน) ระหว่างนั้นใช้ทางสำรองของ ADR-166:
   - เปิดโดเมน staging ใน **Chrome** บนมือถือเครื่องเดียวกัน → login → เมนูสามจุด → **Add to Home screen** (ติดตั้งเป็น PWA)
   - ลงทะเบียน passkey ที่ `/settings/pin` ใน Chrome แบบข้อ 1–3 แล้วอนุมัติยอดสูงใน Chrome · push ยังมาที่แอป BCS Go ตามเดิม แตะแล้วเปิดในแอป ถ้าจะใช้ลายนิ้วมือให้เปิดเลขเอกสารเดียวกันใน Chrome
   - เครื่องที่ไม่มี passkey ใช้ PIN ได้เสมอ

## ส่วนที่ 10 · ถ้าค่าลับรั่ว

- key ของ service account: Firebase → Project settings → Service accounts → **Manage service account permissions** → เลือกบัญชี → แท็บ **Keys** → ลบ key เดิม → สร้างใหม่ตามส่วนที่ 1 ข้อ 6 → ใส่ค่าใหม่ใน Vercel → ขอ agent deploy
- keystore: สร้างใหม่ตามส่วนที่ 2 → APK ใหม่ (ส่วนที่ 4) → เปลี่ยน `BCS_GO_ANDROID_CERT_SHA256` ใน Vercel → ถอนแอปเดิมจากมือถือทุกเครื่องแล้วติดตั้งใหม่ และลงทะเบียน passkey ใหม่
- `google-services.json` ไม่ใช่ความลับเต็มรูปแบบ (อยู่ในแอปทุกตัว) แต่ถ้า commit ลง repo ให้บอก agent เพื่อเอาออก

## ฉาก demo ของขั้น (docs/sub-specs/S17.md "Demo ของขั้น")

ทุกฉากมีเทสต์ e2e ในเบราว์เซอร์ที่เล่นฉากเดียวกันด้วยคนและยอดเดียวกันบนองค์กรจำลองของข้อมูลระยะ 1 (`tests/e2e/s17.spec.ts` · แท็ก `@s17`) ก่อนซ้อมบนมือถือ ให้ฉาก e2e ผ่านบนเครื่องก่อน (`pnpm test:e2e --grep @s17` ทุกฉาก หรือคำสั่งของฉากในตาราง) · ส่วนที่ e2e ทำแทนไม่ได้คือของจริงบนมือถือ: token ของ FCM การแตะแจ้งเตือน กล้องสแกน QR และลายนิ้วมือจริง ซึ่งลองในฉากเหล่านี้

| ฉาก | ฉาก e2e | คำสั่ง |
| --- | --- | --- |

### ฉาก 3 · ขอผ่านแชทเมื่อเปิด AI (FR-LINE-301 AC1 AC3 AC4 AC5)

1. ใน LINE ของ `se_p01a` พิมพ์ในแชท OA: `ขอซื้อเหล็กข้ออ้อย DB25 1 ตัน ส่งไซต์พระราม 9`
2. ส่งรูปใบเสนอราคา (ภาพถ่ายแบบ DOC-031 · ไฟล์ตัวอย่าง `tests/fixtures/ai-docs/DOC-031.jpg` ส่งเข้ามือถือแล้วส่งเป็นรูปในแชท: เหล็กข้ออ้อย DB25 SD40 1 ตัน ก่อน VAT 24,411.00 VAT 1,708.77 รวม 26,119.77)
3. OA ตอบพร้อมปุ่ม **ตรวจและส่งคำขอ** (ข้อความตอบไม่มีสิ่งที่พิมพ์หรือราคา)
4. รอประมาณ 30 วินาที (AI อ่านหลังข้อความหยุดมา 20 วินาที) แล้วแตะปุ่ม → หน้า "ร่างคำขอจากแชท" เห็นข้อความแชทเป็นข้อมูลอ้างอิง รูป และกล่อง **ค่าที่ AI อ่านได้** ป้าย "เติมโดย AI โปรดตรวจ" ประเภท **ซื้อของ** ถูกเลือกไว้
5. **สร้างร่างคำขอ** → หน้าแก้ร่างมีกล่อง **ค่าที่ AI เติมรอยืนยัน** (จำนวน และราคาต่อหน่วย) → ตรวจค่าในฟอร์ม ติ๊กทั้งสองช่อง → **ยืนยันค่าที่ตรวจแล้ว**
6. ขั้นที่ 1 เลือกบรรทัดงบ `P01-MAT-…` ของปีงบปัจจุบัน → ขั้นที่ 2 ตรวจรายการ 24,411.00 + VAT 1,708.77 = 26,119.77 → ขั้นที่ 3 เส้นทางอนุมัติไป `vp_ops` → **ส่งขออนุมัติ**

### ฉาก 4 · push และลายนิ้วมือ (FR-PLT-301 AC1 AC3)

1. มือถือของ `ceo` ทำส่วนที่ 7–9 แล้ว (ติดตั้งแอป เปิดแจ้งเตือน และลงทะเบียน passkey)
2. งานถนนแอสฟัลต์ 9,500 ตร.ม. ของ `pm_p07` (แถว H229 · 2,642,900.00 บาท รวม VAT) ผ่านผู้ตรวจคู่ขนานสามฝ่ายของ S6 แล้วรอ `ceo` · ถ้าจะเล่นการส่งเองด้วย ให้ `pm_p07` ส่งคำขอแบบเดียวกันบนเว็บ แล้วให้ผู้ตรวจ `dm_leg` `dm_qse` `dm_fin` ผ่านก่อน
3. ภายในไม่กี่วินาทีหลังงานถึง `ceo` มือถือได้แจ้งเตือนหัวเรื่อง **มีงานรออนุมัติ** เนื้อความเป็นเลข `PR-…` เท่านั้น (ไม่มียอด ชื่อ หรือชื่อเรื่อง แม้บนหน้าจอล็อก)
4. แตะแจ้งเตือน → แอปเปิดหน้างานนั้น → **อนุมัติ** → ยอดตั้งแต่ 100,000 บาทจึงต้องยืนยัน → **อนุมัติด้วยลายนิ้วมือหรือใบหน้า (passkey)** → สแกนนิ้ว → ขึ้น "อนุมัติแล้ว"
5. เปิดหน้าคำขอ → **เส้นทางอนุมัติ** และแท็บ **ประวัติ** แสดงช่องทาง **แอป BCS Go** ข้างการอนุมัติของ `ceo`
6. ถ้าไม่ได้แจ้งเตือน: ดูส่วน "ปัญหาที่พบบ่อย" งานยังมาทาง LINE หรืออีเมลตามเดิมเสมอ

### ฉาก 5 · ตรวจรับออฟไลน์ (FR-PLT-301 AC5 ถึง AC9)

1. มือถือของ `store_p07` ติดตั้งแอปแล้ว (ส่วนที่ 7) · PO ของคอนกรีตผสมเสร็จ 400 กก./ตร.ซม. 2 ลบ.ม. ราคา 2,780.00 ต่อหน่วย (แถว H042) ส่งให้ผู้ขายแล้ว และพิมพ์ PDF ของ PO ไว้ (บน PDF มี QR ของ PO)
2. ตอนมีสัญญาณ เปิดแอป → เมนู **ตรวจรับ** → ลิงก์ **ตรวจรับหน้างานแบบไม่มีสัญญาณ (BCS Go)** → หน้า **ตรวจรับหน้างาน** (`/go/receive`) ครั้งหนึ่ง เห็น PO ในรายการ (หน้าเก็บสำเนา PO ที่ไม่มีราคาไว้ในเครื่อง และเปิดได้ตอนไม่มีสัญญาณหลังเปิดครั้งแรกนี้)
3. ปิด Wi-Fi และข้อมูลมือถือ (หรือเปิดโหมดเครื่องบิน) → หน้าบอก "ไม่มีสัญญาณ บันทึกไว้ในเครื่องก่อน"
4. แตะ **สแกน QR บนใบสั่งซื้อ** → สแกน QR บน PDF (ครั้งแรกมือถืออาจต้องโหลดตัวสแกนของ Google Play ระหว่างนั้นพิมพ์เลข PO ในช่อง **เลขใบสั่งซื้อ** แทนได้)
5. ฟอร์มตรวจรับเปิดจากสำเนาในเครื่อง → รับรอบนี้ `2` · เลขที่ใบส่งของ · ถ่ายรูปของที่ส่งมา → **บันทึกไว้ในเครื่อง** → ขึ้น "บันทึกไว้ในเครื่องแล้ว จะส่งให้เองเมื่อมีสัญญาณ" และ รอส่ง 1
6. เปิดสัญญาณ → หน้าอัปโหลดรูปแล้วส่งเอง → "ไม่มีรายการค้างในเครื่อง" · บนเว็บ PO เป็น **รับครบ** และมี GR 1 ใบพร้อมรูป
7. สัญญาณหลุดหลังส่ง: ทำซ้ำข้อ 3–5 กับ PO อีกใบ แล้วเปิดสัญญาณแค่ชั่วครู่แล้วปิดทันทีระหว่างที่หน้ากำลังส่ง (บอกได้ยากบนเครื่องจริง ฉาก e2e จำลองคำตอบที่หายไว้แล้ว) → เมื่อสัญญาณกลับมา หน้าส่งซ้ำด้วยรหัสเดิมและได้ผลเดิม · มี GR ใบเดียว

### ฉาก 6 · ขอผ่านแชทเมื่อปิด AI (FR-LINE-301 AC6 · EG-1)

1. ปิด AI: ทีม BCS ปิดโมดูล **ผู้ช่วยอัตโนมัติ** ของ `SIMEC` ที่ `/platform/tenants` (เหมือนส่วนที่ 6) หรือผู้ดูแลองค์กรปิด **ผู้ช่วยกรอกคำขอ** ที่ `/admin/ai` · บนเครื่องใช้ `AI_ENABLED=false` ใน `.env` แล้วเปิดเว็บใหม่
2. เล่นฉาก 3 ข้อ 1–3 ซ้ำ → หน้า "ร่างคำขอจากแชท" ไม่มีกล่องของ AI
3. เลือกประเภท **ซื้อของ** → **สร้างร่างคำขอ** → ชื่อคำขอมาจากบรรทัดแรกของแชท รูปแนบเป็นไฟล์อื่น
4. ขั้นที่ 1 เลือกบรรทัดงบ → ขั้นที่ 2 เลือกสถานที่ส่ง `SITE-P01` และกรอก เหล็กข้ออ้อย DB25 SD40 · 1 · ตัน · 24411.00 → ขั้นที่ 3 → **ส่งขออนุมัติ** → ไป `vp_ops`
5. ถ้าเล่นต่อจากฉาก 3 ในวันเดียวกัน ระบบเตือน "คำขอนี้คล้ายคำขอที่คุณส่งไปแล้ว" (BR-DUP-05) ใส่เหตุผลที่ขออีกครั้งแล้วกดส่งอีกครั้ง
6. เปิด AI คืนเมื่อจบฉาก

- แอป iOS ยังไม่มีในรอบนี้ (S17-20)
