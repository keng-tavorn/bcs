# ทำงานหลายสายพร้อมกัน (รอบ P1)

คู่มือนี้สำหรับเจ้าของโปรเจกต์ ไม่ต้องเขียนโปรแกรมเป็น · กติกาทั้งหมดอยู่ใน spec §16.13 และ ADR-066 · ขั้นตอนของ agent อยู่ใน `.claude/skills/bcs-lane/SKILL.md`

## สายคืออะไร

- **สาย** คือสำเนาของโปรเจกต์อีกชุดในโฟลเดอร์แยก (git worktree) ที่มีฐานข้อมูลและพอร์ตของตัวเอง แชต Claude หนึ่งแชตทำงานในสายเดียว จึงทำหลายขั้นพร้อมกันได้โดยไม่ทับกัน
- **main** คือโฟลเดอร์หลัก `E:\BCS` งานของทุกสายกลับมารวมที่นี่เมื่อจบแต่ละขั้น โดย agent รวมให้เองหลังรีวิวโค้ด
- ทำไมเร็วขึ้น: 3 แชตทำงานพร้อมกันแทนการรอทีละข้อ · ทำไมยังถูกต้องเท่าเดิม: ทุกข้อยังต้องผ่าน `pnpm verify` เหมือนเดิม และทุกขั้นถูกรีวิวโดยตัวตรวจในบริบทใหม่ก่อนรวมเข้า main

## สร้างสาย (ครั้งเดียวต่อสาย)

1. เปิด Docker Desktop ให้ทำงานอยู่ (สายใช้ Postgres RustFS Mailpit ตัวเดียวกับ main)
2. ในแชตที่ main (`E:\BCS`) พิมพ์ `สร้างสาย 1 ตามตารางสายใน spec §16.13` (หรือสาย 2 สาย 3) · agent จะรัน `pnpm lane:create 1` ให้
3. รอราว 1 ถึง 2 นาทีต่อสาย จนเห็นบรรทัด `สาย 1 พร้อม: ...` ซึ่งบอกโฟลเดอร์ branch พอร์ตเว็บ และชื่อฐานข้อมูลของสาย

คำสั่งนี้ทำให้ครบ: สร้างโฟลเดอร์ `E:\BCS\.worktrees\l1` บน branch `p1/l1` (จาก main ถ้ายังไม่มี branch) · คัดลอก `.env` ของ main แล้วเปลี่ยนฐานข้อมูลและพอร์ตเป็นของสายตามตาราง (บล็อก `# --- สาย 1` ท้ายไฟล์ ห้ามแก้ด้วยมือ) · ติดตั้ง (`pnpm install`) · สร้างฐาน `bcs_l1` และใส่ข้อมูลตัวอย่าง (`pnpm db:reset` ในสาย) · ฐานของเทสต์ verify และ e2e ของสายถูกสร้างเองตอนรันครั้งแรก

- รันซ้ำกับสายที่มีอยู่แล้วได้ (เช่นหลังแก้ `.env` ของ main): เขียน `.env` ของสายใหม่ (ไฟล์เดิมเก็บเป็น `.env.lane-backup` ถ้าต่างกัน) ติดตั้ง และล้างฐาน dev ของสายนั้นแล้ว seed ใหม่ · ไม่แตะ branch งานที่ commit แล้ว หรือฐานของสายอื่น
- `.env` ของ main เปลี่ยน (เช่นเพิ่ม key ใหม่) สายไม่ได้ค่าใหม่เอง ให้รัน `pnpm lane:create <เลขสาย>` อีกครั้ง หรือเพิ่มบรรทัดเดียวกันใน `.env` ของสายเหนือบล็อกของสาย
- ความปลอดภัย: `pnpm db:reset` ปฏิเสธฐานของ main เมื่อรันจากในสาย และปฏิเสธฐานของสายเมื่อรันจาก main · `pnpm dev` ในสายเปิดที่พอร์ตของสายเอง (3001 3002 3003) · เทสต์ฐานข้อมูลในสายใช้ไม่เกิน 4 worker เพื่อให้ 3 สายกับ main ไม่เกินจำนวน connection ของ Postgres

ทำไมไม่ใช้ปุ่ม worktree ของแอป Claude: ปุ่มนั้นสร้างโฟลเดอร์ใหม่ที่ยังใช้ฐานข้อมูลและพอร์ตเดียวกับ main ทำให้สายชนกัน จึงให้ agent สร้างสายตามตารางแทน

## ทำ P1-02 ถึง P1-04 พร้อมกัน (สายชั่วคราว ก่อน P1-07)

สาย 1 และ 2 สร้างไว้แล้ว จึงเปิด 3 แชตได้ทันที แต่ละแชตอยู่คนละโฟลเดอร์ ห้ามเปิดสองแชตในโฟลเดอร์เดียวกัน

| แชต | Project folder | พิมพ์ | effort | Ultracode |
| --- | --- | --- | --- | --- |
| 1 | `E:\BCS` | `ทำ P1-02` | high | ปิด |
| 2 | `E:\BCS\.worktrees\l1` | `ทำ P1-04` | high | เปิด แล้วปิดเมื่อเสร็จ |
| 3 | `E:\BCS\.worktrees\l2` | `ทำ P1-03` | high | ปิด |

1. เปิดแชตทีละแชตตามขั้นตอนในหัวข้อ "เปิดแชตของสายในแอป Claude" ด้านล่าง โดยเลือก Project folder ตามตาราง
2. ตั้ง effort เป็น high ทุกแชต · แชต 2 เปิด Ultracode (P1-04 ร่าง sub-spec 5 ฉบับขนานกัน) · แชต 1 และ 3 ปิด
3. พิมพ์คำสั่งตามตาราง แล้วปล่อยให้ทำงานพร้อมกัน
4. แต่ละแชตส่งงานเข้า main เองเมื่อข้อนั้นเสร็จ แล้วสรุปให้ · ถ้าสรุปมีบรรทัด "ตรวจก่อน:" ให้คัดคำสั่งนั้นไปพิมพ์ในแชตเดิม รอผลตรวจขึ้น แล้วพิมพ์ `แก้ตามผลตรวจ`
5. เมื่อทั้ง 3 ข้อเสร็จ เปิดแชตใหม่ที่ `E:\BCS` แล้วพิมพ์ `ทำข้อถัดไปของเส้นชัย A3` (จะได้ P1-05)

ทำไมจัดแบบนี้: P1-04 อยู่บนทางที่ยาวที่สุด (P1-04 → P1-05 → คุณอนุมัติ P1-06 → P1-07) จึงควรเริ่มเร็วที่สุด · P1-03 รันการทดสอบหน้าจอเต็มชุดหลายรอบ ซึ่งรันได้ทีละแชต จึงแยกไว้แชตเดียว · quota ไม่พอให้เปิดแค่แชต 1 กับ 2 ก่อน แล้วทำ P1-03 ต่อในแชตใหม่ที่ main

## เปิดแชตของสายในแอป Claude

1. แอป Claude → แท็บ **Code** → กด **+ New session** (หรือ Ctrl+N)
2. **Environment** เลือก **Local** · **Project folder** เลือก `E:\BCS\.worktrees\l1` (สายอื่นเปลี่ยนเป็น `l2` หรือ `l3`) · ไม่ต้องเปิดตัวเลือก worktree ของแอป
3. ตั้งชื่อแชตให้จำง่าย เช่น "สาย 1 · S6"
4. ตั้ง effort: กด Ctrl+Shift+E → เลือก **high** → กด **s** (ใช้เฉพาะแชตนี้) หรือ Enter (จำไว้ใช้ครั้งต่อไป)
5. ถ้าปุ่มชื่อโมเดลมีคำว่า Ultracode ให้ปิดก่อน
6. พิมพ์คำสั่งของสายตามตารางด้านล่าง
7. ดูหลายแชตพร้อมกัน: กด Ctrl ค้างแล้วคลิกแชตในแถบซ้ายเพื่อแบ่งจอ · Ctrl+Tab สลับแชต

| สาย | โฟลเดอร์ | พิมพ์ | effort |
| --- | --- | --- | --- |
| 1 | `E:\BCS\.worktrees\l1` | `ทำตาม spec.md จนถึงเส้นชัย D` แล้วแชตใหม่ `ทำตาม spec.md จนถึงเส้นชัย G` (ทำเฉพาะส่วนแอป BCS Go) | D: high · G: xhigh |
| 2 | `E:\BCS\.worktrees\l2` | `ทำตาม spec.md จนถึงเส้นชัย E` | xhigh (S9 แตะเงินทุกข้อ) |
| 3 | `E:\BCS\.worktrees\l3` | `ทำตาม spec.md จนถึงเส้นชัย G` (เส้นชัย F เสร็จแล้ว · ทำเฉพาะส่วน LINE ของ S17) | xhigh |
| main | `E:\BCS` | `ทำข้อถัดไปของเส้นชัย A3` | ตามบรรทัด "ถัดไป:" |

ถ้าอยากเห็นทีละข้อและตรวจเองระหว่างทาง ให้พิมพ์ `ทำข้อถัดไปของเส้นชัย D` แทน แล้วเปิดแชตใหม่ทุกข้อ (ช้ากว่าแต่เห็นทุกขั้น)

## ระหว่างที่สายทำงาน

- แต่ละแชตจะหยุดถามเองเมื่อจำเป็น ดูที่หัวข้อ "รอคุณ" ในสรุปของแชตนั้น
- อย่าปิด Docker Desktop และอย่าปิดเครื่องระหว่างที่สายทำงาน · งานที่ commit แล้วไม่หาย ถ้าต้องหยุด กด Stop แล้วพิมพ์ `ทำต่อ` ภายหลัง
- เครื่องนี้ (RAM 40 GB · CPU 12 threads) รัน 3 สายได้ แต่การทดสอบหน้าจอเต็มชุด (e2e) รันได้ทีละสาย agent จะถามก่อนถ้าไม่แน่ใจว่าสายอื่นรันอยู่
- ดูความคืบหน้ารวม: ในแชต main พิมพ์ `สรุปความคืบหน้าจาก checklist ใน spec.md เป็นตาราง` (effort low)

## ค่าใช้จ่ายและความเร็ว (ประมาณ)

- แต่ละแชตใช้ quota การใช้งานของคุณแยกกัน 3 สายจึงใช้ quota เร็วขึ้นราว 3 เท่า · ถ้าใกล้หมด ให้หยุดสายใดสายหนึ่งก่อน
- เวลาจริงเร็วขึ้นราว 2 ถึง 2.5 เท่าเมื่อเทียบกับทำทีละสาย (ไม่ถึง 3 เท่า เพราะต้องรวมงานและรอ e2e ทีละสาย)
- effort ที่สูงขึ้นไม่ได้ทำให้เร็วขึ้น (`xhigh` และ `max` ช้าลง) · ตั้งแต่ 2026-10-15 คุณเลือกให้ข้อที่แตะเงินและสิทธิ์ใช้ `xhigh` และให้ agent รีวิวโค้ดของข้อนั้นทันทีก่อนไปข้อถัดไป (ADR-072) แลกความเร็วต่อข้อกับความถูกต้องที่สูงขึ้น · ข้ออื่นยังใช้ `high` หรือ `medium` ตามตาราง
- Ultracode เหมาะกับงานเอกสารหรืองานกวาดที่แยกเป็นชิ้นได้ ไม่เหมาะกับงานเขียนโค้ดทีละข้อ เพราะช้าและใช้ token มาก · เปิดได้เฉพาะ P1-04 S9-02 คู่ S9-03 (เขียนสองชุดเทียบกัน) S9-09 S17-16 P1-08 และ P1-09 แล้วปิดเมื่อข้อนั้นเสร็จ

## เมื่อสายเสร็จ

- agent รีวิวโค้ดของขั้นแล้วส่งงานเข้า main ให้เอง · แชตบน main เริ่มข้อถัดไปด้วยการดึงงานล่าสุด (`git pull`) เอง
- สาย 3 ทำ S17 ส่วน LINE ต่อในแชตใหม่ที่โฟลเดอร์เดิม (ร่างได้ทันที ทำให้จบหลังเส้นชัย D) · สาย 1 ทำ S17 ส่วนแอป BCS Go ในแชตใหม่ที่โฟลเดอร์เดิมหลังเส้นชัย D · ทั้งสองสายพิมพ์คำสั่งเส้นชัย G เหมือนกัน agent เลือกเฉพาะข้อของสายตัวเองจากคอลัมน์ "สาย" ใน spec §16.18
- ลบสายหลังเส้นชัย A3: ให้แชต main ทำ (agent จะถามคุณก่อนลบ เพราะลบแล้วย้อนไม่ได้)
