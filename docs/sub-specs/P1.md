- ความสามารถ (§2.4): ไม่มีใหม่ · ตัดสินงานของ subject ใหม่ใช้ `approval.decide` เดิม (ผู้ได้รับงานหรือผู้มอบ · ทุก service ตรวจ SoD ซ้ำตอนกด) · แก้ข้อของชนิดใหม่ใช้ความสามารถของตัวแก้ DOA เดิม (ORG_ADMIN · ผู้ส่งอนุมัติเองไม่ได้ BR-SOD-06) · เปิดโมดูลใช้ `platform.modules.manage` เดิม (PLATFORM_ADMIN เท่านั้น ORG_ADMIN ดูอย่างเดียว) · กรณีปฏิเสธที่ต้องมีเทสต์: ORG_ADMIN เรียก `organization.set_module` → `FORBIDDEN` (เดิม) · PLATFORM_ADMIN เปิด PAY โดย DOA ขาดข้อ → `DOA_NOT_CONFIGURED`
- event (§10.2): ไม่มีชนิดใหม่ · `approval_task.*` รับ `subjectType` ใหม่ 5 ค่า · `approval_task.decided` เพิ่มฟิลด์ `coveredRuleCodes` (ว่างได้) และ `doaRuleCode` มาจากขั้น · `approval_task.assigned` เพิ่ม `documentType` และ `ruleCode` ของขั้น
- error (§14.2): ไม่มีรหัสใหม่ · reason ใหม่ `AMOUNT_NOT_ALLOWED` (ของ `VALIDATION_FAILED`) และ `MODULE_RULES_MISSING` (ของ `DOA_NOT_CONFIGURED`) · lint code ใหม่ `DOA_LINT_AMOUNT_NOT_ALLOWED` (ต่อท้ายรายการของ BR-DOA-08)
- การแจ้งเตือน (§10.1): ไม่มีแถวใหม่ · `task.assigned` และแม่แบบ SLA แสดงชื่อชนิดเอกสารใหม่ไทยอังกฤษ เลขเอกสาร และชื่อเรื่องเท่านั้น ไม่มีราคาต่อหน่วยหรือเลขบัญชี (BR-NOTI-01 NFR-SEC-09) · ป้ายใน LINE ของ `BANK_ACCOUNT_CHANGE` ไม่มีปุ่มตัดสิน (BR-DOA-27)
