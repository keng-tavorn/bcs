## State machine

ตารางอยู่ใน `src/core/state-machines` พร้อมเทสต์วนทุกคู่ (§6.4) · ทุกแถวผ่าน `runCommand()` และมี event

**`WorkflowVersion`** (แบบเดียวกับ DOA version)

| จาก | คำสั่ง / เหตุ | ไป | ใครทำได้ | event |
| --- | --- | --- | --- | --- |
| — | `workflowVersion.draft` (คัดลอกฉบับล่าสุด) | DRAFT | `admin.workflow.draft` | `workflow_version.drafted` |
| DRAFT | `workflowVersion.update` (ล้าง dryRunAt) | DRAFT | `admin.workflow.draft` | `workflow_version.updated` |
| DRAFT | `workflowVersion.submit` (lint ผ่าน · test case ผ่าน · dryRunAt ≥ แก้ล่าสุด) | PENDING_APPROVAL | `admin.workflow.submitForPublish` | `workflow_version.submitted` |
| PENDING_APPROVAL | ขั้นสุดท้ายอนุมัติ (ข้อ `DOA_CHANGE` · step-up · ผู้ส่ง ≠ ผู้อนุมัติ) | PUBLISHED | ตามเส้นทาง | `workflow_version.approved` `workflow_version.published` |
| PENDING_APPROVAL | `approval.reject` | REJECTED | ตามเส้นทาง | `workflow_version.rejected` |
| PUBLISHED | ถึง effectiveFrom ของฉบับใหม่ (job `workflow-version-activate`) | SUPERSEDED | SYSTEM | `workflow_version.superseded` |
| PUBLISHED (ยังไม่มีผล) | `workflowVersion.requestWithdrawal` แล้วอนุมัติตามข้อ `DOA_CHANGE` | WITHDRAWN | ผู้มี `admin.workflow.submitForPublish` เสนอ | `workflow_version.withdrawal_requested` `workflow_version.withdrawn` |

**การถอน `DoaVersion` (FR-DOA-104 · BR-DOA-18):** PUBLISHED ที่ `effectiveFrom > now` → `doaVersion.requestWithdrawal` (เหตุผลบังคับ · สร้าง route ข้อ `DOA_CHANGE` · event `doa_version.withdrawal_requested`) → อนุมัติ → `WITHDRAWN` (`doa_version.withdrawn` มีอยู่แล้ว) · ไม่อนุมัติ → คง PUBLISHED (`doa_version.withdrawal_rejected`) · ถึง effectiveFrom ขณะรอ → route ถูกยกเลิก เหตุ `ALREADY_EFFECTIVE` · การตัดสินหลัง effectiveFrom → `INVALID_STATE_TRANSITION` reason `ALREADY_EFFECTIVE`

**`ApprovalStep` แบบ slot**

| จาก | เหตุ | ไป | ผล |
| --- | --- | --- | --- |
| WAITING | ขั้นก่อนหน้า APPROVED หรือเป็นขั้นแรก | ACTIVE | สร้างงานทุก slot พร้อมกัน (ผู้ดำรงตำแหน่งปัจจุบันตาม BR-WF-14) · `approval_task.assigned` ต่องาน |
| ACTIVE | การตัดสินของ slot ทำให้ `stepOutcome` ไม่ใช่ OPEN | DONE | ยกเลิกงานที่ยังเปิดของ step (`approval_task.cancelled` why `STEP_DECIDED`) · `approval_step.completed` · APPROVED → ขั้นถัดไป · REJECTED/RETURNED → เอกสารไปสถานะเดิมของ §6.4 |
| WAITING · ACTIVE | route ถูกยกเลิก | CANCELLED | งานที่เปิดเป็น CANCELLED |

ภายใน slot เดียว กติกาเดิมคงอยู่: การตัดสินแรกของ slot คือผลของ slot และงานอื่นใน slot เดียวกัน (ผู้รับร่วมจาก SLA งานที่ย้ายจากรักษาการ) ถูกยกเลิก (`completeStep` ทำต่อ slot)
